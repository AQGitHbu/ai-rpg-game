# RPG 游戏开发规范

> 本文档记录 RPG 项目的实现差异。跨项目共同规则见 `共同规范/共同游戏开发规范.md`。

## 代码分层

- `src/game/domain/`：稳定领域类型和纯函数；不依赖 gameplay、application、UI 或 provider。
- `src/game/gameplay/rpg/`：RPG 规则、校验和结算；不依赖 application、UI 或 store。
- `src/game/application/`：use case、read model 和 request adapter；不直接改玩法数值。
- `src/game/application/server/`：AI、数据库、密钥和其他 server-only 外部能力。
- `src/components/`、`src/store/`、`src/app/api/`：只通过 application 使用玩法能力。

## 当前脚手架约束

- 已有正式 `GameState`、确定性 fallback、SQLite 存档、固定行动、移动、物品取得与任务 reconciliation；新代码必须建立在已编译蓝图与 application facade 之上，不得从 UI 表单状态自行推导领域模型。
- 当前仍未实现自由输入、AI、物品使用、战斗、失败分支和结局；Phase 6 仅计划实现确定性 boss 战与双结局，不得以便利为由跨越对应 Phase Plan 的边界。
- 新模块先按对应 Spec/Plan 建立，再写实现。
- 新增模块必须有同目录测试；跨层新增路径必须更新 `src/dependencyBoundaries.test.ts`。
- 需要通用 UI、AI、日志或测试基础设施时，按 `AGENTS.md` 的触发条件读取共享模块流程。

## 共享 UI

- `Panel`、`InlineButton`、`Tag` 从 `@ai-game/ui` package 根入口导入，禁止 deep import 或在 RPG 内复制实现。
- package 只负责结构和稳定 class；RPG 主题 CSS 位于 `src/app/globals.css`，业务组合位于 `src/components/`。
- 新游戏表单、对白布局、角色立绘、streaming 和场景状态都是 RPG 业务，不进入 foundation。
- `TabBar`、Surface/Modal 等未进入 v0.1；只有 RPG 出现真实需求后才能按共享流程扩展。
