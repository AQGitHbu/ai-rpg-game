# RPG 游戏开发规范

本文定义跨系统工程约束。实现契约从 [系统索引](Agent文档索引.md) 定位；文档维护遵循 [AGENTS.md](../AGENTS.md)，共享任务按其条件入口展开。

## 分层与依赖

| 层 | 职责与依赖 |
|---|---|
| `src/game/domain/` | RPG 类型、ID 与纯辅助函数；不依赖玩法、application 或外部入口 |
| `src/game/core/` | 无 RPG 语义的通用机制；不依赖 domain、gameplay、application、UI、provider、数据库 |
| `src/game/gameplay/rpg/` | 行动合法性、数值、任务、战斗、状态转移与规则事件；依赖 domain 和 core facade |
| `src/game/application/` | 用例编排、read model、请求适配和 AI 提案一致性审批；通过 gameplay 子系统 facade 调规则 |
| `src/game/application/server/` | 真实 provider、数据库、环境和密钥的装配与适配 |
| `src/components/`、`src/store/`、`src/app/` | 展示、客户端请求状态和传输适配；通过 application 消费游戏能力 |

- application 与 gameplay 跨子系统调用只走 `@/game/gameplay/rpg/<system>` 的 `index.ts`；不 deep-import 内部实现。
- UI/store/页面从 `@/game/application` 获取能力与类型；API route 通过 `@/game/application/server/compositionRoot` 调用用例，不装配 provider、SQL 或 prompt。
- 客户端 facade 不导出 server-only 能力；类型转发同样不能把环境或文件系统带入浏览器。
- AI 提案审批位于 application，只比对候选和已批准事实的一致性，不产生新的行动、数值或胜负规则结论。
- UI 只消费结构化 read model 与 opaque token，不生成或解析 token、不从文案反推状态、不向客户端暴露隐藏事实或内部 Action registry。
- 新增 core 机制必须无 RPG 业务字段、prompt 或存档语义，有 facade、同目录测试与边界守卫。已有公共职责按共享流程处理，不因目录名称预建引擎。
- 生产 use case 和 route 使用无版本后缀的唯一接口；不新建并行生产链、兼容 facade 或版本化 endpoint。持久化 schema 版本是数据契约，归对应系统维护。

## 持久化与服务端

- `GameRepository` 是仓储端口，SQLite 适配器位于 `src/game/application/server/persistence/`；只有 `sqliteClient.ts` 直接导入 Node 内置 `node:sqlite`。运行环境为 Node.js ≥24.15.0 的 Next.js Node runtime，不使用 Edge runtime 或自行编译的数据库驱动。
- composition root 注入仓储、时钟、ID、AI 与日志。数据库路径、SQL、密钥不进入 UI、store 或玩法层。
- 存档写入保持原子性和 compare-and-swap；损坏或不支持的版本返回稳定错误，不静默重置。当前 schema 与支持范围见 [实体状态](agent/实体与组件世界状态.md) 和 [记忆系统](agent/剧情连续性与结构化记忆.md)。
- 开发清档必须由服务端检查 `NODE_ENV === "development"`，只删除 current slot 指向的游戏行，不删除数据库文件、schema、worktree 或其他仓库。
- 配置进入玩法前校验结构和引用；展示字段由 read model 产生，不为样式修改权威规则状态。

## AI、共享 UI 与日志

- `@ai-game/ai-transport` 只在 `application/server/ai/` 导入；RPG 的配置、prompt、解析、重试和审计属于本仓服务端。AI 输出必须经结构、枚举、ID、长度、引用与权限审批。
- 生产 AI 策略遵循 [设计原则](游戏设计原则.md)。失败分类、重试状态机和调用边界由 [运行时 AI](agent/运行时AI导演与场景表演.md) 维护，确定性 source 仅在显式 offline fixture 装配。
- AI source 使用统一生成失败与修复反馈契约；新增接口不得另写缺失原因的回退分类、公共修复 prompt 格式或审计 retry 转换。具体校验码、业务修复说明和次数预算由所属系统提供。
- `Panel`、`InlineButton`、`Tag` 从 `@ai-game/ui` 根入口消费；RPG 主题、地图、对白、HUD 和业务布局留在本仓，不复制公共实现。
- 诊断日志通过 `GameLogger` 注入并从 logging facade 导入，生产代码不直接调用 console；server sink 是唯一例外。异步请求沿用 traceId，事件只含允许字段与稳定分类。
- 普通诊断日志排除 prompt、模型/玩家原文、完整存档及凭据。专用 [AI 文本审计](agent/AI文本审计.md) 按独立契约保留正文；两类日志均排除 API key、Authorization 与 cookie。长期记忆的隐私限制不能代替审计策略。

## 验证

新逻辑在同目录测试合法、非法和边界行为。application 使用注入的仓储、时间、ID、AI 与日志，UI 测试展示和交互；真实 AI 测试通过显式环境门禁，不混入默认离线回归。

- 代码变更最低运行 `npm run typecheck` 与 `npm run test:boundaries`；新增跨层依赖同步更新 `src/dependencyBoundaries.test.ts`。其 facade 清单须覆盖全部 gameplay 子系统。
- 涉及脚本、规范或快速门禁覆盖内容时运行 `npm run test:fast`。合入前完整代码验收运行 `npm test`；构建影响与阶段任务按对应 Plan 追加构建/旅程/实机验收。
- 纯文档变更运行 `npm run check:docs` 与 `git diff --check`；修改检查器时运行 `npm run test:docs`，不因修改文案重跑游戏旅程。

| 改动范围 | 行为验证入口 |
|---|---|
| domain | `npm run test:game-domain` |
| gameplay | `npm run test:game-gameplay` |
| application / AI / persistence | `npm run test:game-application` |
| logging | `npm run test:game-logging` |
| components | `npm run test:components` |
| app / API | `npm run test:app` |

跨层可用 `npm run test:changed` 或 `npm run test:related -- <文件路径...>` 定位受影响测试；子集通过不替代计划要求的完整验收。共享 package 修改按共享流程运行消费者合同与 family 门禁。

环境准备、分支与安全收尾见 [项目脚手架](agent/项目脚手架.md)。
