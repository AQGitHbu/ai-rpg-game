## 剧情流程

> 记录格式：开幕 → 与谁交谈/选择什么 → 获得什么信息或物品 → 前往何处/调查什么 → 因为什么与谁战斗 → 战斗结果 → 幕交接 → 结局。

先用真实 API 跑通基线局，再用真实 API 新建第二局验证修复。真实 AI 名称会变化；修复回归局的实际可见链路如下：

`序幕（沈青崖背着旧刀走进青石镇，看到缉凶告示） → 进入福来酒楼，与老周交谈并选择“表示愿意支持老周” → API 编排顾砚 → 进入铁匠铺，点击“与顾砚交谈”直接打开双选项 → 选择“表示愿意支持顾砚”并由 API 编排苏绾 → 前往断碑谷，点击“与苏绾交谈”直接打开双选项 → 选择“表示愿意支持苏绾”并由 API 编排程砚秋 → 点击“与程砚秋交谈”直接打开双选项 → 选择“表示愿意支持程砚秋”并由 API 编排陆归鸿 → 前往黑水古道，点击“与陆归鸿交谈”直接打开双选项 → 选择“表示愿意支持陆归鸿”并由 API 完成终幕 → 拾取盟誓铁印 → 结局“在废墟之上重建信任”。`

基线局也完整到达“独自揭露真相”结局，并覆盖了断裂镖旗、残缺卷宗、背包和双敌人战斗；它暴露的“交谈仍先触发 API、通用问候、终幕没有分支”问题已在第二局回归中验证修复。拾取单向动作的提前编排仍作为 P-013 保留问题。

### 剧情、对白与选项合理性审查

| 检查项 | 结论 | 处理 |
|---|---|---|
| 开幕动机 | 修复回归局的“旧刀、青石镇、缉凶告示”比基线局更直接；仍可让 AI 把镖局覆灭和告示关系说得更明确 | 保留为开局提示词增强建议 |

## 剧情与界面评价

### 已确认合理之处

- 开幕告示、旧镖局背景与青石镇线索建立主线动机；中篇每幕有明确承接人物和物件。
- 正式 API 行动期间使用模态并锁定底层操作，避免旧 revision 上继续点击。
- 战斗成为独立场景，左右阵营和回合反馈符合 RPG 预期，不再像地点页里的表单。
- 小镇采用“点击高亮建筑后查看建筑/NPC/进入”层级，右侧默认是地图提示而非开发状态列表。

### 已修复的不合理之处

- 已移除“临时会面”常驻侧栏，保留目标人物的建筑入口可达性。
- “当前剧情”只标注真实焦点建筑。
- 地点旁注不再承担任务目标和行动按钮；任务留在 HUD，行动留在底部行动栏。
- 终幕明确支持/质疑选择与信任/怀疑结局对齐。
- 修复后每个带新地点的幕拍都要求先旅行到地点，目标人物、关键物品和敌人位于同一地点，人物对白的“我为何在这里”与地图位置一致。
- 真实 API 返回脱离角色身份的通用问候时，live source 现在拒绝该台词并走同轨角色化 fallback；提示词同时明确禁止“你是来打听事情的吧？想知道什么，直接问我。”这类模板。修复回归局实际拿到的苏绾、陆归鸿对白都承接了身份、线索和信物。
- 场景上下文现在优先把当前主线目标 NPC 作为焦点（上一回合仍是 talk 且未交接时保留原焦点），因此下一幕 NPC 的支持/质疑选项和自由输入会在 ready 场景生成时出现；真实 API 回归验证不再为首次交谈多发一次 talk API。
- 普通敌人战斗按地点组成最多两名敌人组，UI 标题会完整列出敌人，和实际回合队列一致。

### 后续建议

- 增加一轮专门的战斗撤退/失败后果 Chrome 流程，记录失败后的任务状态和敌人再次挑战表现。
- 在 Chrome 中切换窄屏视口，逐项回归背包、任务、日志和减少动态效果。
- AI source 若生成与 act beat 冲突的 NPC/物品/敌人，继续保持“承接上一幕线索”的审批约束。
- P-013 仍需专项设计：单向拾取任务应在任务/物品入口生成时预取下一幕；当前架构仍在玩家拾取后创建 pending job，不能把“已排队”误写成“已预取”。
