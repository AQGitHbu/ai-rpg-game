## 测试中修复的问题

### 1. 未具象化最终幕任务时提前进入结局

第一次流程在第 4 回合直接显示结局，当时故事已跳到目标幕，但目标幕主线任务尚未生成，导致规则引擎把已有任务全部完成误判为可结局。

已在 `src/game/gameplay/rpg/ruleEngine/advanceStoryProgression.ts` 修复：只有当前幕主线任务已存在且全部完成时，才允许生成结局；缺少当前幕任务时继续请求下一幕具象化。

### 2. 动态演化复用 NPC / 任务名称，导致下一幕写回失败

修复提前结局后，第三幕演化提案仍使用重复的“传讯人”和“循迹而行”，被世界状态的重复名称约束拒绝，流程停在“需要下一幕”。

已在 `src/game/application/deterministicEvolutionSource.ts` 增加确定性的重名后缀策略，例如 `传讯人·3`、`循迹而行·第3幕`，并补充回归测试。

### 3. API 调用期间缺失阻塞模态

原状只有场景内的“正在编排下一幕……”或底部状态文字，已有的 `.narrative-generation-modal` CSS 没有对应 JSX 渲染，因此用户无法明确知道页面正在等待 API，也可能误以为操作没有生效。

已恢复统一的 `GenerationStatusModal`，接入：

- 新建游戏生成；
- 序幕确认请求；
- 行动提交；
- 下一幕叙事生成。

Chrome 真机已确认：提交行动后出现遮罩、旋转指示和“正在处理……”；生成下一幕后显示“正在编排下一幕……”，期间人物、行动和对话按钮均禁用。

### 4. 剧情建筑自动聚焦旧 NPC

动态新增 `传讯人·3` 后，进入铁匠铺曾自动打开旧的“传讯人”对话，而 HUD 当前目标已是“与传讯人·3交谈”。

已在 `src/components/AdventureGameShell.tsx` 优先按当前目标解析 NPC，再回退到建筑绑定 NPC，避免进入建筑后打开错误对话。

### 5. HUD 目标文案与实际状态不一致

最终幕任务完成、结局仍在生成时，HUD 曾显示“暂无线索”，与场景中的任务完成提示不一致。

已在 `src/components/AdventureHud.tsx` 优先使用 canonical `currentObjectiveLabel`，并在故事已完成但结局尚未落地时显示“结局生成中”。同时将 API 返回的英文 `Action performed` 映射为“行动已完成”。

## 本轮追加修复的 UI 问题

上一版报告中列出的未修复项已在本轮落实：

1. 场景叙事旁白包含地点描述时，隐藏重复的地点常驻描述；不同内容仍分别展示。
2. 展示层压缩连续的“。。/！！/？？”，不修改后端原始文本和日志内容。
3. 单个 NPC 交谈入口在异步准备正式选项期间显示“正在准备对话……”，避免按钮数量变化没有解释。
4. API 等待模态增加阶段说明、几十秒耗时提示和已等待秒数，长时间生成时能确认页面仍在工作；等待超过 15 秒后提供“重新检查生成状态”入口，叙事轮询也会在短暂失败后继续重试。
5. 小镇侧栏增加地图图例和“当前剧情”标签；剧情建筑描边、发光和呼吸效果增强。
6. 场景没有可用行动时，行动栏显示“等待剧情推进……”，不再留下空白区域。

仍保留为后续产品能力的事项：更细的服务端阶段进度。本轮没有伪造百分比进度，也没有对新建请求增加重复提交重试；叙事生成的重试已限定为重新检查当前 pending 存档状态。
