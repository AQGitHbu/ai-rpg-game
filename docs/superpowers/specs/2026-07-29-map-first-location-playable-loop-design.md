# 地图优先的地点冒险主循环设计

> 状态：已确认设计，等待实现计划
> 日期：2026-07-29
> 范围：单仓 `ai-rpg-game`；不修改 shared foundation，也不调用真实 AI、图片或语音服务。

## 1. 目标

把当前由多个独立面板组成的确定性 RPG 闭环，重组为玩家能够直觉理解的冒险体验：

```text
世界地图 → 选择可前往地点 → 地点场景 → 点击 NPC / 线索 / 物品
→ 固定对话或对应互动 → 规则裁决与任务推进 → 返回地图
```

地图是旅行层，地点是主要游玩层。玩家不再需要从表单式的行动面板中寻找“下一步做什么”；每个地点内可见的角色、线索、物品和目标就是行动入口。

本阶段复用既有移动、观察、交谈、调查、拾取、任务、存档和 battle 规则。它只改变玩家如何看见和触发这些规则，并为 NPC 固定对话选项补齐必要的规则边界。

## 2. 已确认的产品决定

1. 主界面采用地图优先，而不是常驻仪表盘或纯场景优先布局。
2. 点击已解锁地点后进入独立的地点场景；玩家通过明确的“返回地图”回到旅行层。
3. 地点内优先直接点击 NPC、线索、物品等对象；不以固定按钮菜单作为主要入口。
4. 点击 NPC 后先进入对话选项面板；第一阶段只提供由规则决定的固定选项。
5. 第一阶段不使用自由输入、AI 意图识别、AI 对话、AI 叙事、AI 生图或语音。
6. 本阶段先完成探索与地点互动主循环；现有战斗保持功能可用，但不做完整战斗场景重制。
7. 所有背景、地图节点、NPC 剪影、物品和交互图标使用仓库内可审查的 SVG 占位视觉；不得调用外部图片生成服务。

## 3. 玩家体验与信息架构

### 3.1 世界地图（旅行层）

地图打开时，玩家看到：

- 本局世界名、当前主线目标、当前地点、轻量角色状态（例如生命值和背包数量）；
- 已访问、当前、可前往、已知但当前不可直达、以及锁定的地点节点；
- 从当前位置可执行移动的节点，以及锁定节点的明确状态；
- 当前地点节点提供“进入地点”入口；这只是切换到地点场景的 UI 导航，不提交 `move`、不追加事件也不递增 revision；
- 可前往节点点击后执行现有 `move` 规则裁决。移动成功时自动进入目标地点场景；失败时保留地图并显示稳定原因；
- 一个进入角色、背包、任务或冒险记录次级面板的入口；这些信息不得默认挤占地图主体。

锁定节点的可见范围是封闭规则：`worldMap` 只包含 `unlockedLocationIds` 中的地点，加上当前 active 任务 `visit_location` objective 指向、但尚未解锁的目标地点。后者作为锁定节点出现时，使用中性占位名（与既有「探寻未知之地」文案惯例一致）和统一的「尚未解锁」提示，不显示真实名称、描述或解锁条件细节。蓝图中其余未解锁地点完全不出现在地图上。

`unlockedLocationIds` 中但不与当前地点直接连通的节点是“已知但当前不可直达”，显示真实名称但不可点击，并提示“需从相邻地点前往”；它不是锁定节点。只有当前地点的已解锁相邻节点标为“可前往”并可提交 `move`。

地图不显示完整蓝图、隐藏地点内容、未解锁的 NPC、任务内部 ID、seed 或规则状态。

### 3.2 地点场景（主要游玩层）

地点场景由题材化 SVG 背景、地点名称与简短场景描述构成。可互动对象以可见、带文本标签的热点呈现：

| 对象 | 点击后行为 | 现有规则入口 |
|---|---|---|
| NPC | 打开固定对话选项 | 新的 `dialogue_choice` 规则入口 |
| 观察环境 | 确认后观察当前地点 | `observe` |
| 可调查事实 | 打开简短提示并确认调查 | `investigate` |
| 可拾取物品 | 显示物品与确认操作 | `take_item` |
| 可战斗敌人 | 显示遭遇提示 | 既有 `start_battle` |
| 返回地图 | 无状态变化 | 纯 UI 导航 |

观察环境是场景内一个固定热点（不随进入场景自动触发），复用既有 `observe` intent 与 `location_observed` 事件；进入场景本身不写任何状态。

场景中的对象位置不是 AI 输出的自由坐标。每种对象使用有限、响应式的布局槽位（例如左、中、右、前景），由本地纯函数根据稳定 ID 分配；小屏幕转换为同样带标签的纵向对象列表。所有对象必须可以用键盘访问，且不能只依赖颜色传达可用/锁定状态。

### 3.3 NPC 固定对话

点击 NPC 只打开 UI，不立即改写存档。对话面板展示 NPC 的安全身份信息、当前上下文和可用选项。只有选择会改写状态的选项才提交动作。

选项由纯规则依据当前地点、任务、已知事实和 NPC 状态（第一阶段只依赖既有 `met`、任务与事实状态，不新增任何持久化字段）生成。第一阶段的 choice kind 是封闭枚举，服务端按此白名单校验：

- `greet`：仅在 NPC 尚未结识时的初次交谈；
- `ask_main_quest`：仅在当前 active 主线存在尚未满足的 `talk_to_npc` 目标、且目标正是该 NPC 时出现的询问；
- `review_clue`：回顾已经公开的线索。

`choiceId` 必须是当前会话状态的确定性纯函数：采用 `{npcId}:{choiceKind}` 的结构化 ID，同一状态下任意两次投影产生完全相同的 choiceId 集合，保证提交与重算之间不出现非状态原因的假失效。

其中 `review_clue` 是纯 UI 本地展示：所需线索文本已包含在 `dialogue` read model 中，点击后不提交任何 intent、不产生网络请求、不写状态。已经结识且没有当前可问主线的 NPC 只显示此类本地回顾或静态致意，不提交状态动作。只有会改写状态的选项（`greet`、`ask_main_quest`）才提交 `dialogue_choice { npcId, choiceId }` intent；不修改既有 `talk` 的兼容语义。该 intent 由纯 resolver 依据当前状态再次计算 choice 是否可用：`greet` 仅对尚未结识的 NPC 产生既有 `npc_met`；`ask_main_quest` 同样仅对尚未结识的当前目标 NPC 产生该事件，随后由既有 quest reconciliation 满足 `talk_to_npc` objective。已经结识的目标在任务变为 active 时会由既有 fixed-point reconciliation 自动满足，因而不生成无效的重复写入。它不能凭 UI 文案创建奖励、未知事实、关系数值、任务分支或直接完成目标。非法、过期或不再可用的选项必须由服务端拒绝，且零状态写入。

## 4. 架构与规则边界

### 4.1 安全 read model

application 层扩展 `GameSessionView` 或其明确嵌套的只读子视图，提供：

- `worldMap`：节点显示名、状态、题材化 SVG 标识、可移动性和安全提示；
- `locationScene`：地点标题、描述、背景 SVG 标识和可交互对象列表；
- `dialogue`：每个当前可见 NPC 的安全对话资料和选项；UI 点击 NPC 后才展开，不需额外网络请求。与 `presentNpcs`（有意不含 ID）不同，`dialogue` 视图暴露 plain string `npcId` 与每个选项的 `choiceId`，供提交 `dialogue_choice` 使用——口径与既有 `talk` 可用行动视图暴露 npcId 一致，不构成新增泄漏；
- 既有任务、背包、日志、战斗和结局视图继续作为次级信息来源。

UI 只消费 application 门面与 API 返回的 read model；不得读取 `ScenarioBlueprint`、`GameState`、seed、完整任务图、隐藏位置或 SQLite 记录。

### 4.2 行动与持久化

- 地图节点仍经 `move { locationId }` 执行；地点场景只决定展示和导航，不决定移动是否合法。
- 调查、拾取和战斗继续调用既有严格白名单 intent。
- 固定对话选择使用新增 `dialogue_choice { npcId, choiceId }` intent。API 对两个字段严格白名单校验，resolver 根据当前会话重新计算该选项；客户端无法伪造 NPC、选项、奖励或效果。
- 新 UI 只提交 `dialogue_choice`，不再发送 `talk`；`talk` 仅作为 API 兼容入口保留，语义不变。两条路径不得在同一 UI 流程中混用。
- 每个成功的有状态互动仍通过 `performAction` 的 compare-and-swap 一次性持久化；过期 revision 重新读取当前会话；拒绝操作和返回地图不写事件。
- 结局后仍使用既有“普通行动不可用”的规则，地点与地图 UI 只显示结局和只读信息。

### 4.3 SVG 视觉档案

每种游戏类型提供本地 SVG 占位档案：地图基底、地点节点、地点背景、NPC 剪影、线索、物品、敌人与状态图标。资源选择只依赖受校验的游戏类型和地点/对象类别，不能拼接任意路径或接受玩家输入。

七种题材 × 八类资源不要求逐一独立绘制：允许（且推荐）以通用基础形状为底、按题材派生配色与少量装饰的组合策略，只要每个 `(题材, 类别)` 组合都能解析到确定的资源即可。

SVG 是暂时但完整的视觉实现：必须能无网络渲染、含可访问名称、可被未来图片档案替换；它不是接入 AI 生图的变通路径。本阶段不得读取 AI 环境变量、不得发送 fetch 到任何图像服务。

## 5. 错误、降级与兼容

- 缺少或无法加载某个 SVG 时，使用同类型的内联通用图标与文字，不能阻塞进入地点。
- 地图中锁定节点显示 §3.1 规定的统一「尚未解锁」提示，不会发送移动请求。
- 目标已变化、对话选项失效、状态冲突或 API 临时失败时，显示稳定且不泄漏内部细节的提示；状态冲突后重新读取当前会话。
- 本阶段不新增任何 `GameState` / 蓝图持久化字段，不 bump `stateVersion`；地图、场景与对话全部由既有状态投影得出，旧存档零迁移直接可用。不迁移、重写或推测玩家历史。
- 现有表单开局、fallback 开局、离线 fixture、战斗、成功/失败结局和开发环境清档必须继续可用。

## 6. 验收与测试

所有自动验收默认离线、零真实 AI、零图片请求、零 `.env.local` 依赖：

1. 纯投影测试：三种题材的安全地图与地点视图、节点状态、交互槽位和 SVG 档案选择稳定；不泄漏蓝图内部字段。
2. 纯规则测试：NPC 对话选项生成与服务端拒绝分支；选项只能触发允许的现有事实变化。
3. application/API 测试：地图移动、地点互动、过期 revision 与失效对话选项遵守单次 CAS 和零半写入。
4. UI 测试：地图 → 地点 → NPC 对话 / 调查 / 拾取 → 任务更新 → 返回地图；键盘可访问；窄屏断言为结构性检查（渲染为纵向对象列表模式），像素级无横向溢出由真实浏览器人工验收，不由 jsdom 断言。
5. 回归测试：武侠、科幻、都市三种确定性或 fixture 开局完成探索主线并刷新恢复；Phase 6 战斗和双结局仍通过。
6. 视觉资源测试：所有七种题材均有 SVG 占位资源；资源缺失时通用 SVG 降级可用；构建产物和测试中无 AI 图片网络调用。

标准工程验收保持：`npm run lint`、`npm run typecheck`、`npm test`、`npm run test:fast`、`npm run build`、`npm run phase:status`。

## 7. 明确不包含

- 完整战斗场景、随机遭遇、技能、状态、掉落、经验、治疗或装备数值；
- 自由输入、AI 意图识别、AI NPC 对话、AI 场景叙事、记忆或流式输出；
- AI 生图、外部图片服务、真实语音生成或播放；
- 同伴招募与同伴战斗、关系数值、交易、给予、物品使用或多存档；
- 新增无限地点、NPC、任务或不受内容预算约束的世界扩展。

这些能力只有在地图—地点主循环稳定、离线可完整试玩后，才分别设计和实施。
