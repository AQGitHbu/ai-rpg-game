# 开局生成：历史指纹去重与逐步揭示

## 目标

让 API/fallback 自由生成地点、NPC、建筑、线索和任务名称；服务端只负责结构标签、候选校验和近期故事相似度判断。过于雷同的候选重新生成，不通过硬编码名称覆盖来制造差异。

## 方案

1. 开局候选可携带不含实体名的结构标签：场景框架、NPC 功能、线索类型和冲突方式。
2. 编译前从候选提取完整指纹与去除实体名称后的语义指纹。
3. SQLite 单独保存近期同题材开局历史；开发清档只删除当前存档，不删除历史指纹。
4. 新候选与近期历史相似度过高时，向 live/fallback 传递历史摘要和重试次数，最多重试三次。
5. 通过候选保留 AI 自己生成的实体名称；建筑名作为候选字段写入城镇展示 slot，不再由服务端另选锚点覆盖。
6. 开局仍只编译一个地点、一个 NPC、一条主线；后续地点和 NPC 继续由 world evolution + reveal 游标逐步释放。

## 验收

- 同一候选仅改 NPC 名仍被判定为重复。
- NPC 名相同但场景、角色功能、线索和冲突显著不同，不被名字规则误杀。
- 相似候选会触发重新生成，采用的 attempt 写入生成元数据并可重放。
- 清档后历史仍存在，连续新局不依赖进程内内存避重。
- 类型检查、边界测试、全量测试、构建和浏览器多轮新局验证通过。
