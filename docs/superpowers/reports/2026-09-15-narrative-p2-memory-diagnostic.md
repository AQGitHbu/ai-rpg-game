# P2 独立真实记忆诊断

## 结论

`p2-memory-01` 已实际调用配置的 new-api / `ai-slg-game-model`，到第四幕形成56条有效 History。18次行动、59次 HTTP，其中4次摘要请求；4个不同 player preparation job 均未发布摘要，旧事召回未触发。**记忆验收未通过，尚不能判断摘要后回答是否保真。**

本次定位到摘要生成契约与解析契约不一致：解析器限制批次最多4条 History/4个 Event、概览最多8/8，但实际提示只要求选择合法 ID，没有告知数量上限，也未明确优先保留动机、条件与未解决事项。四次响应均返回10条 History、14个 Event，被拒后不推进水位。原始 History 保留，失败没有污染权威游戏状态；重复失败使真正的跨摘要路径无法进入。

这支持先修复摘要选择契约，不支持重做 Entity、增设规划器或继续逐句优化故事。

## 为什么离线通过没有发现它

紧凑离线 fixture 的摘要 source 按测试逻辑返回少量合法 ID，从未要求真实模型理解实际摘要提示。它证明正式链在有效选择下可发布、检索和收束，却没有证明线上提示足以产生有效选择。本次真实响应补上了这一证据，不能用离线通过覆盖它。

来源：`src/game/application/server/ai/liveNarrativeMemorySummarySource.ts` 的系统提示与 `parseMemorySummarySelection` 调用；实际四条摘要请求与响应见 `summary-diagnosis.json`。每次10/14的返回均对应不同 job，非单次 transport 重试的重复统计。

## 后续唯一修复范围

向摘要模型明确传达批次4/4、概览8/8及有用信息的选择目的，提示与解析共享同一限制；保持原文不可改写、引用权限、阈值、水位及失败保留原文的规则。用实际10/14响应补拒绝回归，同时验证发出的两类提示确实包含对应约束。不要用静默截断 ID 把无选择意义的输出变成“成功”。

这项修复后另行冻结真实记忆验证；旧样本继续保留失败。仍需实际两批发布、召回回答保真与作用、同源两臂、UI及整体故事质量，不能因修了提示就宣布P2完成。
