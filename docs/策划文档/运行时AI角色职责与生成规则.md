# 运行时 AI 角色：职责与生成规则

## 1. 概述

当一幕场景需要由 AI 生成时，系统用**三个独立的 AI 角色**接力完成，每个角色是一次单独的请求：

- **世界导演（Director）**：规划这一幕该讲什么、怎么讲。
- **场景编剧（Writer）**：把导演的计划写成玩家能读到的正文、两个选项和 NPC 表演指令。
- **NPC 表演者（NPC）**：只负责当前这一位 NPC 的一句台词（最小知识权限）。

三个角色都关闭模型的"思考/推理"模式，只输出结构化 JSON，输出在本地经过规则审批后才允许进入游戏；审批不过就重试，全部失败则整幕改用确定性兜底文本，绝不把 AI 半成品拼进游戏。

它们的共同前提是**世界蓝图**：所有角色引用的地点、NPC、事实、行动都来自开局时编译好的蓝图。导演可在预算余量内提议新地点/NPC，但必须经独立闸门审批后才追加进蓝图；编剧和 NPC 角色不能新增实体。

## 2. 通用规则（适用于三个角色）

- **只引用既有实体**：所有 ID（地点 / NPC / 事实 / 行动 / 物品 / 敌人）必须从蓝图已存在的实体中选取，不得发明任何未在蓝图中出现的实体、行动或事实。
- **知识分层**：每个角色只拿到它该看到的"最小上下文"，彼此权限不同（详见各角色）。NPC 永远看不到其它 NPC 的私密知识或隐藏事实正文。
- **先审批再写入**：AI 输出先经过纯规则审批，确认结构、引用、知识范围都合法后，才构造正式的批准对象进入游戏；AI 原始对象不直接持久化。
- **有界重试与兜底**：每个角色最多三次尝试，只重试当前失败的角色，不重跑已经批准的上游角色。任一角色用尽尝试则整幕使用确定性 fallback，不拼接部分 AI 输出。
- **纯 JSON、无扩展**：prompt-only 结构化输出，无流式、无图片/语音/视觉生成，无自由文字输入，无意图解析 AI。

审批可能驳回的四类原因（设计层面的"红线"）：

| 驳回类别 | 含义 |
| --- | --- |
| 结构违法 | 字段缺失/类型错、长度或枚举值不合法 |
| 引用断裂 | 引用了蓝图里不存在、或当前不在场的实体 |
| 知识越权 | 使用了超出本角色权限的事实（如引用未揭示或不属于该 NPC 的隐藏事实） |
| 选项不合法 | 选项/行动不是当前合法候选中的既有行动 |

## 3. 角色一：世界导演 Director

**负责内容**：决定这一幕的剧情走向与节奏，给出两个建议玩家行动。它是整幕的"总控计划"，不直接写正文。

**输入（它看得到的）**：世界蓝图（设定、任务结构、当前内容预算）、当前游戏状态、当前合法的行动候选、已发现的事实清单。**当玩家身处一座已生成的小镇（三层地点）时，额外提供该小镇的空间语义**（镇名 + 建筑方位/邻近关系的自然语句，如“铁匠铺位于大石镇北侧”），供导演/编剧在叙事中引用位置关系；该语义只含方位描述，不含坐标、随机种子或完整地图数据。

**输出（它要交出的计划）**：

- `sceneGoal`：本幕目标（1–200 字）。
- `tensionLevel`：张力等级，整数 1–5。
- `pacing`：节奏，枚举 `setup / develop / turn / climax / resolution`。
- `focusNpcId`：焦点 NPC（可为空）。
- `relevantFactIds`：与本幕相关的既有事实。
- `allowedRevealFactIds`：本幕允许向玩家揭示的事实（必须是已发现的事实）。
- `suggestedActionKeys`：两个建议玩家行动（来自合法候选）。
- `introducedEntities`：本幕首次向玩家引入的蓝图实体（本阶段固定为空，仅引用既有实体）。

**硬性规则**：

- 张力等级与节奏必须是合法枚举值。
- 场景目标长度 1–200 字。
- 两个建议行动必须**正好两个、互不相同**，且只能从当前合法行动候选中选取。
- 焦点 NPC 必须确实存在于蓝图，且**当前就在玩家所在地点**。
- 所有事实 ID 必须真实存在于蓝图；可揭示事实必须已经处于"已发现"状态。
- 不得发明任何 ID、地点、NPC、事实或行动。

## 4. 角色二：场景编剧 Writer

**负责内容**：把导演批准后的计划，写成玩家可读的场景正文、两个玩家选项，以及（若本幕有焦点 NPC）给 NPC 的表演指令。

**输入（它看得到的）**：已批准的导演计划、计划允许揭示的事实卡文本、焦点 NPC 档案、两个已批准的行动、有限历史。

**输出（它要交出的脚本）**：

- `narration`：场景正文（1–600 字）。
- `usedFactIds`：本幕实际用到的已揭示事实。
- `npcInstruction`：给焦点 NPC 的表演指令（可选，无焦点 NPC 时为空）。
- `choices`：正好两个玩家选项，每个含 `actionKey`、`label`、`strategy`。

**硬性规则**：

- 正文长度 1–600 字。
- 用到的事实必须是导演"允许揭示事实"的子集（不得引用未揭示或超权事实）。
- 两个选项必须正好两个，且 `actionKey` 必须逐一对应导演计划里的两个建议行动。
- 选项标题 `label` 1–40 字，选项策略 `strategy` 1–80 字。
- 若有 NPC 表演指令：其 NPC 必须是导演指定的焦点 NPC；言语行为（inform/ask/evade/deny/warn/encourage）与情绪必须是合法枚举；其允许使用的事实必须是该 NPC 自身已知事实的子集，且不得撒谎（`mayLie` 固定为 false）。

## 5. 角色三：NPC 表演者 NPC

**负责内容**：只表演当前这一位 NPC 的一句台词，是权限最小、上下文最窄的角色。

**输入（它看得到的）**：该 NPC 的档案、获准且其自身已知（`knownFactIds`）的事实卡、导演/编剧给出的表演指令、有限历史。

**输出（它要交出的台词）**：

- `text`：NPC 台词（1–360 字）。
- `emotion`：情绪，合法枚举（neutral/warm/guarded/afraid/angry/sad）。
- `usedFactIds`：台词中实际用到的事实。

**硬性规则**：

- 台词长度 1–360 字，情绪必须是合法枚举。
- 用到的事实必须落在它被允许的事实卡之内（不得推断或泄漏隐藏事实，不得引用其它 NPC 的私密知识）。
- 仅当导演判定本幕需要补一句 NPC 开场台词（如标记为需要 NPC 台词）时才调用；不是每幕都出现。

## 6. 协作次序与失败处理

```text
导演 Director → 规则审批
  → 编剧 Writer → 规则审批
    → NPC 表演者（仅当本幕需要 NPC 台词时）
      → 整幕以"已批准"状态写入，玩家可见
```

- 只重试当前失败的角色，不重跑已批准的上游角色（导演通过就不因编剧失败而重跑导演）。
- 任一角色用尽三次尝试 → 整幕改用确定性 fallback，不拼接部分 AI 输出。
- 处于战斗或结局中、或当前合法非战斗行动少于两个时，不生成普通场景（避免 AI 伪造选项或强行推进）。

## 7. 与蓝图的关系

- 三个角色引用的所有事实、地点、NPC、行动都来自开局编译好的世界蓝图；蓝图是编剧和 NPC 的"只读规则书"。
- 导演可在预算余量内提议新地点/NPC（`proposedNewLocations` / `proposedNewNpcs`），但这些提议必须经独立闸门审批（终幕不扩、硬顶不扩、软顶不扩）后才由服务端铸 ID 追加进蓝图；编剧和 NPC 不能新增实体。
- 所谓"新人物 / 新地点 / 新道具登场"，在场景生成中**只表示首次向玩家引入蓝图里已经存在的实体**；运行时新增实体只走上述扩展闸门。
- 玩家最终看到的每个地名、NPC 名、事实与两个选项，都经过上述角色生成 + 本地规则审批后才进入游戏。
