# 共享模块开发流程

> 仅当项目根 `AGENTS.md` 的共享基础设施触发条件命中时阅读。

## 公共仓库定位

- 公共仓库名：`ai-game-foundation`。
- sibling 主仓默认路径：相对游戏主仓解析 `../ai-game-foundation`。
- 项目根 `.ai-game-foundation.json` 是 agent 和脚本的机器可读定位文件；其中路径必须使用相对路径，不能提交个人机器的绝对路径。
- 如果仓库不在默认 sibling 位置，使用 `AI_GAME_FOUNDATION_DIR` 覆盖本地路径。
- `.foundation` junction 与 Next.js 本地联调要求游戏和 foundation 位于同一文件系统；三个内部仓库必须使用同一父目录和文件系统，不用绝对路径绕过。
- 游戏位于 `.worktrees/<name>` 时，locator 通过 Git common dir 找到游戏主仓，并优先选择 foundation 的同名 `.worktrees/<name>`；不存在时才回退 foundation 主仓。
- 本地 package 通过项目内被忽略的 `.foundation` junction 暴露为稳定 `file:.foundation/packages/<package>` 路径，禁止把 worktree 绝对路径写进 package.json 或 lockfile。
- 共享 package 不发布外部 registry，确定性 `dist/` 随 foundation 提交；消费者的 `setup` 只建立 `.foundation` 链接并安装自己的依赖，禁止从消费者脚本对 foundation 执行 `npm ci` 或 build，避免多个项目并发写同一目录。
- 修改共享 package 的 agent 必须在 foundation 自己的 worktree 执行 install/build/test，提交源码与更新后的 `dist/`，再运行两个消费者合同；消费者不能依赖另一次开发遗留的未提交产物。
- 提交共享 UI 前运行 `npm run verify:ui-dist`；命令会重新构建并拒绝未纳入提交的 `dist/` 变化。
- `docs/共同规范/` 是已提交的消费副本，权威源始终位于 foundation；禁止直接修改同步副本。
- package 必须声明 `private: true`；package 版本记录内部 API 契约，实际依赖固定使用 `file:.foundation/packages/<package>`。
- 跨仓变更在 foundation 执行 `npm run ready:family`；命令从 `project-family.json` 读取清单，并把三个同名 worktree 视为一个原子验收集合。缺少同名 worktree 时默认失败，不允许 agent 静默混用 main。
- `ready:family` 是项目族基础门禁，不替代各项目完整的浏览器、视觉、真实 AI 或长流程验收；具体计划必须另列这些验收。

## 决策

1. 已有 `@ai-game/*` package 覆盖职责：先修改 foundation，再升级当前项目。
2. 新能力第一次出现：在当前项目实现，保持 facade、测试和清晰边界。
3. 第二个真实消费者出现：比较输入、输出、错误语义和依赖；只有交集稳定且无产品概念时抽取。
4. 名称相同但规则或状态语义不同：继续分别维护。

## 抽取前提

- 两个生产项目真实使用；
- 公共实现不 import 任一项目 domain；
- 有 public API、独立测试和两个消费者 contract test；
- 更新 package 版本并说明兼容性；
- 在三个同名 worktree 中验证两个消费者。

## 跨仓落地顺序

```text
foundation 分支
→ package 测试
→ 两个消费者契约测试
→ npm run ready:family
→ foundation、SLG、RPG 依次提交、合并和推送
```

消费者只从 package public export 导入，禁止 deep import。公共修改不得只在 foundation 自测后直接合并。

## 内部依赖契约

- `ai-game-foundation`、SLG、RPG 都是 Private GitHub 仓库；新机器和 CI 必须同时检出三个 sibling 仓库。
- 禁止为 `@ai-game/*` 配置 npmjs.org、GitHub Packages 或其他外部 registry，也禁止提交 registry token。
- `npm pack --dry-run` 仅审计 package 内容，不表示允许发布。
- 将来确需私有 registry 时，先写 ADR 明确访问控制、费用、密钥轮换、CI 和回滚，再统一迁移三个仓库。
