# AI 游戏项目族定位与共享实践备忘

> 日期：2026-07-26
> 权威位置：`ai-game-foundation/packages/standards/docs/`
> 消费副本：各游戏仓库的 `docs/共同规范/`，由同步命令生成，禁止直接修改

## 1. 形成背景

`ai-slg-game` 已积累 Next.js、文档路由、分层边界、测试、AI transport、日志、持久化和 UI 原语等成熟实践。启动 `ai-rpg-game` 时，目标不是复制 SLG，也不是预先设计一个覆盖所有游戏的通用引擎，而是把已经被两个真实产品证明相同的能力逐步沉淀到 `ai-game-foundation`。

本备忘记录三个仓库的定位、相互关系和共享能力的实际操作方式，避免 agent 因只看到当前仓库而复制公共代码，或在一个项目中修改公共能力却不知道另一个消费者的影响。

## 2. 仓库定位

```text
F:\AI2\
├── ai-slg-game\          # 已成熟的策略游戏产品及现有经验来源
├── ai-rpg-game\          # AI 动态生成世界的单人叙事 RPG 产品
└── ai-game-foundation\   # 已验证的跨游戏规范与公共 package
```

### `ai-slg-game`

- 产品定位：三国题材、季度同时回合、战略经营与战争演绎。
- 当前职责：维护 SLG 玩法、领域模型和产品 UI；提供已有实现作为共享候选的比较对象。
- 不是 foundation 的源码镜像；公共能力迁出后应通过 `@ai-game/*` public API 消费。

### `ai-rpg-game`

- 产品定位：玩家选择游戏类型并输入角色资料、世界观背景和故事开端，AI 生成受规则约束且可完成的单人 RPG 世界。
- 当前职责：维护动态场景、NPC、任务、战斗、记忆、世界状态和 RPG 业务 UI。
- 不复制 SLG 玩法；需要通用 UI、AI transport 等能力时按共享流程处理。

### `ai-game-foundation`

- 产品定位：公共基础仓库，不是第三个游戏，也不是预设的完整游戏引擎。
- 当前职责：共同规范、共享模块目录，以及已经存在两个真实消费者的 `@ai-game/*` package。
- 禁止放入任一游戏的 GameState、任务语义、战斗公式、地图规则、题材 prompt 或业务 UI。

## 3. 已确认决策

1. 三个仓库是 `F:\AI2` 下的 sibling 独立 Git 仓库。
2. 公共 package 使用 `@ai-game/*` scope；发布后由 registry 分发并使用精确版本。
3. 本地 bootstrap 通过 `../ai-game-foundation` 或 `AI_GAME_FOUNDATION_DIR` 找到公共源码，不提交个人绝对路径。
4. 不建立独立的完整 engine 仓库；只有稳定交集逐包进入 foundation。
5. 共同文档的权威源在 `@ai-game/standards`，两个游戏生成并提交 `docs/共同规范/` 副本，agent 不读取 `node_modules`。
6. 根 `AGENTS.md` 保持简短；只有命中共享触发条件才读取共享流程和目录。
7. UI 是 RPG 开发阶段的第一项共享实践，但只抽取两个项目真实使用的无业务原语；对白、地图、HUD、主题和玩法组合仍留在产品项目。
8. AI transport 在 RPG 首次真实接入模型时进行第二项共享实践；共享 HTTP/超时/取消/错误契约，不共享题材 prompt、输出 schema 或账户业务。

## 4. 共享判断流程

```text
当前项目出现需求
→ 查询共享模块目录
→ 已有 package：在 foundation 修改，跑 package 测试与两个消费者契约测试
→ 没有 package，但另一个产品存在真实同语义实现：比较契约，抽取稳定交集
→ 只有一个消费者：保留项目内 facade 与测试，登记候选但不创建空 package
→ 名字相同、业务语义不同：继续分别维护
```

抽取必须同时满足：两个生产消费者、无产品 domain import、稳定 public API、package 独立测试、两个消费者 contract test、明确版本和回滚方式。

## 5. UI 共享实践

第一批只考虑 RPG 当前里程碑真实使用且 SLG 已验证的基础原语：按钮、Panel、状态 Tag，以及需要时的 Tabs/Surface 可访问性交互。共享层负责语义结构、键盘操作、焦点与稳定 class/token 契约；SLG 和 RPG 分别提供主题。

明确不共享：

- SLG 的 `GameViewport`、地图 HUD、势力/城市/武将组件；
- RPG 的视觉小说对白布局、角色创建页、场景布局和选择项业务逻辑；
- 题材颜色、背景图、字体搭配和产品级 CSS；
- 为尚未使用的组件预建 API。

执行顺序：写公共 API Spec → 在 foundation 建 package 和独立测试 → SLG 适配且视觉/交互不回退 → RPG 接入 → 两边 contract test → prerelease/stable。当前本地阶段可用精确 `file:` 依赖联调，registry 可用后改为精确发布版本。

## 6. AI 共享实践

`@ai-game/ai-transport` 的候选交集包括 OpenAI-compatible 请求、并发限制、超时、取消、流式传输和稳定错误结果。SLG 的账户配置、密钥加密、季度计划 prompt，以及 RPG 的世界蓝图、意图、对白和记忆 schema 均不属于公共 transport。

API Key 只放各项目未提交的 `.env.local`：`AI_API_KEY`、`AI_API_BASE_URL`、`AI_MODEL`。公共 package 只接收调用方传入的配置，不自行读取产品环境变量。

## 7. Agent 操作约定

普通玩法任务只读取当前项目文档。遇到 `@ai-game/*`、通用 UI/AI/日志/配置/测试工具、另一个游戏已存在的同语义实现，或用户要求两个项目同步优化时，才读取：

- `docs/共同规范/共享模块开发流程.md`
- `docs/共同规范/共享模块目录.json`
- 本备忘
- 项目根 `.ai-game-foundation.json`

公共变更必须列出两个消费者影响。发布新版本不会自动改变未升级项目；每个项目独立升级、测试和提交。若当前会话没有 sibling 写权限，应申请权限，不能在产品仓库静默复制公共实现。

## 8. 当前状态

- `@ai-game/standards`：已建立，两个游戏都应同步消费。
- `@ai-game/ui`：已确认第二个消费者与抽取方向，等待首批 RPG UI 需求形成 public API Spec 后实施。
- `@ai-game/ai-transport`：已确认候选，等待 RPG 首次真实 AI 调用时实施。
- 完整 game engine：未建立；后续逐模块用真实证据判断。
