# 共同游戏开发规范

> 本文档只记录跨项目稳定工程规则。具体目录、系统入口和例外留在各项目。

## 依赖方向

领域类型和纯规则不依赖 UI、store、API 或 provider。玩法规则不依赖 application/UI。UI、store 和 API 通过 application facade 使用玩法能力。

## AI 边界

Provider 调用只在 server-only 代码中发生。AI 输出必须先经过类型、枚举、ID、长度和越权校验；失败必须记录原因并走可用 fallback。

## 测试与边界

新增模块应有同目录测试。跨层路径变化必须更新自动边界测试。公共 package 只能从 public export 导入，禁止 deep import。

## 日志与追踪

系统边界、关键决策分支和失败路径必须可观测。异步玩家请求应携带同一个 traceId；日志不得记录密钥或完整认证信息。

## 共享基础设施

是否需要读取完整流程由各项目根 `AGENTS.md` 的触发条件决定。新能力第一次出现默认留在项目内；已有共享职责或第二个真实消费者出现时才评估 foundation。

跨仓修改必须在三个同名 worktree 中完成，并由 foundation 的 `npm run ready:family` 做原子验收；只有单仓业务修改时才运行该项目自己的门禁。共同入口不改变“先在产品中证明，再抽取交集”的原则。
