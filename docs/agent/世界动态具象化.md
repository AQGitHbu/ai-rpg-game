# 世界动态具象化

## 系统定位

开局只生成一个可完成的开局切片：故事契约（幕数、中心冲突、两个抽象结局方向）、世界前提、玩家、序幕、一个起始地点、一名开场 NPC、一条活动主线与开场事实。不再生成完整的未来实体蓝图。运行时世界演化只在剧情需要且预算允许时按需具象化新地点、NPC、物品、敌人、下一幕主线或结局对；所有候选先审批再写入，保证每局有变化但仍可完成。

## 正式支持范围

- 产品 UI 只开放 `short`（短篇）与 `medium`（中篇）。
- 开局只铸造 `loc_0` / `npc_0` / `quest_0` 与开场目标所需事实；不命名或持久化未来 NPC、地点、任务、敌人或具体结局。
- 短篇与中篇分别使用有界主线幕数和软顶预算；到达终幕、达到软顶/硬顶或预算边界后停止扩张。
- 长篇/开放式在 segmented ledger 专项 Spec/Plan 完成前不属于正式产品能力，不得宣称无限扩张或无限记忆。

## seed 与每局差异

- 同一输入与同一 seed 生成相同规则结构，支持确定性 reload/replay。
- 不同 seed 必须改变结构化世界组合，而不只是改一段文案；回归至少比较世界名、地点顺序/名称或 NPC 身份组合。
- 玩家选择在同一 seed 内继续造成结构化分叉：关系、NPC 情绪/历史、候选事件、可达路线和结局都可不同。
- seed 不绕过类型、引用完整性、预算、任务可达性和双结局校验。

## 世界演化闭环

```text
成功玩家回合 / 场景编排
  → deriveEvolutionNeed（none | next_act | pacing | ending_pair）
  → 仅 need !== "none" 时调用演化源
  → WorldDeltaProposal（纯字符串引用）
  → approveWorldDelta（类型、ID、引用、预算、节奏、收束、结局对）
  → materializeWorldDelta（服务端铸品牌化 ID、装配预览状态）
  → 与场景写回同一受控 CAS 原子持久化
```

- `StoryEvolutionState` 持久化 ID 铸造序号（location/npc/item/enemy/fact/quest/ending ordinal）与状态（`stable` / `needs_next_act` / `needs_ending_pair`）。
- 演化需求纯领域派生：幕完成 → `needs_next_act`，节奏低 → `pacing: complicate | escalate`，终幕 → `needs_ending_pair`；正常对话回合返回 `none`，不调用演化源。
- 未知实体引用回合可走修复路径：把行动引用 ID 原样铸造为缺失实体（kind 对齐），再以预览状态重演算；成功则单次 CAS 提交。
- 新地点写入后立即解锁并建立双向连接；NPC/物品/敌人必须挂到有效地点索引；新 NPC 进城镇时绑定第一个空闲剧情建筑 slot。
- 终幕只按故事契约的两个抽象方向（trust/doubt）铸造一对互斥结局，不存在预生成的隐藏任务图。
- proposal 无效、source 失败或预算不足时零演化写入，主故事使用现有实体继续。
- AI 只提案；ID 铸造、引用解析、预算消费、任务与结局始终由规则负责。

- `src/game/domain/openingGenerationCandidate.ts` — 开局切片候选与解析。
- `src/game/gameplay/rpg/openingGeneration/` — 开局切片校验与编译。
- `src/game/gameplay/rpg/worldEvolution/` — `deriveEvolutionNeed` / `approveWorldDelta` / `materializeWorldDelta`。

- `src/game/application/worldEvolutionSource.ts` / `deterministicEvolutionSource.ts` / `server/ai/liveWorldEvolutionSource.ts` — 演化 port 与 live/fallback。
- `src/game/application/generatePendingScene.ts` / `performTurn.ts` — 场景与回合编排联动。
- `src/game/application/server/ai/openingGenerationSource.ts` — live 开局切片候选。
- `src/game/application/server/ai/sourceFactory.ts` — live/fallback 装配。

## 主要验收

- 开局恰一地点/一 NPC/一活动主线；同 seed 创建结果结构相等，不同 seed 的结构化世界至少一项不同。
- 首次对话后下一次叙事写回具象化新 NPC 与（地点或物品），下一场景提及已批准名称。
- 演化 proposal 的非法/越权/超预算引用被拒绝且零写入；source 失败零写入并可继续主流程。
- 复用、收束、预算耗尽与 source 失败均能继续主流程。
- 完整旅程跨地点、候选事件、战斗抵达结局；同 seed 的不同选择抵达不同 ending ID。

## 修改注意事项

- 预算数值只从 domain policy 读取，prompt、validator 和 UI 不复制另一份事实。
- 不为未落地的长篇能力放宽 hard limit 或使用伪无限数值作为产品承诺。
- 新实体必须服务当前主线缺口、角色选择后果或可完成路线，不能成为无规则引用的背景填充。
- 不再恢复旧蓝图聚合、旧全量世界候选、旧 `expansion` 管线或旧 `town ensure` 路由。
