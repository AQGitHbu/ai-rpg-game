# 世界动态具象化

## 职责

世界演化把当前故事需求转换为受预算、题材、可达性和实体一致性约束的 `WorldDelta`。审批器负责规则闸门与 ID 铸造，materializer 负责预览状态；应用层负责把批准结果与叙事 bundle 原子写回。

## 当前契约

- `deriveEvolutionNeed` 优先处理下一幕或结局对；stable 状态在幕数与事件预算满足时也可派生 complicate/escalate 节奏需求，其他情况为 none。需求经生产决策包处理，不启动独立 world provider。
- `approveWorldDelta` 校验形状、引用、预算和硬上限、重复名称、题材词、地点容量、主线目标可达性以及 NPC 与目标地点共址。新地点、NPC、物品、敌人、事实、任务和结局 ID 由服务端铸造。
- 动态物品可按场景拾取或同批 NPC 对话给予装配；取得方式、归属与赠予条件统一见[物品与任务奖励](物品与任务奖励.md)。
- 动态地点区分世界地图地点与当前城镇 `town_building`；后者复用城镇建筑 slot，不铸造地图节点。满槽建筑容量和同批 NPC 的 `locationRef` 由审批约束。
- 下一幕主线地点必须从玩家当前地点可接入；主线目标物品/敌人必须与新地点共址。NPC 目标必须位于可达目标地点，否则返回 `unreachable_objective` 或相关拒绝码。
- 调查方式为可选的 2–3 条公开 label/hint；允许复用事实关键词，禁止完整复制 secret fact 正文。非法列表按规则过滤为自动揭示，不阻塞本轮。
- trust/doubt 结局方向由规则依据关键 NPC 关系铸造；provider 不能提交结局 requirements、立场或终幕 choices。
- 实体生成与玩家可见释放分离：同包可批准后续结构，`StoryState.reveal` 只释放当前目标所需实体。已存在于 store 的未来 NPC、物品或敌人不因此成为玩家已知内容。
- P1 递送契约的 `recipientKey` 指向最终幕主线对话目标。该幕获批具象化时才把目标 NPC 绑定到 `StoryState.delivery.recipientNpcId`，绑定后不因称呼或新文案改变；开局只绑定唯一交付物与委托人，不提前创建接应人。实际持有仍只读 Entity，完成须有对该接应人的成功交付事件及当前 owner 一致。
- 新 NPC 的初始知识只能由审批产生的 `npcCreationComponentsById` 写入，来源固定为 `initial_world`。`newNpc.existingFactIds` 可省略（等于空数组），只能显式引用当前实体上下文闭包中已有 `known + public + initial_world` 权威来源的事实；重复、未知、私密、条件披露、仅玩家已发现或闭包外引用均拒绝，不从角色描述、目标或台词推定知识。同批 `npc_private` 事实保持 `discovered=false`，不会从兼容 `NpcEntry.memory` 或未来步骤推导给玩家或其他 NPC。后续披露必须经过 NPC 权限和实际 audience 的规则结算。

## 关键流程

```
deriveEvolutionNeed
  → NarrativeBundleSource 提交 worldDelta
  → approveNarrativeBundle（含 approveWorldDelta 与 materializeWorldDelta）
  → explicit NPC creation layers + materialize preview
  → one CAS with scene, events, memory and bundle
```

生产 world delta 使用 `compileDecisionNarrativeContext` 提供的同包上下文，包含已批准实体、占用名称、空间与物品状态和需求约束；不另调 world source。生成与重试契约见 [运行时 AI](运行时AI导演与场景表演.md)，prompt 约束不替代规则审批。
