# 蓝图动态化

## 系统定位

开局生成器根据玩家选择的题材、时长与 seed 产生结构化世界；运行时 expansion 只在剧情需要且预算允许时提出新地点、NPC、事实、物品或敌人。所有候选先审批再写入，保证每局有变化但仍可完成。

## 正式支持范围

- 产品 UI 只开放 `short`（短篇）与 `medium`（中篇）。
- 开局生成包含可完成的主线、至少两个结局、地点/NPC/任务/敌人/物品及起始锚点。
- 短篇与中篇分别使用有界主线幕数和扩展预算；到达 climax/resolution、终局或预算边界后停止扩张。
- 长篇/开放式在 segmented ledger 专项 Spec/Plan 完成前不属于正式产品能力，不得宣称无限扩张或无限记忆。

## seed 与每局差异

- 同一输入与同一 seed 生成相同规则结构，支持确定性 reload/replay。
- 不同 seed 必须改变结构化世界组合，而不只是改一段文案；回归至少比较世界名、地点顺序/名称或 NPC 身份组合。
- 玩家选择在同一 seed 内继续造成结构化分叉：关系、NPC 情绪/历史、候选事件、可达路线和结局都可不同。
- seed 不绕过类型、引用完整性、预算、任务可达性和双结局校验。

## expansion 闭环

```text
PendingNarrativeJob / 当前世界缺口
  → expansion trigger
  → ExpansionSource proposal
  → approveExpansion（类型、ID、引用、预算、节奏、收束）
  → applyExpansion（服务端铸 ID、解锁/双向连接/挂载索引）
  → 与玩家回合或场景 write-back 的受控 CAS 持久化
```

- 已有合适实体时优先 reuse，不为“看起来更丰富”无条件新增。
- 明确目标不存在时可提出补齐，但仍需通过同批 ID 唯一、跨批引用、地点连通和预算检查。
- 新地点写入后立即解锁并建立双向连接；NPC/物品/敌人必须挂到有效地点索引。
- proposal 无效、source 失败或预算不足时零 expansion 写入，主故事使用现有实体继续。
- AI 只提案；ID 铸造、引用解析、预算消费、任务与结局始终由规则负责。

## 主要文件

- `src/game/domain/budgetPolicy.ts` / `storyBudget.ts` — 时长与内容预算。
- `src/game/domain/worldGenerationCandidate.ts` — 开局候选合同。
- `src/game/gameplay/rpg/worldGeneration/` — 候选校验与编译。
- `src/game/gameplay/rpg/expansion/` — trigger、审批与应用。
- `src/game/application/createGame.ts` — seed 驱动开局编排。
- `src/game/application/expansionProposer.ts` — 运行时扩展编排。
- `src/game/application/server/ai/worldGenerationSource.ts` — live 世界候选。
- `src/game/application/server/ai/liveExpansionSource.ts` — live expansion proposal。
- `src/game/application/server/ai/sourceFactory.ts` — live/fixture/fallback 装配。

## 主要验收

- 同 seed 创建结果结构相等，不同 seed 的结构化世界至少一项不同。
- proposal 的非法/越权/超预算引用被拒绝且零写入。
- 复用、收束、预算耗尽与 source 失败均能继续主流程。
- 完整旅程跨地点、候选事件、战斗抵达结局；同 seed 的不同选择抵达不同 ending ID。

## 修改注意事项

- 预算数值只从 domain policy 读取，prompt、validator 和 UI 不复制另一份事实。
- 不为未落地的长篇能力放宽 hard limit 或使用伪无限数值作为产品承诺。
- 新实体必须服务当前主线缺口、角色选择后果或可完成路线，不能成为无规则引用的背景填充。
