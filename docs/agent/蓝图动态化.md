# 蓝图动态化

## 系统定位

时长档位（GameLength）驱动的 BudgetPolicy 替代旧冻结常量 CONTENT_BUDGET，主线幕数可变（3/5/8），运行时世界导演可提议新地点/NPC，或为当前原子事件懒提议一个事实/物品/敌人，经闸门审批后追加进蓝图并持久化。

## 当前规则摘要

- 开局时由 `NewGameInput.gameLength`（short/medium/long/open，默认 open）决定本局 BudgetPolicy。
- 旧存档无 `budgetPolicy` 字段时回退到 `LEGACY_BUDGET_POLICY`（等价旧 CONTENT_BUDGET 语义：3 幕、主地点恒 4）。
- 终幕判定不再硬编码 stage 3，改为 `finalMainActOf(blueprint)` 读取 policy.mainActs。
- 导演可在场景生成时提议新地点/NPC，或在 `investigate` / `item` / `battle` 原子事件中最多提议一种对应的新资源；提议经纯函数闸门审批，通过后由服务端铸 ID 并以 CAS 追加进蓝图。
- 扩展审批失败不影响场景生成——场景照常保存，扩展被静默丢弃。

## 当前实现现状

### BudgetPolicy 档位表

| 档位 | mainActs | 开局主地点 | 地点软顶 | NPC 软顶 | 地点硬顶 | NPC 硬顶 |
|---|---|---|---|---|---|---|
| short | 3 | 3–5 | 8 | 10 | 40 | 30 |
| medium | 5 | 3–5 | 14 | 16 | 40 | 30 |
| long | 8 | 3–5 | 22 | 24 | 40 | 30 |
| open | 5 | 3–5 | 无 | 无 | 40 | 30 |

开局预算全档位统一：主地点 3–5、隐藏 1、NPC 4–6、同伴 1、支线 2、结局 2、town 2。

### LEGACY 回退

`budgetPolicyOf(blueprint)` 返回 `blueprint.budgetPolicy ?? LEGACY_BUDGET_POLICY`。LEGACY 等价旧语义：mainActs 3、mainLocationsMin/Max 均 4、expansion {8, 10}、safety {40, 30}、gameLength "short"。

### 扩展闸门顺序与拒绝码

`approveBlueprintExpansion`（纯函数，`src/game/gameplay/rpg/narrative/approveBlueprintExpansion.ts`）按固定顺序检查：

1. `none_proposed` — 导演未提议任何新实体
2. `invalid_payload` — 名称/描述/理由长度越界、scale 非法、connectFromLocationId 不存在、NPC locationId 无效
3. `pacing_locked` — 当前节奏为 climax 或 resolution 时不扩张
4. `endgame_locked` — 终幕主线 active 或全部主线 completed
5. `soft_cap_reached` — 地点/NPC 数量达到 policy.expansion 软顶
6. `hard_cap_reached` — 地点/NPC 数量达到 policy.safety 硬顶
7. `connect_not_unlocked` — 新地点的 connectFromLocationId 不在已解锁集合中
8. `town_cap_reached` — 新地点 scale 为 town 且 town 数量已达 opening.townLocationsMax

通过后返回 `{ ok: true, expansion: ApprovedBlueprintExpansion }`，逐字段重建（不返回 AI 原对象引用）。

### compileBlueprintExpansion（铸 ID）

纯函数（`src/game/gameplay/rpg/narrative/compileBlueprintExpansion.ts`）：

- 新地点 ID：`loc_dyn_<n>`（扫描既有 `loc_dyn_*` 取 max+1）。
- 新 NPC ID：`npc_dyn_<n>`（同理）。
- 新事实/物品/敌人 ID：分别为 `fact_dyn_<n>` / `item_dyn_<n>` / `enemy_dyn_<n>`；新事实进入当前地点的未发现事实，新物品挂到当前地点，新敌人进入蓝图并等待战斗规则裁决。
- 新地点 kind 为 main、双向连通 connectFromLocationId、自动加入 unlockedLocationIds。
- 新 NPC 若 `locationId === "new:0"` 则落位到新铸地点 ID。
- 追加 `blueprint_expanded` 事件到 eventLedger。
- 返回 `{ nextBlueprint, nextState, newFactId, newItemId, newEnemyId }`，地点/NPC/资源 ID 同时写入 `blueprint_expanded` 结构索引事件。

### applyBlueprintExpansion（CAS 持久化）

`GameRepository.applyBlueprintExpansion`（`src/game/application/server/persistence/sqliteGameRepository.ts`）：

- 单事务 UPDATE games SET blueprint_json = ?, state_json = ?, revision = revision + 1 WHERE game_id = ? AND revision = ?。
- 与 applyResolvedAction 共用 CAS 语义；冲突返回 STALE_GAME_REVISION。

### 编排集成

- `orchestrateNarrativeScene` 成功路径：导演计划批准后调用 `approveBlueprintExpansion`，结果存入 `OrchestrateSceneResult.expansionDecision`。
- `generatePendingNarrativeScene`：expansionDecision.ok 时调用 `compileBlueprintExpansion` + `applyBlueprintExpansion`（蓝图与状态同事务）；否则走 `applyResolvedAction`。
- fallback 路径：`expansionDecision: { ok: false, reason: "none_proposed" }`。

### DirectorContext 扩展信号

`toDirectorContext`（`src/game/application/runtimeNarrativeContexts.ts`）注入：

- `expansionAllowed: boolean` — 非终幕 && 未达硬顶 && 未达软顶。
- `remainingLocationBudget: number | null` — 软顶余量（open 档位为 null 表示无限制）。

导演 prompt 指示：仅当 expansionAllowed 为 true 时才提议；每次最多一个地点 + 一个 NPC。

### 导演输出修复

`liveRuntimeNarrativeSources.ts` 中 `repairLocationProposals` / `repairNpcProposals`：丢弃式修复——数组非法则返回 `[]`，绝不使场景失败。

## 修改注意事项

- BudgetPolicy 数值表唯一事实源在 `budgetPolicy.ts`；validator / schema / prompt / 闸门一律引用本模块，禁止另写字面量。
- 扩展审批失败绝不使场景失败；丢弃式修复（malformed 数组 → []）。
- 每次扩展最多一个地点 + 一个 NPC + 一种事件级资源；事件级资源必须与当前原子事件类型和地点匹配。
- 资源仍不携带任务或结局；它们只进入蓝图/事实/地点可取得物/战斗候选，由规则层继续独占结算。
- `applyBlueprintExpansion` 与 `applyResolvedAction` 共用 revision 序列；交错调用安全。
- 旧存档 schemaVersion 保持 1；多出的旧 `contentBudget` JSON 字段被忽略。
