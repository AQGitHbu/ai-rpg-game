# 探索与任务推进

## 系统定位

探索、调查、交谈、移动、拾取与战斗结果由 ruleEngine 产生结构化事件，再由任务 reconciliation 推进 objective、主线幕和可达路线。AI 文本与玩家宣称都不能直接完成任务。

## 当前规则

- `explore`：观察当前地点并产生正式 `location_explored` 类主事件。
  - 探索的服务端合法性与 AI 提案候选只在当前地点存在可探索内容时成立（2026-08-10 方案 1 修订）：仍有未发现的线索事实、未满足的地点相关目标（visit_location / discover_fact），或候选事件池中有涉及当前地点的有效（未过期）候选事件。
  - **探索与实体处理分离**：探索动作不替代拾取或攻击（分别走独立 take_item / attack 入口），但场景存在未处理物品或敌人时允许先观察现场；完全没有实体或线索的地点仍不显示探索，避免空转按钮（2026-08-12 真机覆盖修复）。
  - 判定实现：`src/game/application/buildChoiceMap.ts` 导出 `hasExplorableContent(ws, ss)`；choice map 与场景候选共用该判定，地点组件不再渲染底部行动栏。
- `investigate`：保留为历史 action 的规则兼容入口，但当前 read model/choice map 不投影调查方式。所有当前 `discover_fact` 目标都在规则边界自动确认，避免纯点击调查造成无意义回合。
- `talk`：目标 NPC 必须在场；NPC 对话会更新结构化关系/记忆，并可满足交谈目标。
- `move`：未到访目标必须已解锁且与当前位置相邻；已解锁且已到访地点允许从地图直接回访（不要求仍与当前位置相邻），目标不能是当前位置；成功更新 current/visited location。
- `take_item`：物品必须存在、位于当前地点且未拥有。
- `attack` / `battle_action`：只有合法敌人与 active battle 可推进 defeat objective。
- objective 支持 visit location、talk to NPC、obtain item、discover fact、defeat enemy；完成/解锁/失败/结局只由规则事件触发。

## Plan 3 NPC 连续性边界（待验收）

- `talk`、赠物和 NPC 任务使用同一个 `projectNpcRuntimeProfile`/Entity Store 投影。只有任务 objective 明确指向某 NPC 且该 NPC 参与本轮时，才写关系或知识后果；纯地点、物品或敌人目标不猜测“关键 NPC”关系。
- 赠物的 `gave_item` signal 只在明确 NPC owner 且规则允许时产生；需要回报的物品类型才开启 debt，普通物品不自动制造承诺。事实发现仍由规则自动确认，传播由 `FactChange.audience` 显式限制。
- 动态具象化产生的新 NPC 只有在 approved creation components 已存在时才能进入任务链；其 typed goals、位置和有向关系 seed 与同一次 world delta/scene CAS 写回，未释放实体不会提前成为可执行目标。

## 2026-08-24 移动与 prepared continuation

- `move` 走即时规则结算，并在同一次 StateCommit/CAS 中消费正式 NPC 回合已经审批的 `PreparedContinuationState` step；命中时零 live/world/provider 调用，按 post-commit revision 铸造当前 scene 的 choice token。prepared 内容缺失或图与权威事件不匹配时返回稳定 continuation 错误并零写入，绝不在动作路径转 live source 或生成 deterministic fallback。历史 investigate step 仅兼容旧状态。
- `take_item` 没有可消费步骤时是规则拥有的物品边界，写入 `source="rule"` 场景；回退到已访问非目标地点和 active battle round 同样只走规则 CAS。幕推进/结局对需要的世界演化必须在此前被允许的 provider job 内完成，不能由线性动作补发 provider。
- 2026-08-29 v7 修订：`give_item` 与 `move`/`battle_*` 一样必须消费 `narrativeBundle` 的权威步骤，步骤键由 `narrativeBundleTriggerKey` 归一。缺步时返回 `NARRATIVE_CONTINUATION_MISSING` 并零写入，不再退回 rule-owned 场景；因此 `gameSessionView` 只在当前束真正持有活跃 `give_item` 步骤时才投影「给予道具」按钮，避免下发必然失败的死按钮。

## 2026-08-29 任务链空窗桥接目标

- 上一任务刚结算、AI 尚未在后续束中铸造后继任务时，`currentObjectiveOf` 返回 null，HUD 会显示「暂无线索」而玩家其实仍有可执行行动。
- `gameSessionView` 此时按 `在场 NPC → 未到访已解锁地点 → 可探索内容` 派生一个桥接目标，同时下发 `currentObjectiveLabel` 与可执行的 opaque token（地点行动栏同步投影该 `ask` 入口，保证 token 可提交）。
- 战斗中被战斗面板接管、结局抉择有专属标签、任务链尚未开启（零任务）三种情况不桥接。
- 后继任务一旦铸造，`currentObjectiveOf` 重新取得权威地位，桥接自动让位；桥接不写入任何状态，只是读模型派生。

## 2026-08-23 对话收尾 handoff

- 普通焦点 NPC ready scene 固定为两个对白选项；完成所需对话轮次且 objective 已推进时，同一次 scene 生成 NPC 最后一段直接回应和一个唯一 handoff choice。该 choice 是玩家承接 NPC、前往下一任务/地点/人物的真实 opaque Action，不生成第二个选项，也不以“知道了”结束。
- `gameSessionView` 将唯一 scene choice 挂到旧 NPC 的 `handoffChoice`，不重复投影到底部 `narrative.choices`；只有非焦点零回合闲聊继续使用“知道了”。

- handoff acknowledgement 是本地 UI 关闭动作：不创建 actionId、choiceToken 或 pending job，不改变 revision/turn/location，也不显示“等待 NPC”。

## 2026-08-25 调查方式下线与远端事实任务链

- 无论事实是否带历史 `investigationApproaches`，规则都在当前成功行动的 reconciliation 边界自动写入一次 `fact_discovered`，事件省略 approach/evidence/tension 元数据；一次最多推进一个 `discover_fact` 目标。
- 同一提案创建 world 新地点与事实时，objective 顺序为 `visit_location → discover_fact → ...`，事实 `locationId` 与新地点一致，新地点由首个 visit 目标释放。玩家先从地图进入正确场景，抵达后再自动确认事实。
- 2026-08-26：`resolveTurn` 在回合边界先推进故事揭示游标，再执行自动事实发现，确保 `visit_location → discover_fact` 的移动完成后不会出现“已到达但没有可操作项”的死路。
- `buildChoiceMap`、`GameSessionView` 和地点组件不再投影调查方式或底部行动栏；地图 travel、NPC 卡片、场景热点和战斗面板是当前交互入口。`investigate` 规则结算仍为旧存档兼容，不是新玩家路径。
- 自动揭示、目标推进和 eventLedger 写入都由规则层完成；`generatePendingScene` 与即时场景 write-back 只消费已结算结果，不能重复裁决事实或修改 tension。reload 只恢复已经写入的事件，不等待不存在的调查 pending。
- AI 仍可携带历史调查方式字段以兼容旧内容，但审批后的字段不再生成玩家入口，不能改变地点、任务顺序或规则结算。

## 原子性

- 一次成功 Action 的状态转移、任务 reconciliation、候选事件激活和 provider job 由一个 StateCommit 提交；若 action 命中 prepared step，规则结果、scene 物化、token 铸造和 continuation 消费也在该 CAS 中完成。
- `revision` 是唯一 CAS；stale/非法选择零写入且不部分完成 objective。
- 场景生成 write-back 不重新执行任务规则。

## 动态世界

- expansion 可以在任务角色/地点缺口、低张力或候选事件需要时提出新实体。
- 已有合适实体时优先 reuse；新实体通过类型、引用、预算、节奏与收束审批后才可加入世界。
- 终幕、resolution、soft/hard limit 或 budget exhausted 时停止扩张，保持主线可完成。

## 修改注意事项

- objective 只能读取 `WorldState` 已提交事实，不读取 narration 或玩家原文。
- 新任务必须有可验证 objective、解锁路径与至少一个可达结束条件。
- UI 只提交 opaque token 或 free text；不得直接提交 location/fact/quest effect。
