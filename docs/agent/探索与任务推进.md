# 探索与任务推进

## 职责

本系统把探索、交谈、移动、拾取、战斗结果和事实发现转换为结构化事件，再由任务 reconciliation 推进 objective、主线幕、可达路线和结局条件。叙事文本与玩家宣称不能直接完成任务。

## 当前契约

- 当前客户端不提供泛化 `explore` 或“继续追查”兜底按钮；环境观察直接展示。独立 scene 的已批准主动调查由 `currentLocation.investigations` 投影安全 label、hint 与 opaque token。内部 `explore` 可承载已批准的具体目标建筑抵达步骤，只有匹配当前目标与活跃 bundle 时才下发建筑入口 token。
- `investigate` 仍在 Action 与 bundle trigger 中，但主动调查只接受 `discoveryMode="investigation"` 的当前独立 `scale="scene"` 事实；服务端经 `src/game/gameplay/rpg/investigation` facade 投影当前可执行的安全 label/hint/action，不返回事实正文。每条调查事实必须有 2–3 个合法方式；requirements 每次重查，witness NPC 必须 active 且与玩家同场。town 建筑不等于 scene 内位置，不能授予调查资格。
- `discoveryMode="automatic"` 是唯一允许零行动揭示的路径；普通事实即使残留旧 `investigationApproaches` 也不自动变成主动调查。主动调查成功才写入 `investigationSource`、approach/evidence/witness 事件，并只把知识写给实际见证 NPC；玩家私下调查不广播。
- 后果绑定审批检查当前已物化调查片段的封闭依赖：所有方式都依赖自身事实、相互调查或无法达成的目标状态时拒绝；已有可行替代方式可打破环。该检查不推演整个世界的物品取得或未来任务路径。
- 主动调查成功后，服务端以事实从未发现→已发现、匹配方式和同批 `fact_discovered` EventId 生成 `investigation_result` proof；没有有效 bundle 时才进入同一 A/B 生成链。真实移动到已访问地点后，只有该地点已有 `narrative_scene_presented` 且该场景之后的已提交历史中出现与地点/在场角色相关的可见目标、承诺、知识或物品变化，才生成 `changed_revisit` proof；玩家在外取得且被该地点 active NPC 已批准目标条件或合作前提明确引用的事实发现事件也可作为回访来源；仍需玩家可见且晚于该地点最后已展示场景，只放行生成，不给旧 NPC 自动授知。普通移动、首次到访、UI 导航和无变化回访不生成。
- 本轮实际行动提交后，`npcGoals` 会消费同批已提交事件：clean/noisy 见证和明确 `share_known_fact` 的来源分别影响对应 NPC；目标变化写 `npc_goal_status_changed`，Quest 的 talk objective 可带 `completionConditions`，必须满足条件且有本人实际交谈事件；满足后不再受普通两轮会话门槛限制。合作定义再约束引荐/核验的可用性。私下事实不会经摘要或作者文案替代告知。
- `talk` 要求 NPC 在场；`move` 要求目标地点已解锁且可从当前位置到达，已访问地点可从地图回访；`take_item` 要求物品属于当前地点且尚未拥有。
- `attack` / `battle_action` 只处理合法敌人与 active battle。任务 objective 支持访问地点、交谈 NPC、取得物品、发现事实和击败敌人。
- `town_building` 是当前城镇内的建筑承载，不铸造世界地图地点；需要离镇旅行时才使用独立 `world` placement。
- 生产 `move`、`explore`、`take_item`、`give_item` 和战斗边界只消费 `narrativeBundle` 的权威步骤；缺步骤返回稳定 continuation 错误并零写入。`PreparedContinuationState` 仅用于 offline fixture。
- 回访结果的当前候选可聚焦与来源事实有明确条件引用的在场 NPC；后续实际交谈沿用在场的 job focus，不强制使用场外 Quest 目标 NPC。继续未完成交谈目标时，B 可明确准备该目标 NPC 所在的已访问相连地点 `move` 续接；审批重新按当前 Quest、位置和邻接关系求图，玩家实际选择才移动。该续接不自动抢占旧 NPC 的告知/合作选择，也不使普通移动获得生成资格。
- 递送物仍由玩家持有且原委托人在场时，B 可提出精确绑定 itemId/giverNpcId 的 `give_item` 返还续接；审批只准备该步骤，实际返还仍需玩家选择，解除委托另选 `abandon_quest`。普通开局不因存在委托人而被强制切到返还路径，错误对象或未准备续接不产生物品流转。
- 任务链短暂没有 active objective 时，read model 可派生在场 NPC 或未到访地点的桥接目标；桥接不写入状态，权威任务铸造后自动让位。不以泛化探索充当下一幕或终幕生成入口。
- 场景拾取与 NPC 给予的规则见[物品与任务奖励](物品与任务奖励.md)。旅行、交付和开战仍需明确玩家选择。
- 主线 `StoryState.threads` 是开放问题、冲突和承诺后续的权威投影；只有与本批已提交事件相关的 Thread 才会追加证据，非空 closure 条件全部满足才可收束。没有显式 closure 的 question 在绑定任务完成后只推进为 advanced，`ending_reached` 不证明疑问已有答案。`unresolvedThreads` 仅由它派生，不单独维护；有限委托的终幕许可见 [战斗与结局](战斗与结局.md)。
- `abandon_quest` 是唯一的主动退出入口：只接受当前 active 主线，提交 `quest_abandoned` 后进入失败态并按是否仍持有任务物品解除或违约承诺；移动、普通交谈和自由输入不能隐式放弃，也不销毁或转移物品。

## 必要流程

```text
合法 Action → resolveTurn → 自动揭示 / objective reconciliation / candidate event
→ committed event 与状态变更 → 生产 bundle step 消费
→ GameSessionView 投影下一入口
```

移动抵达场景地点后，规则先推进揭示游标，再自动确认连续的 automatic 事实目标；调查事实必须由已释放的 `investigate` action 选择方式完成。城镇容器不证明已经到达目标建筑，其事实由具体建筑抵达边界承接。AI 场景内容表达规则结果，不决定事实发现或张力数值。地点层与正文 fixed choice 都消费服务端 investigation facade 和同一 opaque Action 身份，不能自行复制过滤逻辑。

开局与 decision bundle 的 `consequenceBindings` 只在完整候选预览中原子安装目标、调查、任务条件和合作条款；绑定本身不完成调查、不授予知识，也不写虚假行动。
