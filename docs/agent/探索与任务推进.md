# 探索与任务推进

## 职责

本系统把探索、交谈、移动、拾取、战斗结果和事实发现转换为结构化事件，再由任务 reconciliation 推进 objective、主线幕、可达路线和结局条件。叙事文本与玩家宣称不能直接完成任务。

## 当前契约

- `explore` 只在当前地点存在未发现事实、地点相关目标或有效候选事件时合法；探索不替代拾取或攻击。
- `investigate` 保留在 Action 与 bundle trigger 中，供显式 offline fixture 或内部规则测试消费；新 read model 不投影调查方式，当前 `discover_fact` 目标由规则边界自动确认，一次最多推进一个目标。
- `talk` 要求 NPC 在场；`move` 要求目标地点已解锁且可从当前位置到达，已访问地点可从地图回访；`take_item` 要求物品属于当前地点且尚未拥有。
- `attack` / `battle_action` 只处理合法敌人与 active battle。任务 objective 支持访问地点、交谈 NPC、取得物品、发现事实和击败敌人。
- `town_building` 是当前城镇内的建筑承载，不铸造世界地图地点；需要离镇旅行时才使用独立 `world` placement。
- 生产 `move`、`explore`、`take_item`、`give_item` 和战斗边界只消费 `narrativeBundle` 的权威步骤；缺步骤返回稳定 continuation 错误并零写入。`PreparedContinuationState` 仅用于 offline fixture。
- 任务链短暂没有 active objective 时，read model 可派生在场 NPC、未到访地点或可探索内容的桥接目标；桥接不写入状态，权威任务铸造后自动让位。

## 必要流程

```text
合法 Action → resolveTurn → 自动揭示 / objective reconciliation / candidate event
→ committed event 与状态变更 → 生产 bundle step 消费
→ GameSessionView 投影下一入口
```

移动抵达目标地点后，规则先推进揭示游标，再自动确认当前事实目标，避免到达后没有可执行项。场景生成只消费已经结算的结果，不重新发现事实或修改 tension。
