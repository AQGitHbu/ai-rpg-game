# 物品与任务奖励

## 系统定位

物品是结构化世界实体。玩家只能通过服务器下发的合法 `take_item` 选择取得当前地点物品；背包事实可满足 `obtain_item` objective。AI、UI 与自由文本都不能直接把物品或奖励写入存档。

## 当前规则

- 物品必须存在并挂到有效地点；动态扩展物品也必须通过 proposal 审批和服务端 ID 铸造。
- `take_item` 检查当前地点、可取得索引和背包去重；非法、异地或重复取得零写入。
- 成功取得在同一个规则 CAS 中更新 inventory、地点可取得索引、结构化事件、任务进度和下一幕 pending。
- `obtain_item` objective 只读取 inventory 事实。
- `GameSessionView` 只投影玩家可见的名称、描述和 opaque choice；不泄露内部 item ID、候选 effect 或隐藏任务条件。

## 当前能力边界

- 已实现取得、背包展示、任务物品推进和结构化 reload。
- 未承诺物品使用、给予、交易、装备数值效果、随机掉落或奖励经济；这些能力不能以无效按钮或 AI 文案伪装。

## 主要文件与测试

- `src/game/domain/worldState.ts` — items、inventory、地点物品索引。
- `src/game/gameplay/rpg/ruleEngine/` — take_item 校验/结算与任务 reconciliation。
- `src/game/gameplay/rpg/expansion/` — 动态物品审批与挂载。
- `src/game/application/gameSessionView.ts` — obtainable/inventory read model。
- `src/game/application/testing/foundationJourney.test.ts` — 拾取、reload 和后续幕推进。

## 修改注意事项

- 展示元数据不参与战斗或任务规则，除非先扩展 domain 与 ruleEngine。
- 新物品必须有规则用途、任务锚点或明确可见取舍，不能只为叙事装饰持续膨胀存档。
