# 物品与任务奖励

## 职责

物品是结构化世界实体。系统负责物品可取得性、背包事实、`obtain_item` objective 和与任务推进相关的事件；AI、UI 和自由文本不能直接写入物品或奖励。

## 当前契约

- 物品必须挂到有效地点；动态物品先经 world proposal 审批，再由服务端铸造 ID。
- `take_item` 校验当前位置、地点可取得索引和背包去重；非法、异地或重复取得零写入。
- 成功拾取在一次规则 CAS 中更新 inventory、地点索引、committed event 和任务进度。
- `obtain_item` 只读取 inventory 事实。读模型只投影玩家可见名称、描述和 opaque choice。
- 城镇物品由读模型稳定分配到一个剧情建筑，避免跨建筑重复显示；建筑展示归属不构成第二份物品持有事实。
- 生产 `take_item` 与 `give_item` 都消费匹配的 bundle 步骤，缺失时零写入；无 bundle 的直接拾取提交仅属于显式 offline fixture。
- 当前未提供物品使用、装备数值、交易、随机掉落或通用奖励经济；没有对应规则的能力不生成按钮。

## 必要流程

```text
地点可取得物品 → opaque take_item choice → validate / resolve
→ inventory + location index + event + objective → 单次 CAS
→ bundle scene（offline fixture 可直接规则提交）
```
