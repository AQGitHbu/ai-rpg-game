# 物品与任务奖励

## 状态

Phase 5 已实现完成（2026-07-27）。玩家可以在蓝图预定义的地点取得一个可验证的关键物品，背包事实推进 `obtain_item` objective，主线第二阶段完成并解锁第三阶段；全过程保持一次 revision compare-and-swap 写入与刷新恢复。

背包界面重构已完成（2026-07-30）：四分类页签（装备/道具/材料/任务）+ 物品图标网格 + 选中物品详情（稀有度/等级/属性行/描述），挂载在冒险弹层背包页签。

## 设计边界

- 物品定义和可取得位置属于已编译 `ScenarioBlueprint`；UI、API、自由文本和 AI 都不能凭空新增或把物品写入 `GameState`。
- 初始装备与地点可取得物品是不同来源：初始装备只在初始化时进入背包，不能由地点再次取得。
- `take_item` 只能取得玩家当前地点中、尚未拥有的预定义物品；重复、未知、异地或非可取得物品必须返回稳定拒绝码且零写入。
- `obtain_item` 只读取 `GameState.inventory` 这项规则事实。任务 reconciliation 仍是唯一任务状态推进者。
- 取得物品、任务完成/解锁、事件账本和 revision 必须经既有 `performAction` 的一次 compare-and-swap 持久化；不得另开 SQL 写入。
- Phase 5 不含 `use_item`、给予、交易、装备/数值效果、奖励随机化、战斗、敌人掉落、失败或结局。
- 物品展示元数据（category/rarity/level/statLines）仅供背包界面展示：全部为可选字段，缺省由 `resolveItemPresentation` 按 kind 确定性推导；数值不进战斗/任务结算，旧存档蓝图零迁移可用；AI 结构化输出格式（strictObject）未扩展，AI 候选一律走推导兜底。

## 实现记录

- 蓝图：`LocationDefinition.availableItemIds`（`src/game/domain/scenarioBlueprint.ts`）显式表示地点可取得物品；候选校验保证引用存在、同一物品落位唯一且不与初始装备冲突；fallback 模板把 stage 2 的 key 物品（`item_key`）预置在 `loc_3`。
- 行动：`take_item { itemId }` 只能取得当前地点、尚未拥有的预定义物品；稳定拒绝码 `UNKNOWN_ITEM` / `ITEM_NOT_AVAILABLE_HERE` / `ITEM_ALREADY_OWNED`，拒绝零写入；成功追加 `item_obtained { itemId, locationId, occurredAt }` 并写入 `GameState.inventory`。
- 任务：`obtain_item` objective 以背包是否含目标 ID 判定；stage 2 的 talk + key item 两个 objective 齐备后完成并解锁 stage 3，行动与任务事件同一次 CAS 写入；`defeat_enemy` 仍未支持（视图 `supported: false`）。
- Read model / UI：`GameSessionView.obtainableItems`（当前地点可取得物品摘要）与 take 可用行动；`inventoryItems` 已升级为 `InventoryItemView` 富视图（name/description + category/rarity/level/statLines/icon，不泄漏物品 ID/tags），`initialItems`/`obtainableItems` 保持简单形态；API 严格白名单解析 `take_item`（多余目标字段 400）；`src/components/ItemPanel.tsx` 展示可拾取物品与背包（无生产引用，被边界守卫钉死保留）。
- 背包界面（2026-07-30 重构）：
  - domain：`src/game/domain/itemPresentation.ts` — `resolveItemPresentation` 纯函数按 kind 推导缺省 category（weapon/armor/gear/talisman/equipment→equipment；key/quest→quest；material/ore/herb→material；其余→consumable）、rarity（quest→rare，其余→common）、icon（sword/armor/trinket/potion/material/key）；`ItemDefinition` 新增可选 `category/rarity/level/statLines`。
  - gameplay：`validateScenarioBlueprint.ts` 新增 `INVALID_ITEM_PRESENTATION` 校验（枚举合法、level ∈ [1,99] 整数、statLines ≤ 6 且条目非空）；`createFallbackBlueprint.ts` 升版 `fallback-4`，七题材模板物品全部携带显式展示元数据（phase1 fixture pin 已同步重算）。
  - application：`gameSessionView.ts` 的 `InventoryItemView` 投影 + facade 导出展示元数据基础类型。
  - UI：`src/components/InventoryPanel.tsx`（四页签 + 图标网格 + 详情，本地 UI 状态，零 fetch）与 `inventoryVisuals.tsx`（六类内联 SVG 占位图标，currentColor 随稀有度着色）；`AdventureDetailsPanel` inventory 分支改用 InventoryPanel；样式在 `globals.css`（`--rarity-*` 变量 + `.inventory-*`）；依赖边界新增 InventoryPanel/inventoryVisuals 门面守卫。
- 回归：`src/game/application/phase5ItemQuestRegression.test.ts` 对武侠/科幻/都市三个固定 seed fixture 跑真实临时 SQLite 全旅程：创建 → 移动完成 stage 1 → 抵达 key 地点 → 交谈 → 取得 key → stage 2 完成 / stage 3 解锁 → reload 视图一致；内容预算不变、`item_obtained` 事件与背包物品恰好一份、重复取得被拒且零写入。

未实现：`use_item`、给予、交易、装备/数值效果、奖励随机化、战斗、敌人掉落、失败与结局。
