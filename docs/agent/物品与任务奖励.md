# 物品与任务奖励

## 状态

Phase 5 已规划，尚未开始（2026-07-27）。本阶段只让玩家在蓝图预定义的地点取得一个可验证的关键物品，并用背包事实推进 `obtain_item` objective，完成主线第二阶段、解锁第三阶段。

## 设计边界

- 物品定义和可取得位置属于已编译 `ScenarioBlueprint`；UI、API、自由文本和 AI 都不能凭空新增或把物品写入 `GameState`。
- 初始装备与地点可取得物品是不同来源：初始装备只在初始化时进入背包，不能由地点再次取得。
- `take_item` 只能取得玩家当前地点中、尚未拥有的预定义物品；重复、未知、异地或非可取得物品必须返回稳定拒绝码且零写入。
- `obtain_item` 只读取 `GameState.player.itemIds` 这项规则事实。任务 reconciliation 仍是唯一任务状态推进者。
- 取得物品、任务完成/解锁、事件账本和 revision 必须经既有 `performAction` 的一次 compare-and-swap 持久化；不得另开 SQL 写入。
- Phase 5 不含 `use_item`、给予、交易、装备/数值效果、奖励随机化、战斗、敌人掉落、失败或结局。

## 预期完成事实

- `ScenarioBlueprint` 显式表示地点可取得物品，并由候选校验保证引用存在、地点唯一和不与初始物品冲突。
- `take_item { itemId }` 产生 `item_obtained`；read model 只投影当前地点可取得物品和玩家背包中允许展示的摘要。
- `obtain_item` objective 以背包是否含目标 ID 判定；第二阶段的 talk + key item 两个条件齐备后完成并解锁第三阶段。
- 三种固定 seed 的真实 SQLite 回归证明：创建 → Phase 4 旅程 → 抵达物品地点、交谈、取得 key → stage 2 完成 / stage 3 解锁 → reload；同物品不能重复取得，拒绝和冲突不写入。
