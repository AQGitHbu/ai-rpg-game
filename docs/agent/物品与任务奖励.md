# 物品与任务奖励

## 职责

物品是结构化世界实体。系统负责物品可取得性、背包事实、`obtain_item` objective 和与任务推进相关的事件；AI、UI 和自由文本不能直接写入物品或奖励。

## 当前契约

- 动态物品先经 world proposal 审批，再由服务端铸造 ID。`newItem.acquisition` 可为 `scene` 或 `npc_gift`，省略时按场景拾取；`npc_gift` 必须与同批次、同地点的新 NPC 及主线任务一同批准。
- `take_item` 校验当前位置、地点可取得索引和背包去重；非法、异地或重复取得零写入。
- 场景物品由玩家点击拾取，在一次规则 CAS 中更新 inventory、地点索引、committed event 和任务进度。主线需要该物品不构成自动拾取授权。
- `obtain_item` 读取持有或已取得事件事实。NPC 给予目标额外保存服务端铸造的 `giftFromNpcId`；物品最初归该 NPC 持有，不进入地点可拾取索引。该 NPC 的正式对话本轮刚完成、目标推进到对应赠品且归属仍匹配时，规则在同次对话 CAS 中将物品转给玩家，追加带赠予者来源的 `item_obtained` 事件，并推进任务。仅有 NPC 持有、玩家索要文本或 AI 赠予台词都不能授权转移。
- NPC 给予结果随本轮规则结果提供给叙事生成，直接进入背包，无额外 Action、拾取按钮或 AI 请求；生成失败仍按同一 job 重试。玩家规则见[玩家行动与反馈](../策划文档/AI生成RPG_MVP.md#5-玩家行动与反馈)。读模型只投影玩家可见名称、描述和 opaque choice。
- 城镇物品由读模型分配到一个剧情建筑，避免跨建筑重复显示；建筑展示归属不构成第二份物品持有事实。进入建筑展示其物品热点，不因到达城镇而自动取物。
- 生产 `take_item` 与 `give_item` 都消费匹配的 bundle 步骤，缺失时零写入；无 bundle 的直接拾取提交仅属于显式 offline fixture。场景拾取和玩家向 NPC 交付保留明确选择，AI 台词不能直接转移物品。
- 当前未提供物品使用、装备数值、交易、随机掉落或通用奖励经济；没有对应规则的能力不生成按钮。

## 必要流程

```text
地点可取得物品 → opaque take_item token → validate / resolve
→ inventory + location index + event + objective → 单次 CAS
→ bundle scene（offline fixture 可直接规则提交）
```
