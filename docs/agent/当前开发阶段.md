## 当前已实现

- Phase 0 新游戏资料 UI；`@ai-game/ui@0.1.0` 真实消费者；worktree-aware foundation 定位与共同规范检查。
- Phase 1 领域基线（不依赖 UI/数据库/AI）：
  - `src/game/domain/newGame.ts`：`NewGameInput` 契约与 `validateNewGameInput`（收集全部错误、品牌化 `ValidatedNewGameInput`、稳定错误码）。
  - `src/game/gameplay/rpg/scenario/gameTypeProfiles.ts` + `data/base/*.json`：7 个游戏类型与艺术风格 profile 及 loader。
  - `src/game/domain/scenarioBlueprint.ts`、`gameState.ts`、`events.ts`：蓝图/运行时类型、`CONTENT_BUDGET` 冻结常量、9 种品牌化实体 ID。
  - `src/game/gameplay/rpg/scenario/questGraph.ts`：任务图循环检测（迭代 Tarjan）与双结局可达性分析。
  - `validateScenarioBlueprint.ts` / `compileScenarioBlueprint.ts`：候选蓝图校验（collect-all 诊断）、编译铸造与 `GameState` 初始化。
  - `createFallbackBlueprint.ts` + `data/fixtures/phase1/*.json`：确定性 fallback 生成（FNV-1a + mulberry32，digest 覆盖全部影响输入），武侠/科幻/都市三类型跨进程钉值 fixture。
  - `src/dependencyBoundaries.test.ts` + `phase1Regression.test.ts`：依赖边界守卫（别名与相对路径双拦截）与全链路聚合回归。
  - 同输入 + seed + templateVersion 生成相同蓝图；三类型均通过校验且两结局可达；当时测试规模 12 文件 / 229 用例。
- Phase 2 创建游戏与本地存档（已完成，全部为确定性 fallback，无真实 AI）：
  - `src/game/application/createGame.ts` / `getCurrentGame.ts` / `openingGameView.ts`：`createGame` use case（domain 校验 → fallback 生成 → validate/compile → 原子保存）、`getCurrentGame` 与 `OpeningGameView` 投影（不泄漏 blueprint/state/seed/inputDigest）；`index.ts` 是 UI/API 唯一游戏业务门面（含 `validateNewGameInput` 转发与纯端口类型再导出）。
  - `src/game/application/server/persistence/`：`gameRepository.ts` 纯端口（类型 + `asGameId`，无 libsql）；`sqliteClient.ts`——全库唯一允许 import `@libsql/client`、读 `GAME_DB_PATH` 与感知数据库路径的文件（含 `typeof window` 运行时守卫，`server-only` 包未安装）；`sqliteGameRepository.ts` 事务化 adapter：`createInitialGame` 原子写入，失败无半初始化数据，结果区分无存档/损坏/冲突/基础设施失败。
  - `src/game/application/server/compositionRoot.ts`：生产装配点（真实 repository + UUID gameId + 随机 seed + 真实时钟）；只有 server 层读 `process.env`；浏览器/API 无法指定 seed、gameId 或数据库路径。
  - `src/app/api/game/`（POST 创建，201/400/409/422/503/500 稳定错误码）与 `src/app/api/game/current/`（GET 恢复）：thin adapter，仅注入组合根单例，异常文本不外泄。
  - `src/components/NewGameSetupForm.tsx`（真实提交 + 门面预校验）、`CurrentGameScreen.tsx`（挂载时恢复当前存档，corrupt 按 reason 分支文案）、`OpeningGameView.tsx`（纯展示开场 read model）。
  - 边界与静态守卫（`src/dependencyBoundaries.test.ts` 扩展）：UI/API/store 只许消费 `@/game/application` 门面，domain/gameplay/server 持久化均禁止直连（别名 + 相对路径双拦截）；server-only 静态守卫锁定 `application/server` 仅三个合法入口（层内、门面对纯端口、api 对组合根），`@libsql/client` 与 `process.env` 不离开 server 层。

已验证闭环：表单创建 fallback 世界 → SQLite 原子写入 → 开场视图（只含允许信息）→ 刷新恢复同一存档；无效输入、生成失败、数据库失败（故障注入已测）或重复创建均不产生半存档。`next build` 通过且客户端 chunk 不含 libsql/`GAME_DB_PATH`。测试规模 22 文件 / 322 用例。

## Phase 4 计划范围

- 增加 `move`，并按连通与解锁状态裁决；
- 建立纯任务 reconciliation，推进 visit/talk/discover objective 和 unlock_quests；
- 将 read model/UI 从开场专用信息扩展到当前地点和 active quests；
- 继续使用 revision compare-and-swap 原子续存档与同仓 API。

不实现自由输入、AI、物品、战斗、失败/结局、多存档或新共享 UI。详细任务与验收以本阶段唯一 Plan 为准。

## 开始与完成

1. 在主工作区 `main` 执行 `npm run phase:start`；实现 agent 只在该阶段 worktree 修改 RPG。
2. 完成时同步所有 agent 文档与索引，将机器状态设为 `completed / implemented`，但不自动切到 Phase 5。
