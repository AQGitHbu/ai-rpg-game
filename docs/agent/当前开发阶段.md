## Phase 4A 已实现

- 契约与 port（`src/game/application/scenarioGeneration.ts`，纯 TypeScript，无 IO）：`ScenarioCandidateSource` 单方法 port、`SCENARIO_CANDIDATE_CONTRACT_VERSION = "phase4a-v1"`、11 个稳定失败类别（含 `invalid_json`、`schema_violation`、`timeout`、`rate_limited`、`service_error`）与仅供内部的生成阶段事件（`requested` / `candidate_received` / `validating` / `repairing` / `retrying` / `falling_back` / `completed`，经 `generationObserver` 进 contract test 与结构化日志，不随玩家 API 返回）。
- server-only fixture source（`src/game/application/server/ai/fixtureScenarioCandidateSource.ts` + `data/fixtures/phase4/`）：版本化 JSON fixture 模拟合法候选、可修复候选、超时、不可修复引用与跨类型内容；`manifest.json` 的 `expectedStages` 是事件序列唯一事实来源，契约回归直接消费。仅用于开发与测试，永不进生产装配。
- `createGame` 编排（`src/game/application/createGame.ts`）：source 请求候选，最多 2 次尝试；每次尝试允许一次机械确定性修复（移除未知根字段、trim 字符串、裁剪超预算数组，修复后必须重新完整校验）；全部失败走既有 `createFallbackBlueprint`。候选与 fallback 一律经 validate/compile 后原子写入 SQLite，失败无半存档。结果携带 `source: "generated" | "fallback"`。
- 生产 composition root 注入 `createUnavailableScenarioCandidateSource()`：真实 AI 尚未接入，玩家路径稳定走确定性 fallback；`@ai-game/ai-transport` 与外网调用留给 Phase 4B。
- `POST /api/game` 201 body 精确为 `{ view, generationSource }`（仅二元安全值）；GET current 不含该字段。`NewGameSetupForm` 等待态（"正在生成世界"、提交期间禁用表单）+ `parseGenerationSource` 严格收窄（缺失/未知值不默认 generated）；`CurrentGameScreen` 仅在本次创建后显示一次性 fallback 降级提示（刷新/行动/清档后消失，不持久化）。
- 守卫与回归：`dependencyBoundaries.test.ts` 增补 Phase 4A 合成违例与专项扫描（fixture source server-only、不 import 持久化，domain/gameplay 不 import scenarioGeneration port）；`phase4aScenarioGenerationRegression.test.ts` 覆盖三类型合法 fixture（generated）与三失败 fixture（fallback）的事件契约、reload、内容预算/双结局与零泄漏。
