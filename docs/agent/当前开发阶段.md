# 当前开发阶段

> 当前阶段：动态世界具象化与情境化叙事 MVP 收口
> 状态：已实现，待本页验收命令复核（worktree `.worktrees/dynamic-story-materialization`，分支 `codex/dynamic-story-materialization`）

## 阶段目标

- 开局只生成可完成的开局切片：故事契约（幕数/中心冲突/两个抽象结局方向）、世界前提、玩家、序幕、1 个起始地点、1 名开场 NPC、1 条活动主线与开场事实；不再生成完整未来实体蓝图。
- 每个 ready 场景走一次场景表演调用：分段旁白逐段对应服务端强制节拍（≤8），`objectiveLink` 与权威当前目标一致，焦点 NPC 只收到隔离记忆（最近 5 条结构化交互、回应政策、允许披露事实，不含玩家原文与未披露私密正文）。
- 世界演化是按需的可选调用：仅 `EvolutionNeed !== none`（幕推进/节奏/终局对）时触发；AI 只提案，审批后服务端铸造 ID，与场景写回同一受控 CAS 原子持久化。
- 终幕按 trust/doubt 两个抽象方向具象化互斥结局对；不存在预生成的隐藏任务图。
- 城镇层确定性重建：几何与剧情建筑 slot 开局预分配，运行时 NPC 绑定 slot；无 `/api/game/town/ensure` 路由、无 AI 生图。
- 无需玩家决策的 pending 在创建新局/成功回合后立即后台排队：序幕阅读期间静默预生成，协调器按 `gameId + jobId` 去重，客户端 ensure 只作恢复；序幕确认状态在并发 scene CAS 中单调保留。
- 场景候选不足时先进行 `scene_candidate_shortage` 受控演化再重建候选；明确 NPC talk 行动首击即提交，不制造二次确认或假等待。
- 保持六个 `/api/game/**` route、单次规则 CAS 与独立 scene CAS、确定性 fallback/回放；正式产品只开放短篇与中篇。

## 生产运行链

```text
CurrentGameScreen / AdventureGameShell / TownLayerScreen
  → POST /api/game/actions
  → compositionRoot.performTurn
  → performTurn（规则审批、任务/关系/知识/结局、派生 ObjectiveTransition + 强制节拍、单次规则 CAS）
  → GameRepository.applyState（revision CAS）
  → PendingNarrativeJob
  → BackgroundEnsureCoordinator（快速排队 / gameId + jobId 去重）
  → generatePendingScene
       └（可选）world-evolution：EvolutionNeed → proposal → 审批 → 铸 ID → 预览状态
       → scene-performance proposal（分段旁白 / objectiveLink / 焦点 NPC 台词 / 合法选项）
       → approveScenePerformance
  → GameRepository.applySceneWriteBack（独立 CAS，原子写回世界演化 + scene + registry + 候选事件）
  → GameSessionView
```

生产 API 精确为六个 route：

1. `POST /api/game`
2. `GET /api/game/current`
3. `POST /api/game/actions`
4. `POST /api/game/narrative/ensure`
5. `POST /api/game/prologue/ack`
6. `DELETE /api/game/dev/current`（仅 development）

不存在旧路由、重定向、兼容 facade 或并行仓储，也没有 `town ensure` 路由。SQLite 只使用 `game_records` 与 `current_game`；既有本地开发存档不迁移，升级后必须清档重开。坏数据和不支持的 record 只返回稳定分类，不能静默重置。

## 玩家选择闭环

- 固定选择请求：`{ actionId, interaction: { kind: "fixed_choice", choiceToken }, expectedRevision }`。
- 自定义输入请求：`{ actionId, interaction: { kind: "free_text", text, targetNpcId }, expectedRevision }`。
- 浏览器每次提交生成新的 UUID；同一 NPC 的连续自定义输入不会被错误去重。
- 焦点 NPC 对话视图严格提供两个服务端批准的固定选择；仅焦点 NPC 开启一个自定义输入。
- 自定义输入由服务端意图解析器转换成受支持 Action；玩家原文只存在于 `PendingNarrativeJob.utterance`，不进入长期记忆、事件账本或日志。
- tampered、stale、已消费 token 均零写入；AI/fixture 不能直接修改规则状态。

## 可玩性证明

- `dynamicMaterializationJourney.test.ts`：开局恰 1 地点/1 NPC/1 主线；首次对话后下一次写回具象化新 NPC 与（地点或物品），下一场景提及已批准名称；地图 → 城镇 → 建筑场景、物品、战斗与结局 ≥15 成功回合、三次 repository reload。
- `narrativeGroundingJourney.test.ts`：提交当前话语 → 下一场景出现直接 NPC 回应节拍；hostile/trusted 档位给出不同回应政策/fallback 台词；物品/任务/战斗后每个场景覆盖全部强制节拍，且 `objectiveLink` 等于 HUD 当前目标。
- `storyDivergenceJourney.test.ts`：同 seed 的“支持/质疑”两条分支各自具象化可完成内容、保留隔离 NPC 记忆并抵达不同结局方向——stock 确定性源为结局对附上规则要求（信任需关键 NPC 亲和度 ≥10，质疑 ≤9），支持分支亲和度走高命中信任、质疑分支亲和度走低命中质疑，全程离线裁决；分支 replay 深比较 `WorldState + StoryState` 完全一致。
- `mediumActJourney.test.ts`：中篇（5 幕）离线可完成性证明——从第 1 幕经真实幕链（交谈→具象化→传讯人·N→具象化…）推进到第 5 幕终点并解析结局；断言 `currentAct == targetActs`、结局已具象化且已解析、预算各维度仍在软上限内。
- `foundationJourney.test.ts`：驱动至少 15 个成功回合，跨多次 reload，覆盖固定 NPC 选择、自定义输入、旅行、拾取、探索、战斗和结局。
- seed 回归证明相同 seed 生成相同结构，不同 seed 至少改变世界名、地点或 NPC 的结构化组合。
- AI 不可用时走同一 proposal/审批/write-back 链的确定性 fallback，仍可完成游戏。

## 兼容与容量边界

- 本阶段允许破坏性重建：旧 HTTP 契约、旧存储表、旧 application/UI 链和类型隔离均已删除，不提供迁移或兼容层；旧蓝图聚合与全量世界生成候选已移除。
- 当前 SQLite 以单条 `worldState + storyState` JSON record 持久化整局；短篇/中篇是正式支持范围。
