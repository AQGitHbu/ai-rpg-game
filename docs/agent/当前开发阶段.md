## 阶段目标

把 Phase 1–6 已实现的确定性 RPG 闭环重组为玩家直觉可理解的冒险体验：

```text
世界地图 → 选择可前往地点 → 地点场景 → 点击 NPC / 线索 / 物品
→ 固定对话或对应互动 → 规则裁决与任务推进 → 返回地图
```

地图是旅行层，地点是主要游玩层。本阶段复用既有移动、观察、交谈、调查、拾取、任务、存档和 battle 规则，只改变玩家如何看见和触发这些规则，并新增封闭的 `dialogue_choice` NPC 固定对话入口。

## 阶段范围

- 地图节点状态封闭为 `current | travelable | known | locked`：仅 `travelable` 提交 `move`；`current` 只做进入地点的 UI 导航（零请求、零事件）；`known` 显示真实名与“需从相邻地点前往”；`locked` 只显示“探寻未知之地 / 尚未解锁”。
- 地点场景以可点击热点触发既有 `observe` / `investigate` / `take_item` / `start_battle` 规则；NPC 热点打开固定对话面板。
- NPC 固定对话 choice kind 封闭为 `greet | ask_main_quest | review_clue`：只有 `greet` 与 `ask_main_quest` 提交写状态的 `dialogue_choice { npcId, choiceId }`；`review_clue` 是纯本地展示，零 fetch、零写入。既有 `talk` 保留 API 兼容语义，新 UI 不提交它。
- application 层扩展安全 read model（`worldMap` / `locationScene` / `dialogues`），UI/API 只消费门面投影，不读取蓝图、`GameState`、seed 或 SQLite。
- 所有地图、场景、NPC、线索、物品、敌人与状态视觉使用本仓可审查的内联 SVG 占位（七题材 × 八类资源，允许通用基底 + 题材派生）；零 AI 图片调用——不得读 AI 环境变量、不得 fetch 任何图像服务、不依赖 `.env.local`。
- 不新增 `GameState` / 蓝图持久化字段，不 bump `stateVersion`；旧存档零迁移可投影。
