# 当前开发阶段

> 当前阶段：单一选择驱动 RPG 运行时收口
> 状态：已实现，待本页验收命令复核（worktree `.worktrees/v2-foundation-remediation`，分支 `codex-v2-foundation-remediation`）

## 阶段目标

- 生产运行时只保留一条无版本后缀的链路：`/api/game/**` → `compositionRoot` → `performTurn` / `generatePendingScene` → `GameRepository`。
- 每个焦点 NPC 场景向玩家展示两个语义不同的固定对白选择和一个自定义输入；两种输入都经过同一个 `/api/game/actions` 与 `performTurn`。
- 场景源只提交 proposal。服务端审批后铸造 opaque `choiceToken`，将 ready scene、`ApprovedChoice` registry 与候选事件池用同一次叙事 CAS 写回；客户端不接收或构造 `actionKey`。
- 每个成功玩家选择都有唯一 `actionId`，形成一次 `TurnResolution`、一个 `PendingNarrativeJob` 和一次规则 CAS；scene write-back 使用独立 CAS。
- 开局 seed 影响世界结构；同 seed 可确定性重放，同 seed 下不同选择会改变 NPC 关系、候选事件、结构化状态和最终结局。
- 正式产品只开放短篇与中篇。长篇/开放式游玩须先完成 segmented ledger 专项 Spec/Plan，不得宣传无限时长或无限记忆。

## 生产运行链

```text
CurrentGameScreen / AdventureGameShell
  → POST /api/game/actions
  → compositionRoot.performTurn
  → performTurn（规则审批、任务/关系/知识/结局、单次 StateCommit）
  → GameRepository.applyState（revision CAS）
  → PendingNarrativeJob
  → generatePendingScene（AI/fixture proposal → 服务端审批）
  → GameRepository.applySceneWriteBack（独立 revision CAS）
  → GameSessionView
```

生产 API 精确为六个 route：

1. `POST /api/game`
2. `GET /api/game/current`
3. `POST /api/game/actions`
4. `POST /api/game/narrative/ensure`
5. `POST /api/game/prologue/ack`
6. `DELETE /api/game/dev/current`（仅 development）

不存在旧路由、重定向、兼容 facade 或并行仓储。SQLite 只使用 `game_records` 与 `current_game`；既有本地开发存档不迁移，升级后必须清档重开。坏数据和不支持的 record 只返回稳定分类，不能静默重置。

## 玩家选择闭环

- 固定选择请求：`{ actionId, interaction: { kind: "fixed_choice", choiceToken }, expectedRevision }`。
- 自定义输入请求：`{ actionId, interaction: { kind: "free_text", text, targetNpcId }, expectedRevision }`。
- 浏览器每次提交生成新的 UUID；同一 NPC 的连续自定义输入不会被错误去重。
- 焦点 NPC 对话视图严格提供两个服务端批准的固定选择；仅焦点 NPC 开启一个自定义输入。
- 自定义输入由服务端意图解析器转换成受支持 Action；玩家原文不进入长期记忆、事件账本或日志。
- tampered、stale、已消费 token 均零写入；AI/fixture 不能直接修改规则状态。

## 可玩性证明

- `foundationJourney.test.ts` 驱动至少 15 个成功回合，跨多次 reload，覆盖固定 NPC 选择、自定义输入、旅行、拾取、探索、战斗和结局。
- `storyDivergenceJourney.test.ts` 以同一 seed 执行“支持”和“质疑”两条完整分支，证明 NPC affinity/emotion/history、候选事件与 ending ID 分化；各分支重复 replay 完全确定。
- seed 回归证明相同 seed 生成相同结构，不同 seed 至少改变世界名、地点或 NPC 的结构化组合。
- AI 不可用时走同一 proposal/审批/write-back 链的确定性 fallback，仍可完成游戏。

## 兼容与容量边界

- 本阶段允许破坏性重建：旧 HTTP 契约、旧存储表、旧 application/UI 链和类型隔离均已删除，不提供迁移或兼容层。
- 当前 SQLite 以单条 `worldState + storyState` JSON record 持久化整局；短篇/中篇是正式支持范围。
- 长篇/开放式支持必须另立 segmented ledger Spec/Plan，覆盖 append/event 分段、snapshot/cursor、归档、回放、事务和迁移后，才可进入 UI 或产品承诺。
