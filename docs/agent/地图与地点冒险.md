# 地图与地点冒险

## 系统定位

Phase 7 的地图优先地点冒险主循环：世界地图是旅行层，地点场景是主要游玩层。玩家在地图选择可前往地点，进入地点后直接点击 NPC、线索、物品、敌人等热点触发既有规则（`observe` / `investigate` / `take_item` / `start_battle` / `move`），NPC 通过封闭的固定对话选项推进任务，完成后返回地图。本系统不新增世界内容，只重组既有确定性规则的可见方式与触发入口。

## 当前规则摘要

- 地图节点状态四元组（封闭枚举）：
  - `current`：当前地点，只提供“进入地点”的纯 UI 导航（零请求、零事件、不递增 revision）；
  - `travelable`：当前地点的已解锁相邻节点，点击提交既有 `move { locationId }` 规则裁决；
  - `known`：已解锁但与当前地点不直接连通，显示真实名称、不可点击，提示“需从相邻地点前往”；
  - `locked`：仅限当前 active 任务 `visit_location` objective 指向且未解锁的目标，统一显示“探寻未知之地 / 尚未解锁”，不显示真实名称；其余未解锁地点完全不投影。
- `dialogue_choice` 三种 choice kind 的边界（封闭枚举，服务端白名单校验）：
  - `greet`：仅对当前地点尚未结识（`met === false`）的 NPC 投影；成功只产生既有 `npc_met` 事件；
  - `ask_main_quest`：仅当 active 主线存在未满足的 `talk_to_npc` objective 且目标正是该未结识 NPC 时投影；同样只产生 `npc_met`，由既有 quest reconciliation 满足 objective；
  - `review_clue`：纯 UI 本地展示已公开线索，零 fetch、零状态写入，不提交 intent。
  - `choiceId` 是确定性纯函数 `{npcId}:{choiceKind}`；非法、过期或不再可用的选项由服务端拒绝且零状态写入。既有 `talk` 仅作 API 兼容入口保留，新 UI 不提交它。
- 视觉全部为本仓内联 SVG 占位（七题材 × 八类：`map_base | map_node | map_node_locked | location_backdrop | npc | fact | item | enemy`），资源缺失时通用 SVG 降级；零 AI 图片调用、零外部图片服务、不读 AI 环境变量。
- 不新增 `GameState` / 蓝图持久化字段，不 bump `stateVersion`；旧存档零迁移可投影。

## 修改注意事项

- 地图可见范围是封闭规则：只投影 `unlockedLocationIds` 加当前 active `visit_location` 指向的未解锁目标；不得泄漏隐藏地点真实信息、seed 或完整蓝图。
- `review_clue` 永远本地展示，不得改成提交 intent；`greet` / `ask_main_quest` 不得新增事件类型或 GameState 字段。
- 不修改 `scripts/checkHandoff.mjs`、foundation、`@ai-game/ui`；不读 `.env.local`；测试零真实 AI、零图片网络调用。
- 结局或战斗中：地图/地点只读投影，interactions 为空，battle/ending 仍走既有 `BattlePanel` / `EndingPanel`。
