# 地图与地点冒险

## 系统定位

`GameSessionView` 将唯一权威状态投影成世界地图、当前地点、城镇层、在场 NPC、可取得物品、叙事场景、战斗与结局。`AdventureGameShell` 只渲染这些事实并提交 opaque token/free text，不再维护并行旧视图或从文案推导 Action。

## 当前 read model

- `worldMap.locations`：地点名称、current/visited 状态和可选 `travelChoice`。
- 地图旅行：非战斗时，未到访地点只在当前地点相邻且已解锁时下发 `travelChoice`；已解锁且已到访地点保留回访入口，避免玩家返回上游地点后看到“已到访”却无法进入。
- `currentLocation`：名称、描述、`scale`（`scene` / `town`）和当前合法 actions。
- `currentLocation.town`（仅 `scale: "town"`）：确定性城镇快照、展示标签与可交互建筑条目（`TownView`）；正常使用 slot 绑定，旧存档若仅保存了当前地点 NPC，则在读模型中补入空闲剧情 slot，不写回存档；当前主线人物通过 `currentFocusNpcId` 标记 `isCurrentFocus`，只有真正焦点建筑显示“当前剧情”；不暴露 seed、空闲 slot、生成器内部、隐藏 NPC 或未批准地点。
- `narrative`：ready scene、叙述、NPC 台词、两个批准选择和 `npcDialogues`。
- 若规则型 travel 覆盖了尚未消费的目标 NPC 抵达 scene，ready narrative 的 `dialogueResume` 会在返回该 NPC 所在地点时恢复原台词和批准选择；缺少该缓存的旧存档由目标 NPC 点击触发一次权威 talk 补生成，不投影空白台词和默认回应。
- 移动回合可能在抵达调查地点时由规则自动确认 `discover_fact`，从而推进当前目标；只有存在精确匹配的 `preparedContinuation` 时才消费预备场景，否则保留 rule-owned travel scene，不能因缺少 AI continuation 拒绝合法移动。
- 当前 `discover_fact` 的下一目标是城镇建筑内 NPC 时，`TownView.interactiveBuildings` 会只给该建筑下发服务端铸造的 `arrivalChoiceToken`；玩家进入建筑后消费一次规则型 `explore`，自动确认事实并推进释放游标，随后目标 NPC 才出现在场景。该入口不调用 AI，也不恢复已下线的调查方式按钮；普通建筑仍只做本地导航。
- `currentLocation.actions`：只投影当前仍可由服务端消费的地点行动；调查方式不再进入当前 read model。历史 `investigate` action 仍由规则层兼容结算，但新场景统一通过地图、NPC 卡片、场景热点和战斗面板交互。
- `NpcDialogueView`：焦点 NPC 有两个固定 choices 且 `freeInputEnabled: true`；非焦点 NPC 不拥有该输入能力；交付道具只使用 `giveChoices` 下发的固定按钮，自定义文本即使包含“交给/递给”也只作为对白。
- `obtainableItems` / `inventory`：只含玩家可见资料与合法 choice。
- 地图、当前地点、NPC、物品、事实和敌人都只投影当前 `StoryState.reveal` 已释放的实体；完整演化结果可以已持久化，但未释放实体不能因为名称存在于存档或旧场景 token 而提前出现。
- `battle`：active battle controls；`ending`：结构化结局。
- `narrativeGeneration`：只投影 `idle`、`pending(jobKey)` 或 `failed(jobKey, failureKind)`，阻止 pending 期间的并发玩家 Action；服务器在 provider job 写入后立即后台排队，客户端对新 job 只 ensure 一次，随后 GET 轮询观测，failed 只由同 job 手动重试恢复。序幕阅读期间不显示叙事生成模态；NPC 对话提交后保留对话框并显示内联 loading；prepared/rule action 不创建 provider pending。

## 三层导航

- 地图（世界地图旅行层）→ 城镇（`scale: "town"`，`TownLayerScreen`）→ 建筑场景（`LocationSceneScreen`）。
- 从建筑场景返回城镇；从城镇返回世界地图。`scale: "scene"` 地点保持地图 → 场景两层直达。
- 城镇内的酒楼后巷、街角等调查点属于当前城镇的地点事实/建筑场景，不应在世界地图另造一个同义远端节点；只有剧情明确要求离镇追踪时，才生成并释放独立的 `scale: "scene"` 地点，例如“北巷旧道”。
- 城镇几何与剧情建筑 slot 在开局预分配（`createTownRuntime`，确定性 seed 重建），运行时 NPC 才绑定到 slot（`bindNpcToTownSlot`，取第一个空闲 slot）；普通建筑进入只切换到建筑场景，不提交回合；若建筑承载当前事实目标，则入口消费服务端下发的规则型 `arrivalChoiceToken` 完成自动揭示。点击右侧 NPC 卡片打开本幕已预生成的焦点 NPC 对话，只有弹窗内两个选项或自定义输入才发起正式对话回合。
- 城镇层默认是纯 UI 导航，不改变位置指针粒度，也不新增 `enter_building` 意图或 `/api/game/town/ensure` 路由；事实目标建筑的例外只是消费服务端已有的 `arrivalChoiceToken`，不产生新的建筑意图。右侧建筑信息默认只显示地图提示；玩家点击高亮建筑后才显示建筑名、NPC 名和“进入建筑”。侧栏不再常驻“临时会面”开发面板，普通建筑不显示“当前剧情”，仅 `isCurrentFocus` 为真时显示该标签。
- 城镇地图按视口高度约束 SVG 尺寸，桌面端与建筑入口面板并列；避免地图撑出固定游戏视口后把“进入建筑”操作推到不可见区域。
- 新局创建时首场景可处于 `narrativeGeneration.status="pending"`（read model 同时提供 opaque `jobKey`）；服务器创建成功后立即排队生成，客户端在黑屏序幕阅读期间对该 job 一次 ensure、随后静默 GET 轮询并缓存 ready 场景。确认“开始冒险”只提交幂等序幕确认，不能成为启动生成的门闩，也不能因场景写回并发而被回滚。

## 客户端边界

- 客户端只能发送 read model 下发的 `choiceToken` 或焦点 NPC 自定义文本。
- UI 不拼接 `move:*`、`talk:*` 等业务 token，不解析 token，不接收 `actionKey`。
- 每次提交由 `gameActionRequest` 创建 UUID；固定和自定义输入共享 `/api/game/actions`。
- 地图导航中的纯 UI 切换不写状态；真正移动只通过 `travelChoice`。
- pending、stale、网络错误与结局状态必须显示稳定反馈，不能伪造成功；地点场景不渲染底部行动栏，地图、NPC 卡片、场景热点和战斗面板分别承载各自入口。主线焦点对白已准备好时，两个回应选项只在对话框内呈现。
- 当前客户端不提交调查方式 token，也不读取或计算 `factId`、`approachId`、`tensionDelta`、evidence consequence；历史 `investigate` action 只为旧存档/规则兼容保留。NPC 对话的两个选项仍是独立社交行动。
- pending 完成和新 NPC 出现都不能驱动弹窗导航；NPC 对话只由玩家点击打开。ready 快照若已把当前主线目标 NPC 编排为焦点，点击该 NPC 只打开双选项/自由输入，不提交新的 talk 回合；正式对白提交先进入等待/回应态，回应确认后才恢复选项或关闭旧焦点；ready 快照暴露不同权威目标时在回应框和 HUD 显示“下一步：<目标>”。
- 城镇地点的物品在 read model 中只归属一个已绑定剧情建筑；建筑场景只渲染自身归属物品，避免同一地点的物品同时出现在来福酒楼、铁匠铺等多个建筑中。旧存档由确定性投影补偿。
- 动态世界演化的地点提案必须声明 `placement`：`world` 才会铸造世界地图 `LocationEntry`；`town_building` 表示当前城镇内部的茶馆/酒楼/宅院/后巷等剧情建筑，不新增地图节点，而是把新 NPC 绑定到当前城镇 slot 并使用提案名称作为建筑展示名。城镇建筑提案要求当前地点为 town 且存在空闲剧情建筑 slot。
- 拾取物品属于规则已完全确定的单动作；提交后同步写回确定性场景，不触发 live 场景编排等待。
- 场景展示层对旁白、地点描述与 NPC 台词做轻量重复句末标点清洗；玩家提交对白后，权威 `npcLine` 在 NPC 对话框中以“NPC回应”阶段显示，不因主线交接被隐藏；地点 caption 按小句与旁注比对字符重合度，剔除旁注已复述过的氛围小句后仍有余量才渲染，全部被覆盖时隐藏（见 `displayText.removeCoveredClauses`）；没有可交互实体时保持场景静态，不伪造底部行动栏等待态。

## 2026-08-19 建筑场景旁注与动态行动叙事

- 建筑场景旁注中动态行动叙事（历史 `investigate`、物品、移动）优先于静态建筑氛围描述；初始进入（observe/dialogue）才展示建筑描述。
- 不破坏既有“地点旁注清洗系统元话术”规则：清洗与去重仍按原链路执行。

## 2026-08-19 目标交接场景的动线承接

- 对话回合写回后若权威目标切换为 `visit_location` 等非对话行动，建筑场景保留 handoff 旁注，移动入口由地图承载；旧焦点 NPC 的过期对白选项不进入场景。
- **token scope 根因（历史记录）**：`currentObjectiveChoiceToken` 的 visit_location 分支曾优先返回场景 scope move token；当前地点不再渲染该 token，移动统一由地图层 travelChoice 承载，场景只保留 handoff 旁注与返回入口。
- 旁注动态优先条件扩展到目标交接场景：权威目标行动在当前场景可用（`currentObjectiveIsSceneAction`，含 travel）时，刚写回的场景叙事（含 NPC 引导词）优先于静态建筑氛围描述，玩家关闭对话框后仍能看到“为什么去下一地点”的剧情承接。
- 交接目标在当前场景无权威行动入口（如新目标 NPC 在别处建筑、目标地点未连通）时，旁注/HUD 显示动线提示“主线已指向别处——<目标>。请返回小镇或地图，再前往下一处”；关闭旧 NPC 交接框仍是本地 UI 行为，不提交 acknowledgement action。

## 2026-08-25 调查方式下线与远端事实落点

- 所有当前 `discover_fact` 事实都由规则边界自动确认，不再根据 `investigationApproaches` 生成调查按钮或 prepared investigation 分支；自动 `fact_discovered` 省略 approach/evidence/tension 元数据。
- 同一 world-evolution 提案同时创建新地点和事实时，主线目标顺序固定为 `visit_location → discover_fact → ...`，事实 `locationId` 挂到新地点。新地点由首个 visit 目标释放，玩家先从地图抵达，抵达回合再自动确认事实，避免把远端渡口事实错误安装在当前茶棚。
- `investigate` 领域行动仍保留用于旧存档/事件兼容，但不再由 `buildChoiceMap`、`GameSessionView` 或地点组件暴露。reload 只恢复已经写入的自动发现事件，不等待不存在的调查 pending。
- `NPC 对话` 仍是独立交互：焦点 NPC 的两个固定选择与自定义输入只表达社交行动，不复用为调查方式。未来的套话/质问等调查必须以独立 targetNpcId 调查契约进入 read model。
- reload 只从 SQLite 的 WorldState/StoryState、eventLedger 和 scene CAS 恢复已结算的调查结果；UI 不通过重新 ensure 再裁决事实。选择路径的 evidence quality/tension 差异和自动路径的零额外张力均由权威状态重建。

## 2026-08-20 剧情文本来源标记

- `GameSessionView` 在唯一 read model 投影出口统一处理当前场景的玩家可见文本：场景或 NPC 对话 entry 的来源为 `fallback` 时，旁白、当前 NPC 台词和 NPC 对话分页前增加 `【fallback】`；`generated` 文本保持原文。新场景 API 生成的非焦点闲聊保存 `speechSource="generated"`，不再被误标记。
- 标记只属于展示层，不写回场景或 SQLite；玩家填写的 setup 文本、静态地点/任务/物品/结局描述，以及没有来源契约的旧存档实体描述不做推断标记。实现集中在 `src/game/application/narrativeText.ts` 与 `projectGameSessionView`，组件无需各自判断来源。

## 2026-08-22 NPC 交接对白与入口收口

- NPC 对话完成后若权威目标切换为 `visit_location`、调查或其他下一步，旧 NPC 的收尾场景仍展示其最后回应；同一次生成的唯一 handoff choice 同时作为玩家最后一句对白展示，不再把旧 NPC 降级后的零回合弹窗错误显示为“知道了”。该按钮只提交绑定的下一步 Action，不生成第二个对话分支。
- 地图承载 travel 入口，右侧场景人物卡承载 NPC 对话入口；地点场景不再渲染底部行动栏。物品/战斗等仍由场景热点或专用战斗面板承载，调查方式不再成为玩家入口。

## 2026-08-23 同地点 NPC 交接

- NPC 对话完成后若权威目标切换为同一地点另一名 NPC 的 `talk_to_npc`，旧 NPC 最后一条生成台词继续显示；当前目标的 talk choice label 作为唯一交接按钮，不发起新的 API 回合，点击后关闭旧建筑对话，玩家进入目标 NPC 所在建筑再开始正式对话。
- 建筑场景的关闭判定必须区分“目标是当前地点另一名 NPC”与“目标已离开当前地点”；前者保留交接台词和单线入口，后者才关闭旧焦点并交给地图/小镇动线。

## 2026-08-24 Prepared continuation 消费

- 正式 NPC 回合生成的后续 travel/battle step 保存在 server-authored `PreparedContinuationState` 图中；客户端只看到当前 scene 与 opaque choices，不读取图结构或未来实体。历史 investigate step 仅用于旧状态兼容。
- 目标移动、battle start/resolution 命中 active step 时，规则结果、场景物化、token 铸造、分支消费和 revision 递增共用一次 CAS；discover_fact 由规则自动确认，不创建调查兄弟分支。
- 没有 active matching step 或权威事件不匹配时分别返回 `NARRATIVE_CONTINUATION_MISSING` / `NARRATIVE_CONTINUATION_INVALID`，不创建 pending、不调用 provider、不写入状态。回退到已访问非目标地点、无 prepared step 的物品交换和 active battle round 均由规则场景完成。

## 修改注意事项

- 新展示事实先进入 `GameSessionView`，不让组件 deep-import domain/gameplay。

- 不为 UI 便利增加 adapter、compat view 或第二套 session type。

## 2026-08-13 无决策等待优化

- 新局和正式 NPC 回合写入白名单 provider job 后，服务端立即按 `gameId + jobId` 去重排队场景生成；`/narrative/ensure` 是一次性恢复/观测入口，普通轮询不重跑 failed job。
- 目标已由本回合唯一确定的 `move` 仍即时完成规则结算，但只消费同一正式 NPC 回合已审批的 prepared travel step；若抵达地点已有下一目标 NPC，抵达 step 自带其首句和后续正式 choice 的 seed，点击 NPC 只打开 ready 对话，不为抵达/打开动作调用 provider。
- prepared step 未命中或权威状态不匹配时返回稳定 continuation 错误并零写入，不降级为 live scene 或玩家可见的伪 deterministic 成功；仅显式 offline fixture 可以提供 fixture source。
- `take_item` 仍按规则后的权威物品/地点/候选同步完成场景写回；没有对应 prepared step 时使用 `source="rule"`，不参与任何叙事 provider job。
- 序幕阅读期间静默预生成且不显示全屏叙事模态；序幕确认与场景写回通过存储层单调合并保护 `prologueShown`。
- 普通建筑入口和明确 NPC talk 行动都不直接提交回合；事实目标建筑的入口例外消费一次服务端下发的规则型 `arrivalChoiceToken`，不触发 AI。talk 行动只打开已准备好的对话，NPC 资料卡仍保持只查看语义，正式 NPC 回合只由对话双选项或自定义输入提交。
- 正式 provider job 内可按既有 world-evolution 契约补足后续内容；线性动作本身不再补充演化。无 prepared 内容或图不一致时 UI 显示稳定错误与恢复提示。

## 2026-08-13 场景上下文与逐幕行动

- 小镇建筑进入场景时由客户端保存已点击建筑的展示名与绑定 NPC；场景标题使用建筑名，NPC 侧栏、对白和场景行动只投影该建筑 NPC，返回小镇/地图或实际移动时清除临时上下文。
- 原建筑中的对话完成后若主线已交给另一建筑的 NPC，仍停留在原场景让玩家读完回应，但不在底栏残留旧 NPC、探索或战斗按钮；HUD 指出“下一步”，玩家返回小镇并进入目标 NPC 的建筑，保持空间与主线唯一性。
- `GameSessionView.story.currentObjectiveChoiceToken` 使用 opaque token 指向当前幕首个未完成目标在当前地点的合法行动；地点组件不再把该 token 映射到底部行动栏，目标位于其他地点时由地图旅行入口承接。

- 下一幕交接不再自动打开新增 NPC；旧对话先保留 NPC 回应和“查看下一步”确认，确认后关闭旧焦点，新目标 NPC 在 ready 场景可直接成为焦点并带双选项，目标变化通过回应框与 HUD 的“下一步”提示呈现（2026-08-15）。
- 普通敌人按当前地点组成最多两名敌人组；独立战斗场景的标题和敌方 HUD 显示实际敌人列表，避免“挑战某一人”与战斗中出现队友之间产生误解。
- `TownLayerScreen` 与 `TownMapSvg` 提供可进入建筑图例、焦点建筑标签和增强高亮；未探索建筑仍不泄漏真实名称；旁注/侧栏按“点击后显示”原则展示建筑和 NPC 信息，不再输出临时会面开发面板。
- 小镇恢复并压缩历史预设的 8 类建筑图到 `public/assets/town/*.webp`；图片为非交互表现层，普通/未探索建筑不再成为伪按钮，未探索剧情建筑不加载真实类型图片。
- 满槽小镇仍可通过当前焦点建筑入口进入目标 NPC 场景；不把 NPC 暴露为“镇口临时会面”旁路，避免地图层出现开发态入口。
- 多 NPC 小镇以玩家实际点击的建筑绑定决定 talk token；目标文案解析只用于缺失绑定的旧存档补偿。
- 窄屏 HUD 目标卡明确清除旧 `bottom` 定位，避免目标卡拉伸遮挡地图；开发清档改为游戏内二次确认并显示失败反馈。
- 新游戏切换题材只替换仍是旧预设的字段，不覆盖玩家已编辑内容；序幕确认失败提供可重试错误。

## 2026-08-29 场景文本观感收口

- 真机中篇回放里，地点旁注与地点描述由同一批氛围素材写成，会出现“窗外风声呜咽，远处……”几乎逐句复述。展示层改为按小句统计与旁注的字符重合度（`displayText.removeCoveredClauses`，阈值 0.5），只删除旁注已表达的小句并收敛句末标点；整段被覆盖时隐藏 caption。建筑场景仍按原规则不渲染地点描述。
