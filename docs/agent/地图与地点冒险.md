# 地图与地点冒险

## 系统定位

`GameSessionView` 将唯一权威状态投影成世界地图、当前地点、城镇层、在场 NPC、可取得物品、叙事场景、战斗与结局。`AdventureGameShell` 只渲染这些事实并提交 opaque token/free text，不再维护并行旧视图或从文案推导 Action。

## 当前 read model

- `worldMap.locations`：地点名称、current/visited 状态和可选 `travelChoice`。
- `currentLocation`：名称、描述、`scale`（`scene` / `town`）和当前合法 actions。
- `currentLocation.town`（仅 `scale: "town"`）：确定性城镇快照、展示标签与可交互建筑条目（`TownView`）；正常使用 slot 绑定，旧存档若仅保存了当前地点 NPC，则在读模型中补入空闲剧情 slot，不写回存档；当前主线人物通过 `currentFocusNpcId` 标记 `isCurrentFocus`，只有真正焦点建筑显示“当前剧情”；不暴露 seed、空闲 slot、生成器内部、隐藏 NPC 或未批准地点。
- `narrative`：ready scene、叙述、NPC 台词、两个批准选择和 `npcDialogues`。
- `currentLocation.actions`：只为当前 `discover_fact` 目标投影已审批调查方式；每个方式有独立 opaque token，label/hint 不包含完整事实正文。没有方式的事实不投影 investigate action，而由规则边界自动揭示并在结果场景中反馈。
- `NpcDialogueView`：焦点 NPC 有两个固定 choices 且 `freeInputEnabled: true`；非焦点 NPC 不拥有该输入能力；交付道具只使用 `giveChoices` 下发的固定按钮，自定义文本即使包含“交给/递给”也只作为对白。
- `obtainableItems` / `inventory`：只含玩家可见资料与合法 choice。
- 地图、当前地点、NPC、物品、事实和敌人都只投影当前 `StoryState.reveal` 已释放的实体；完整演化结果可以已持久化，但未释放实体不能因为名称存在于存档或旧场景 token 而提前出现。
- `battle`：active battle controls；`ending`：结构化结局。
- `narrativeGeneration.pending`：阻止并发玩家 Action；服务器在 pending 写入后立即后台排队，客户端轮询负责观测与中断恢复。序幕阅读期间不显示叙事生成模态；NPC 对话提交后保留对话框并显示内联 loading，不弹出全屏进度模态；非 NPC 行动（地图移动、探索、战斗等）仍使用全屏 `GenerationStatusModal` 锁住底图、HUD 和规则按钮。

## 三层导航

- 地图（世界地图旅行层）→ 城镇（`scale: "town"`，`TownLayerScreen`）→ 建筑场景（`LocationSceneScreen`）。
- 从建筑场景返回城镇；从城镇返回世界地图。`scale: "scene"` 地点保持地图 → 场景两层直达。
- 城镇内的酒楼后巷、街角等调查点属于当前城镇的地点事实/建筑场景，不应在世界地图另造一个同义远端节点；只有剧情明确要求离镇追踪时，才生成并释放独立的 `scale: "scene"` 地点，例如“北巷旧道”。
- 城镇几何与剧情建筑 slot 在开局预分配（`createTownRuntime`，确定性 seed 重建），运行时 NPC 才绑定到 slot（`bindNpcToTownSlot`，取第一个空闲 slot）；进入已绑定建筑只切换到建筑场景，不提交回合；点击地点行动栏中的明确 talk 行动时打开本幕已预生成的焦点 NPC 对话；行动栏的“与 NPC 交谈”条目只为当前权威 talk 目标显示，只有弹窗内两个选项或自定义输入才发起正式对话回合。
- 城镇层是纯 UI 导航，不改变位置指针粒度，也不新增 `enter_building` 意图或 `/api/game/town/ensure` 路由。右侧建筑信息默认只显示地图提示；玩家点击高亮建筑后才显示建筑名、NPC 名和“进入建筑”。侧栏不再常驻“临时会面”开发面板，普通建筑不显示“当前剧情”，仅 `isCurrentFocus` 为真时显示该标签。
- 城镇地图按视口高度约束 SVG 尺寸，桌面端与建筑入口面板并列；避免地图撑出固定游戏视口后把“进入建筑”操作推到不可见区域。
- 新局创建时首场景可处于 `narrativeGeneration.pending`；服务器创建成功后立即排队生成，客户端在黑屏序幕阅读期间静默轮询并缓存 ready 场景。确认“开始冒险”只提交幂等序幕确认，不能成为启动生成的门闩，也不能因场景写回并发而被回滚。

## 客户端边界

- 客户端只能发送 read model 下发的 `choiceToken` 或焦点 NPC 自定义文本。
- UI 不拼接 `move:*`、`talk:*` 等业务 token，不解析 token，不接收 `actionKey`。
- 每次提交由 `gameActionRequest` 创建 UUID；固定和自定义输入共享 `/api/game/actions`。
- 地图导航中的纯 UI 切换不写状态；真正移动只通过 `travelChoice`。
- pending、stale、网络错误与结局状态必须显示稳定反馈，不能伪造成功；存在权威主线目标时，底部行动栏只保留该目标的一个入口。主线焦点对白已准备好时，两个回应选项只在对话框内呈现，不能与探索、战斗或其他 NPC 的通用动作并列成多条“主线”。
- 调查方式按钮只提交 read model 下发的 opaque token；客户端不读取或计算 `factId`、`approachId`、`tensionDelta`、evidence consequence，也不把 NPC 对话的两个选项伪装成现场调查。
- pending 完成和新 NPC 出现都不能驱动弹窗导航；NPC 对话只由玩家点击打开。ready 快照若已把当前主线目标 NPC 编排为焦点，点击该 NPC 只打开双选项/自由输入，不提交新的 talk 回合；正式对白提交先进入等待/回应态，回应确认后才恢复选项或关闭旧焦点；ready 快照暴露不同权威目标时在回应框和 HUD 显示“下一步：<目标>”。
- 城镇地点的物品在 read model 中只归属一个已绑定剧情建筑；建筑场景只渲染自身归属物品，避免同一地点的物品同时出现在来福酒楼、铁匠铺等多个建筑中。旧存档由确定性投影补偿。
- 动态世界演化的地点提案必须声明 `placement`：`world` 才会铸造世界地图 `LocationEntry`；`town_building` 表示当前城镇内部的茶馆/酒楼/宅院/后巷等剧情建筑，不新增地图节点，而是把新 NPC 绑定到当前城镇 slot 并使用提案名称作为建筑展示名。城镇建筑提案要求当前地点为 town 且存在空闲剧情建筑 slot。
- 拾取物品属于规则已完全确定的单动作；提交后同步写回确定性场景，不触发 live 场景编排等待。
- 场景展示层对旁白、地点描述与 NPC 台词做轻量重复句末标点清洗；玩家提交对白后，权威 `npcLine` 在 NPC 对话框中以“NPC回应”阶段显示，不因主线交接被隐藏；当旁白已包含地点描述时不重复渲染地点 caption；没有任何真实可执行行动或对话时行动栏显示明确错误/恢复提示，不能伪装成仍在等待生成。

## 2026-08-19 建筑场景旁注与动态行动叙事

- 建筑场景旁注中动态行动叙事（eventKind investigate/item/travel）优先于静态建筑氛围描述；初始进入（observe/dialogue）才展示建筑描述。
- 不破坏既有“地点旁注清洗系统元话术”规则：清洗与去重仍按原链路执行。

## 2026-08-19 目标交接场景的动线承接

- 对话回合写回后若权威目标切换为 `visit_location` 等非对话行动，建筑场景行动栏保留该目标的权威入口：`currentObjectiveAction` 查找扩展到 `narrative.choices`，可确定性命中 AI 在对话回合预生成的 move 交接选项（如“（放下茶钱，起身）北巷旧道是吧，我这就去瞧瞧”），点击后经 fast path 消费 `linearNarrativeQueue` 预生成叙事即时抵达；旧焦点 NPC 的过期对白选项不进入行动栏。
- **token scope 根因（第二层修复）**：`currentObjectiveChoiceToken` 的 visit_location 分支优先返回当前场景已审批 move 交接选项的 scene scope token（`scene:<sceneId>` 派生），与 runtime travelChoice token（`canonical-runtime-actions` 派生）永不相等——若不优先采用前者，UI 按目标 token 在 `narrative.choices` 中查找永远落空，`currentObjectiveIsSceneAction=false` 会让 handoff 判定强制关闭对话弹窗、旁注回落静态建筑描述。命中后：弹窗保持打开展示 `scene.npcDialogues` 的 NPC 引导台词（“再讲一句话”承接），行动栏给出角色化 move 入口；无场景 move 选项时回退 runtime travelChoice token（地图层旅行入口）。
- 旁注动态优先条件扩展到目标交接场景：权威目标行动在当前场景可用（`currentObjectiveIsSceneAction`，含 travel）时，刚写回的场景叙事（含 NPC 引导词）优先于静态建筑氛围描述，玩家关闭对话框后仍能看到“为什么去下一地点”的剧情承接。
- 交接目标在当前场景无权威行动入口（如新目标 NPC 在别处建筑、目标地点未连通）时，行动栏显示动线提示“主线已指向别处——<目标>。请返回小镇或地图，再前往下一处”，不再静默留空。

## 2026-08-20 调查方式投影与自动揭示反馈

- 有 2–3 个已审批调查方式的当前事实只投影这些方式，不投影同地点其他未发现事实；每个方式由服务端用 fact/approach 语义铸造互不相同的 runtime token。玩家选择后进入正式 `investigate` 回合，成功结果场景展示方式、证据完整度和是否留下动静。
- 没有调查方式的旧事实或线性事实不显示调查按钮。移动抵达或 NPC 交接成功时，由规则层在同一回合自动写入 `fact_discovered`，场景只展示已结算的发现结果与下一步动线；不会产生额外确认、空按钮或不存在的 pending。
- `NPC 对话` 仍是独立交互：焦点 NPC 的两个固定选择与自定义输入只表达社交行动，不复用为调查方式。未来的套话/质问等调查必须以独立 targetNpcId 调查契约进入 read model。
- reload 只从 SQLite 的 WorldState/StoryState、eventLedger 和 scene CAS 恢复已结算的调查结果；UI 不通过重新 ensure 再裁决事实。选择路径的 evidence quality/tension 差异和自动路径的零额外张力均由权威状态重建。

## 2026-08-20 剧情文本来源标记

- `GameSessionView` 在唯一 read model 投影出口统一处理当前场景的玩家可见文本：场景或 NPC 对话 entry 的来源为 `fallback` 时，旁白、当前 NPC 台词和 NPC 对话分页前增加 `【fallback】`；`generated` 文本保持原文。新场景 API 生成的非焦点闲聊保存 `speechSource="generated"`，不再被误标记。
- 标记只属于展示层，不写回场景或 SQLite；玩家填写的 setup 文本、静态地点/任务/物品/结局描述，以及没有来源契约的旧存档实体描述不做推断标记。实现集中在 `src/game/application/narrativeText.ts` 与 `projectGameSessionView`，组件无需各自判断来源。

## 2026-08-22 NPC 交接对白与底部入口收口

- NPC 对话完成后若权威目标切换为 `visit_location`，旧 NPC 的交接场景仍展示其回应；当前目标的 travel choice label 同时作为玩家最后一句对白展示，不再把旧 NPC 降级后的零回合弹窗错误显示为“知道了”。该展示是只读反馈，不提交新的回合。
- 地图承载 travel 入口，右侧场景人物卡承载 NPC 对话入口；底部行动栏不再重复渲染 `travel`、`dialogue` 或“主线已指向别处/无行动”的提示，仅保留当前场景没有其它专属入口的 explore/investigate/item/battle 等真实行动。

## 2026-08-23 同地点 NPC 交接

- NPC 对话完成后若权威目标切换为同一地点另一名 NPC 的 `talk_to_npc`，旧 NPC 最后一条生成台词继续显示；当前目标的 talk choice label 作为唯一交接按钮，不发起新的 API 回合，点击后关闭旧建筑对话，玩家进入目标 NPC 所在建筑再开始正式对话。
- 建筑场景的关闭判定必须区分“目标是当前地点另一名 NPC”与“目标已离开当前地点”；前者保留交接台词和单线入口，后者才关闭旧焦点并交给地图/小镇动线。

## 修改注意事项

- 新展示事实先进入 `GameSessionView`，不让组件 deep-import domain/gameplay。
- read model 不能泄露未发现 fact、内部 ID、registry、effect、seed 或 AI diagnostics。
- 不为 UI 便利增加 adapter、compat view 或第二套 session type。

## 2026-08-13 无决策等待优化

- 新局和每个成功回合写入 pending 后，服务端立即按 `gameId + jobId` 去重排队场景生成；`/narrative/ensure` 成为快速、幂等的恢复入口。
- 目标已由本回合唯一确定的 `move` 仍即时完成规则结算，但场景表现优先消费对话回合已审批的预生成移动叙事；若抵达地点已有下一目标 NPC，移动队列同时提供该 NPC 的生成对白，点击 NPC 只打开已生成的 ready 对话，不再为抵达/打开动作调用选项 API。
- `move` 队列未命中、旧队列缺少抵达对白或 live 内容修复失败时保存 failed 并等待同一 job 手动重试，不降级为玩家可见的 deterministic/fallback NPC 台词；仅离线 fixture 可以显式注入 deterministic source。
- `take_item` 仍按规则后的权威物品/地点/候选同步完成场景写回，但不参与移动对白队列。
- 序幕阅读期间静默预生成且不显示全屏叙事模态；序幕确认与场景写回通过存储层单调合并保护 `prologueShown`。
- 建筑入口和明确 NPC talk 行动都不直接提交回合；talk 行动只打开已准备好的对话，NPC 资料卡仍保持只查看语义，正式回合只由对话双选项或自定义输入提交。
- 场景候选不足时先进行受控补充演化；无行动 UI 改为可感知的异常与恢复提示。

## 2026-08-13 场景上下文与逐幕行动

- 小镇建筑进入场景时由客户端保存已点击建筑的展示名与绑定 NPC；场景标题使用建筑名，NPC 侧栏、对白和场景行动只投影该建筑 NPC，返回小镇/地图或实际移动时清除临时上下文。
- 原建筑中的对话完成后若主线已交给另一建筑的 NPC，仍停留在原场景让玩家读完回应，但不在底栏残留旧 NPC、探索或战斗按钮；HUD 指出“下一步”，玩家返回小镇并进入目标 NPC 的建筑，保持空间与主线唯一性。
- `GameSessionView.story.currentObjectiveChoiceToken` 使用 opaque token 指向当前幕首个未完成目标在当前地点的合法行动；场景行动栏按该 token 显示当前幕行动，避免把同地点的其他 NPC、线索和敌人混成一组“任务”。目标位于其他地点时 token 为空，由地图旅行入口承接。
