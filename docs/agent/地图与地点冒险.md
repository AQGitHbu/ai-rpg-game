# 地图与地点冒险

## 职责

`GameSessionView` 把权威世界状态投影为世界地图、当前地点、城镇层、建筑场景、NPC、物品、叙事、战斗和结局。组件只渲染这些事实并提交 opaque token 或焦点 NPC 自定义输入。

## 当前契约

- 地图只投影已释放地点、current/visited 状态和合法 `travelChoice`；未到访地点须已解锁且相邻，已访问地点可回访。
- `scale: "scene"` 使用地图→场景两层；`scale: "town"` 使用地图→城镇→建筑场景三层。城镇内部建筑切换通常是 UI 导航，不新增 `enter_building` action 或 town API。
- `currentLocation.actions` 不投影泛化探索与调查方式；地点页不显示“继续追查下一幕线索”等探索兜底按钮。地图旅行、NPC 卡片、可选物品热点与开战/战斗面板承载各自入口。
- 现有合法 `abandon_quest` 通过 `currentLocation.actions` 的 `presentation: "exit"` 投影为独立场景行动栏入口，沿既有 opaque token 提交与禁用链，不占用 NPC 两个回答；仅 ready、非战斗、未结束且合法映射仍允许退出时提供，真实交付后不再提供。对话覆盖层打开时行动栏按既有规则隐藏，关闭对话后可选退出。
- 普通焦点 NPC 的 ready scene 提供两个固定选择和一个自定义输入，交接与终幕按对话契约收束；没有 ready focus scene 时只提供服务器铸造的单一 `ask`。
- `narrative` 只投影已审批 scene、选择和非焦点 `npcDialogues`。台词用途由 `speechPurpose=focus|ambient` 表示，`speechSource` 只表示来源。
- 规则移动、探索、拾取、给予物品和战斗开始/胜利交接在生产必须消费匹配的 `narrativeBundle` 步骤；缺步骤返回 continuation 错误并零写入。offline fixture 才允许其明确的 rule-only 路径（例如 `take_item`），`PreparedContinuationState` 只属于 offline fixture。
- `narrativeGeneration` 只表达 idle、pending 或 failed。pending 由服务端后台排队，客户端只观察；failed 以同一 job 重试。
- 城镇目标建筑通过服务端下发的 `arrivalChoiceToken` 消费已批准的抵达步骤，承接该处线索；没有匹配步骤时不铸造 token。普通建筑只做导航。城镇建筑与世界地图地点的职责分离；物品交互见[物品与任务奖励](物品与任务奖励.md)。
- 客户端不生成、解析或拼接 token，不读取 `actionKey`、内部 registry、seed 或隐藏事实；实体选择只使用安全 view 下发的标识。
- `GameSessionView.visualAssets?` 是纯展示入口（定义于 `src/game/application/contentAssetView.ts`）；`LocationSceneScreen` 按当前建筑与 `displayedDialogue` 选择图片绑定，图片展示期与叙事/输入分离，无新增 Action、API 或存档字段。图片合同见 [图片展示框架](./图片展示框架.md)。

## 必要流程

```text
GameSessionView → AdventureGameShell
  ├ map travelChoice → POST /api/game/actions
  ├ town/building → UI navigation（目标建筑入口例外消费 arrivalChoiceToken）
  ├ NPC overlay → fixed choice / free text → performTurn
  ├ location hotspot → rule or narrativeBundle step
  └ battle panel → battle_action
```

建筑场景返回城镇，城镇返回地图；主线目标变化时旧 NPC 对话关闭，目标地点由地图承接，新 NPC 不自动弹出。
