# 地图与地点冒险

## 系统定位

`GameSessionView` 将唯一权威状态投影成世界地图、当前地点、城镇层、在场 NPC、可取得物品、叙事场景、战斗与结局。`AdventureGameShell` 只渲染这些事实并提交 opaque token/free text，不再维护并行旧视图或从文案推导 Action。

## 当前 read model

- `worldMap.locations`：地点名称、current/visited 状态和可选 `travelChoice`。
- `currentLocation`：名称、描述、`scale`（`scene` / `town`）和当前合法 actions。
- `currentLocation.town`（仅 `scale: "town"`）：确定性城镇快照、展示标签与可交互建筑条目（`TownView`）；正常使用 slot 绑定，旧存档若仅保存了当前地点 NPC，则在读模型中补入空闲剧情 slot，不写回存档；当前主线人物通过 `currentFocusNpcId` 标记 `isCurrentFocus`，只有真正焦点建筑显示“当前剧情”；不暴露 seed、空闲 slot、生成器内部、隐藏 NPC 或未批准地点。
- `narrative`：ready scene、叙述、NPC 台词、两个批准选择和 `npcDialogues`。
- `NpcDialogueView`：焦点 NPC 有两个固定 choices 且 `freeInputEnabled: true`；非焦点 NPC 不拥有该输入能力；交付道具只使用 `giveChoices` 下发的固定按钮，自定义文本即使包含“交给/递给”也只作为对白。
- `obtainableItems` / `inventory`：只含玩家可见资料与合法 choice。
- 地图、当前地点、NPC、物品、事实和敌人都只投影当前 `StoryState.reveal` 已释放的实体；完整演化结果可以已持久化，但未释放实体不能因为名称存在于存档或旧场景 token 而提前出现。
- `battle`：active battle controls；`ending`：结构化结局。
- `narrativeGeneration.pending`：阻止并发玩家 Action；服务器在 pending 写入后立即后台排队，客户端轮询负责观测与中断恢复。序幕阅读期间不显示叙事生成模态；玩家已提交需要等待 API/后台编排的行动时使用全屏 `GenerationStatusModal` 锁住底图、HUD 和规则按钮，场景内不再重复渲染“正在编排下一幕”。

## 三层导航

- 地图（世界地图旅行层）→ 城镇（`scale: "town"`，`TownLayerScreen`）→ 建筑场景（`LocationSceneScreen`）。
- 从建筑场景返回城镇；从城镇返回世界地图。`scale: "scene"` 地点保持地图 → 场景两层直达。
- 城镇内的酒楼后巷、街角等调查点属于当前城镇的地点事实/建筑场景，不应在世界地图另造一个同义远端节点；只有剧情明确要求离镇追踪时，才生成并释放独立的 `scale: "scene"` 地点，例如“北巷旧道”。
- 城镇几何与剧情建筑 slot 在开局预分配（`createTownRuntime`，确定性 seed 重建），运行时 NPC 才绑定到 slot（`bindNpcToTownSlot`，取第一个空闲 slot）；进入已绑定建筑只切换到建筑场景，不提交回合；点击地点行动栏中的明确 talk 行动时打开本幕已预生成的焦点 NPC 对话；行动栏的“与 NPC 交谈”条目只为当前权威 talk 目标显示，只有弹窗内两个选项或自定义输入才发起正式对话回合。
- 城镇层是纯 UI 导航，不改变位置指针粒度，也不新增 `enter_building` 意图或 `/api/game/town/ensure` 路由。右侧建筑信息默认只显示地图提示；玩家点击高亮建筑后才显示建筑名、NPC 名和“进入建筑”。侧栏不再常驻“临时会面”开发面板，普通建筑不显示“当前剧情”，仅 `isCurrentFocus` 为真时显示该标签。
- 城镇地图按视口高度约束 SVG 尺寸，桌面端与建筑入口面板并列；避免地图撑出固定游戏视口后把“进入建筑”操作推到不可见区域。
- 新局创建时首场景可处于 `narrativeGeneration.pending`；服务器创建成功后立即排队生成，客户端在黑屏序幕阅读期间静默轮询并缓存 ready 场景。确认“开始冒险”只提交幂等序幕确认，不能成为启动生成的门闩，也不能因场景写回并发而被回滚。

## 客户端边界

- 客户端只能发送 read model 下发的 `choiceToken` 或焦点 NPC 自定义文本。
- UI 不拼接 `move:*`、`talk:*` 等业务 token，不解析 token，不接收 `actionKey`。
- 每次提交由 `gameActionRequest` 创建 UUID；固定和自定义输入共享 `/api/game/actions`。
- 地图导航中的纯 UI 切换不写状态；真正移动只通过 `travelChoice`。
- pending、stale、网络错误与结局状态必须显示稳定反馈，不能伪造成功；存在权威主线目标时，底部行动栏只保留该目标的一个入口。主线焦点对白已准备好时，两个回应选项只在对话框内呈现，不能与探索、战斗或其他 NPC 的通用动作并列成多条“主线”。
- pending 完成和新 NPC 出现都不能驱动弹窗导航；NPC 对话只由玩家点击打开。ready 快照若已把当前主线目标 NPC 编排为焦点，点击该 NPC 只打开双选项/自由输入，不提交新的 talk 回合；正式对白提交先进入等待/回应态，回应确认后才恢复选项或关闭旧焦点；ready 快照暴露不同权威目标时在回应框和 HUD 显示“下一步：<目标>”。
- 城镇地点的物品在 read model 中只归属一个已绑定剧情建筑；建筑场景只渲染自身归属物品，避免同一地点的物品同时出现在来福酒楼、铁匠铺等多个建筑中。旧存档由确定性投影补偿。
- 拾取物品属于规则已完全确定的单动作；提交后同步写回确定性场景，不触发 live 场景编排等待。
- 场景展示层对旁白、地点描述与 NPC 台词做轻量重复句末标点清洗；玩家提交对白后，权威 `npcLine` 在 NPC 对话框中以“NPC回应”阶段显示，不因主线交接被隐藏；当旁白已包含地点描述时不重复渲染地点 caption；没有任何真实可执行行动或对话时行动栏显示明确错误/恢复提示，不能伪装成仍在等待生成。

## 修改注意事项

- 新展示事实先进入 `GameSessionView`，不让组件 deep-import domain/gameplay。
- read model 不能泄露未发现 fact、内部 ID、registry、effect、seed 或 AI diagnostics。
- 不为 UI 便利增加 adapter、compat view 或第二套 session type。

## 2026-08-13 无决策等待优化

- 新局和每个成功回合写入 pending 后，服务端立即按 `gameId + jobId` 去重排队场景生成；`/narrative/ensure` 成为快速、幂等的恢复入口。
- 目标已由本回合唯一确定的 `move` 不等待 live 表演源或 live 世界演化：服务端在 action 响应前以移动后的权威地点/目标/候选同步写回确定性落点场景并走同一审批链，抵达后可直接交谈；只有候选不足等异常才降级为后台恢复。
- `take_item` 与 `move` 一样不等待 live 表演源或 live 世界演化：服务端在 action 响应前按规则后的权威物品/地点/候选同步写回确定性场景。
- 序幕阅读期间静默预生成且不显示全屏叙事模态；序幕确认与场景写回通过存储层单调合并保护 `prologueShown`。
- 建筑入口和明确 NPC talk 行动都不直接提交回合；talk 行动只打开已准备好的对话，NPC 资料卡仍保持只查看语义，正式回合只由对话双选项或自定义输入提交。
- 场景候选不足时先进行受控补充演化；无行动 UI 改为可感知的异常与恢复提示。

## 2026-08-13 场景上下文与逐幕行动

- 小镇建筑进入场景时由客户端保存已点击建筑的展示名与绑定 NPC；场景标题使用建筑名，NPC 侧栏、对白和场景行动只投影该建筑 NPC，返回小镇/地图或实际移动时清除临时上下文。
- 原建筑中的对话完成后若主线已交给另一建筑的 NPC，仍停留在原场景让玩家读完回应，但不在底栏残留旧 NPC、探索或战斗按钮；HUD 指出“下一步”，玩家返回小镇并进入目标 NPC 的建筑，保持空间与主线唯一性。
- `GameSessionView.story.currentObjectiveChoiceToken` 使用 opaque token 指向当前幕首个未完成目标在当前地点的合法行动；场景行动栏按该 token 显示当前幕行动，避免把同地点的其他 NPC、线索和敌人混成一组“任务”。目标位于其他地点时 token 为空，由地图旅行入口承接。

## 2026-08-12 真机 UI 修复

- `GenerationStatusModal` 覆盖新建和必要的显式提交等待；叙事 pending 由游戏界面静默观测，超过阈值仍可重新检查当前存档。
- `LocationSceneScreen` 标注单按钮 NPC 对话准备态，去重场景/地点文本，并在无行动时提供非交互等待提示。
- 下一幕交接不再自动打开新增 NPC；旧对话先保留 NPC 回应和“查看下一步”确认，确认后关闭旧焦点，新目标 NPC 在 ready 场景可直接成为焦点并带双选项，目标变化通过回应框与 HUD 的“下一步”提示呈现（2026-08-15）。
- 普通敌人按当前地点组成最多两名敌人组；独立战斗场景的标题和敌方 HUD 显示实际敌人列表，避免“挑战某一人”与战斗中出现队友之间产生误解。
- `TownLayerScreen` 与 `TownMapSvg` 提供可进入建筑图例、焦点建筑标签和增强高亮；未探索建筑仍不泄漏真实名称；旁注/侧栏按“点击后显示”原则展示建筑和 NPC 信息，不再输出临时会面开发面板。
- 小镇恢复并压缩历史预设的 8 类建筑图到 `public/assets/town/*.webp`；图片为非交互表现层，普通/未探索建筑不再成为伪按钮，未探索剧情建筑不加载真实类型图片。
- 满槽小镇仍可通过当前焦点建筑入口进入目标 NPC 场景；不把 NPC 暴露为“镇口临时会面”旁路，避免地图层出现开发态入口。
- 多 NPC 小镇以玩家实际点击的建筑绑定决定 talk token；目标文案解析只用于缺失绑定的旧存档补偿。
- 窄屏 HUD 目标卡明确清除旧 `bottom` 定位，避免目标卡拉伸遮挡地图；开发清档改为游戏内二次确认并显示失败反馈。
- 新游戏切换题材只替换仍是旧预设的字段，不覆盖玩家已编辑内容；序幕确认失败提供可重试错误。
