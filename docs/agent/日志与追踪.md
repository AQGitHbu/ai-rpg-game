# 日志与追踪

## 系统定位

RPG 保留跨层日志 facade，通用底层由 foundation 的 `@ai-game/logging` 提供。服务器侧结构化日志与业务结果解耦，日志初始化、写入或 fallback 失败均不得影响规则裁决、AI fallback 或存档事务。

## 当前实现现状

- `src/game/logging/index.ts` 是 RPG 兼容 facade，保留同步 `GameLogger`、`GameLogEntry`、`createGameLogger` 与 `NOOP_GAME_LOGGER`，业务调用方不直接依赖共享包。
- `@ai-game/logging` 统一拥有递归脱敏、事件校验/截断、SQLite schema 与迁移、查询和 JSONL sink；RPG 不复制这些底层。
- `src/game/logging/serverConsoleLogger.ts` 是同步 facade 到共享异步 sink 的惰性适配层，也是唯一允许直接调用 `console` 的生产模块；只能由 `application/server/compositionRoot.ts` 导入。
- composition root 创建同一日志运行时并注入 SQLite repository、scenario/runtime/town AI source 与后台任务协调器；`close()` 会排空待写日志并关闭独立日志连接。
- HTTP route 统一创建/透传安全的 `traceId`，返回 `X-Request-Trace-Id`；`http_request_started`、`http_request_completed` 和 `http_request_failed` 记录方法、路由、状态码、稳定结果码与耗时。
- 叙事审批、town provider 遥测、NPC 对话、后台生成和 scenario lifecycle 均可关联同一 `traceId`；provider 遥测仅记录白名单字段，不记录 prompt、密钥、URL 或模型原文。
- composition root 记录启动/停止、创建与读取存档、玩家命令、NPC 对话、后台生成和异常结果；业务日志补充稳定 intent/目标摘要、revision、battle/生成状态、任务数量等排障上下文，不写玩家输入或完整存档。
- 运维入口为 `npm run logs:health`、`npm run logs:query -- ...` 和 `npm run logs:retention`，详见 `docs/operations/logging.md`。
- 共享策略按字段名脱敏 API key、Authorization、cookie、token、密码、secret、prompt、原始请求/响应与模型输入输出；超大事件只保留摘要、原始字节数和 SHA-256。
- AI 文本审计日志独立于普通诊断日志：默认开启（`AI_TEXT_AUDIT=full`，只有显式 `AI_TEXT_AUDIT=off` 才关闭），保存完整 prompt、模型正文、玩家语义输入、游戏 API 输入输出和最终文本，落到 `logs/ai-text-audit/<runId>/events.jsonl`（JSONL append-only），不经过普通日志的脱敏和 128 KiB 截断。唯一安全排除项是 API key、Authorization、cookie 和完整 URL。查询使用 `npm run ai-text-audit -- list|query|verify|export` CLI。

## 存储与配置

- 生产默认日志库为 `data/logs.db`，与游戏状态库 `db/rpg.sqlite` 完全分离；日志库包含 `log_events` 与自身迁移表，不得写入游戏库。
- `GAME_LOG_DB_PATH` 覆盖日志 SQLite 路径；空白值回退默认路径。
- `GAME_LOG_FALLBACK_DIR` 覆盖 SQLite 初始化失败时的共享 JSONL fallback 目录，默认 `logs/`。初始化失败只向 stderr 输出稳定事件名，不输出异常正文、数据库路径或连接信息。
- `GAME_LOG_MAX_EVENT_BYTES` 可覆盖单事件上限，必须是至少 512 的安全整数；无效值采用共享包默认值。
- 初始化由首条日志惰性触发，入口创建不等待 SQLite；同步 facade 调用保持 `void`，生命周期 `close()` 负责可靠排空。

## 修改注意事项

- 新调用点只能从 `@/game/logging` 导入 `GameLogger` 或 `NOOP_GAME_LOGGER`；不得 deep-import logging 内部实现。
- 只有 `src/game/logging/**` 可以导入 `@ai-game/logging`；业务层继续面向 RPG facade。
- 真实输出能力由 server composition root 注入；纯 application 代码必须接受可选 logger 或使用 no-op，不能重新引入 `console`。
- 日志字段是白名单，不传密码、token、prompt、完整 request/response、异常 message/stack、存档或玩家输入；需要关联请求时先确认该 telemetry 契约允许输出 `traceId`。
- 新增生产级 `console.log`、`console.warn` 或 `console.error` 会被边界测试拒绝，除非它属于唯一的 server sink。
