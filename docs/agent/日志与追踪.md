# 日志与追踪

## 系统定位

RPG 内部的跨层、无玩法语义日志端口。它将服务器侧的结构化可观测性与业务结果解耦，保证日志 sink 失败不会影响规则裁决、AI fallback 或存档事务。

## 当前实现现状

- `src/game/logging/index.ts` 是纯 facade，导出 `GameLogger`、`GameLogEntry`、`createGameLogger`、`NOOP_GAME_LOGGER` 与递归脱敏函数。
- `src/game/logging/serverConsoleLogger.ts` 是唯一允许直接调用 `console` 的生产模块；只能由 `application/server/compositionRoot.ts` 导入。
- composition root 创建同一 logger 并注入 SQLite repository、scenario/runtime/town AI source 与两个后台任务协调器。
- 叙事审批日志包含 `traceId`、角色和稳定失败分类；provider 遥测仅记录白名单字段，保留既有“不记录 town traceId”的安全契约。
- 递归按字段名脱敏 API key、Authorization、cookie、token、密码、secret、prompt、模型输出、数据库连接信息与存档/状态字段；sink 异常被吞掉，不改变游戏流程。
- 该模块目前只有 RPG 一个消费者，禁止迁入 foundation；第二个产品出现稳定同语义需求后才按共享流程评估。

## 修改注意事项

- 新调用点只能从 `@/game/logging` 导入 `GameLogger` 或 `NOOP_GAME_LOGGER`；不得 deep-import logging 内部实现。
- 真实输出能力由 server composition root 注入；纯 application 代码必须接受可选 logger 或使用 no-op，不能重新引入 `console`。
- 日志字段是白名单，不传完整 request、response、异常 message、存档或玩家输入；需要关联请求时先确认该 telemetry 契约允许输出 `traceId`。
- 新增生产级 `console.log`、`console.warn` 或 `console.error` 会被边界测试拒绝，除非它属于唯一的 server sink。
