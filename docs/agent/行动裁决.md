# 行动裁决

## 状态

Phase 3 已实现完成（2026-07-27）。玩家可以执行 `observe`、`talk`、`investigate` 三类固定行动，resolver 产出下一份 `GameState` 和领域事件，原子写入 SQLite 并递增 revision。

Phase 4 已实现完成（2026-07-27）：新增 `move` 意图与三个 move 拒绝码，成功行动后由 quests facade 推进任务状态（`quest_completed` / `quest_unlocked` 事件与行动事件同一次写入），read model 演进为 `GameSessionView`。详见 `docs/agent/探索与任务推进.md`。

Phase 5 已实现完成（2026-07-27）：新增 `take_item` 意图与三个物品拒绝码，成功取得追加 `item_obtained` 并写入 `GameState.inventory`；API 对所有 intent 执行目标字段白名单（多余目标字段 400）。详见 `docs/agent/物品与任务奖励.md`。

Phase 6 已实现完成（2026-07-28）：新增 `start_battle` 与 `battle_action` 意图，提供确定性轻量回合战；战斗胜利后 reconciliation 拾取 `defeat_enemy` objective 并完成 stage 3，战斗失败/撤退后 `failQuest` 标记 stage 3 为 failed；无论胜败都触发 `resolveEnding` 结局解析器，到达结构化双结局。详见 `docs/agent/战斗与结局.md`。

## 设计边界

- 玩家提交的是结构化意图，而不是已经发生的事实。
- 只有 `src/game/gameplay/rpg/actions/` 与 `src/game/gameplay/rpg/battle/` 的纯规则 resolver 可以产出下一份 `GameState` 和领域事件。
- UI/API 只能通过 `@/game/application` 门面调用动作 use case，不能直接导入 domain、gameplay 或 persistence。
- Phase 3 只做固定选项的 `observe`、`talk`、`investigate`；Phase 4 新增 `move`；Phase 5 新增 `take_item`；Phase 6 新增 `start_battle` / `battle_action`。
- 自由输入、AI 意图解析、技能、状态、治疗、装备/物品效果、重试、关系/记忆或 AI 叙事均不在 MVP 范围。
- 行动结果必须先以原子 compare-and-swap 写入 SQLite；版本冲突或拒绝的行动不得留下事件或部分状态。

## 实现记录

### Intent、拒绝码、事件类型

**PlayerIntent（七种固定意图；move 为 Phase 4、take_item 为 Phase 5、start_battle/battle_action 为 Phase 6 新增）**：
- `observe { locationId }` - 观察当前地点
- `talk { npcId }` - 与在场 NPC 交谈
- `investigate { factId }` - 调查可调查事实
- `move { locationId }` - 移动到连通且已解锁的相邻地点（Phase 4）
- `take_item { itemId }` - 取得当前地点预置且尚未拥有的物品（Phase 5）
- `start_battle { enemyId }` - 在敌人地点发起战斗（Phase 6）
- `battle_action { action: "attack" | "guard" | "withdraw" }` - 执行战斗行动（Phase 6）

**ValidationCode（稳定拒绝码；Phase 4 新增 3 个、Phase 5 新增 3 个、Phase 6 新增 6 个）**：
- `LOCATION_NOT_CURRENT` - 目标地点不是当前地点
- `UNKNOWN_LOCATION` - 地点不存在
- `LOCATION_ALREADY_OBSERVED` - 地点已观察过
- `LOCATION_ALREADY_CURRENT` - 已在目标地点（Phase 4，move）
- `LOCATION_NOT_CONNECTED` - 当前地点与目标不连通（Phase 4，move）
- `LOCATION_LOCKED` - 目标地点尚未解锁（Phase 4，move）
- `NPC_NOT_PRESENT` - NPC 不在当前地点
- `UNKNOWN_NPC` - NPC 不存在
- `NPC_ALREADY_MET` - NPC 已见过
- `FACT_NOT_INVESTIGABLE` - 事实不在可调查列表中
- `UNKNOWN_FACT` - 事实不存在
- `FACT_ALREADY_DISCOVERED` - 事实已发现
- `UNKNOWN_ITEM` - 物品不存在（Phase 5，take_item）
- `ITEM_NOT_AVAILABLE_HERE` - 物品不在当前地点可取得列表（Phase 5，take_item）
- `ITEM_ALREADY_OWNED` - 物品已在背包（Phase 5，take_item）
- `UNKNOWN_ENEMY` - 敌人不存在（Phase 6，battle）
- `ENEMY_NOT_AT_LOCATION` - 玩家不在敌人所在地点（Phase 6，battle）
- `BATTLE_ALREADY_ACTIVE` - 已有进行中的战斗（Phase 6，battle）
- `ENDING_REACHED` - 游戏已结局（Phase 6，battle）
- `ENEMY_NOT_STAGE3_TARGET` - 敌人不是当前 stage 3 active 任务的击败目标（Phase 6，battle）
- `ENEMY_ALREADY_DEFEATED` - 敌人已被击败（Phase 6，battle）
- `NO_ACTIVE_BATTLE` - 当前没有进行中的战斗（Phase 6，battle）

**GameEvent（Phase 3 新增三种 + Phase 4 新增三种 + Phase 5 新增一种 + Phase 6 新增六种）**：
- `LocationObservedEvent { type: "location_observed", occurredAt, locationId }`
- `NpcMetEvent { type: "npc_met", occurredAt, npcId }`
- `FactDiscoveredEvent { type: "fact_discovered", occurredAt, factId }`
- `LocationVisitedEvent { type: "location_visited", occurredAt, locationId }`（Phase 4）
- `QuestCompletedEvent { type: "quest_completed", occurredAt, questId }`（Phase 4）
- `QuestUnlockedEvent { type: "quest_unlocked", occurredAt, questId }`（Phase 4）
- `ItemObtainedEvent { type: "item_obtained", occurredAt, itemId, locationId }`（Phase 5）
- `BattleStartedEvent { type: "battle_started", occurredAt, enemyId }`（Phase 6）
- `BattleRoundResolvedEvent { type: "battle_round_resolved", occurredAt, enemyId, round, playerHp, enemyHp, action }`（Phase 6）
- `BattleResolvedEvent { type: "battle_resolved", occurredAt, enemyId, outcome }`（Phase 6）
- `EnemyDefeatedEvent { type: "enemy_defeated", occurredAt, enemyId }`（Phase 6）
- `QuestFailedEvent { type: "quest_failed", occurredAt, questId }`（Phase 6）
- `EndingReachedEvent { type: "ending_reached", occurredAt, endingId, outcome }`（Phase 6）

### SQLite revision / migration 与原子写入

**Schema v2（从 v1 迁移）**：
- `games` 表新增 `revision INTEGER DEFAULT 0` 列
- Migration 幂等、事务化，保留 Phase 2 存档并补 revision 0
- `compare-and-swap` 逻辑：`WHERE gameId = ? AND revision = ?`

**原子操作**：
- `GameRepository.applyResolvedAction(gameId, expectedRevision, nextState, events)`
- 同一事务更新 `stateJSON`、`eventLedgerJSON`、`revision`
- revision 不匹配时返回 `STALE_GAME_REVISION`，不重试、不覆盖
