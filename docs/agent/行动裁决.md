# 行动裁决

## 职责

行动裁决把客户端提交的固定选择或焦点 NPC 自定义输入转换为受支持的 `Action`，校验当前世界状态，并在一次规则提交中产生状态、任务、关系、知识、战斗和结局结果。AI、UI 和玩家原文都不能直接写入事实。

## 当前契约

- 固定选择使用当前 revision 的 opaque `choiceToken`；客户端不提交 `Action`、`actionKey`、effect、事实 ID 或候选事件 ID。服务端批准的 `talk` 可带 `interactionId`，它进入动作重建、语义摘要和 token，并只能解析当前 choice map 中已安装的互动定义。
- 自定义输入携带文本和焦点 NPC ID，由 `convertInteraction` 映射为中性 `talk/ask`；原文供当前叙事表达，不做独立 intent provider 调用，也不直接声明规则结果。
- 请求带独立 `actionId` 与 `expectedRevision`。非法、过期、重复、已消费或结局后的请求零写入。
- 玩家操作由 `talk`、`move`、`take_item`、`give_item`、`attack` 和 `battle_action` 承载。Action union 中的 `explore`、`investigate`、`ack_prologue`、`freeform` 保留内部或流程用途，不代表泛化探索、调查或任意意图的公开玩家入口；自由输入实际转换为 `talk/ask`。
- NPC 对话、赠物、明确 NPC 任务和共同战斗的后果通过 Entity Store 的 `EntityMutation` 写入；关系 signal、知识传播、债务和对话完成由规则计算。
- 故事互动先由 bundle/opening proposal 解析、绑定当前 NPC 与事实来源，再由 `resolveStoryInteraction` 结算；普通 talk 不带 `interactionId` 时仍走普通对白规则。互动的事实只写入明确听众，`give_item` 不得藏在 talk 效果中。
- `promise_confidentiality` 由玩家作出承诺，NPC 是听众；该操作本身不揭露事实。已经成功结算的互动不再进入候选；新提案的 `interaction:proposalKey` 在完整规则预览后按真实互动身份绑定，场景明确选用的合法互动优先进入候选槽，不能按文案或数组位置替换动作。
- 每个成功规则回合通过 `commitEventDrafts` 追加 committed event，`StoryState.memory` 从完整 event ledger 重建。CAS 失败不补写事件、记忆或玩家行动。
- 新的 automatic `discover_fact` 目标在规则边界自动确认；`investigate` 仍保留在 Action 与 bundle trigger 中，当前生产 read model 尚未生成调查方式 token。显式调查必须提交已批准方式并由规则写入匹配 `fact_discovered`，没有可消费续接时由 `ResultBoundaryProof` 进入既有 provider pending 链；不能以缺稿为由对普通行动泛化调用 provider。
- 生产续接只消费已批准的 `narrativeBundle` 步骤。`PreparedContinuationState` 只用于显式 offline fixture；生产线性动作不能因缺少步骤而调用 provider 或生成替代剧情。

## 必要流程

```text
Interaction → requestParser / actionConverter → validateAction / resolveByType
→ quest、NPC、战斗、结局与事件 reconciliation → TurnResolution
→ 单次 StateCommit / repository CAS → GameSessionView
```

规则回合最多执行一次 `applyState`。正式 NPC 回合可写入白名单 `PendingNarrativeJob`；生成包审批与写回是独立的 narrative CAS。`move`、物品、战斗和回退导航只消费 bundle 或规则场景，不重复执行 AI 生成。
