# 行动裁决

## 状态

Phase 3 已实现完成（2026-07-27）。玩家可以执行 `observe`、`talk`、`investigate` 三类固定行动，resolver 产出下一份 `GameState` 和领域事件，原子写入 SQLite 并递增 revision。

Phase 4 已实现完成（2026-07-27）：新增 `move` 意图与三个 move 拒绝码，成功行动后由 quests facade 推进任务状态（`quest_completed` / `quest_unlocked` 事件与行动事件同一次写入），read model 演进为 `GameSessionView`。详见 `docs/agent/探索与任务推进.md`。

## 设计边界

- 玩家提交的是结构化意图，而不是已经发生的事实。
- 只有 `src/game/gameplay/rpg/actions/` 的纯规则 resolver 可以产出下一份 `GameState` 和领域事件。
- UI/API 只能通过 `@/game/application` 门面调用动作 use case，不能直接导入 domain、gameplay 或 persistence。
- Phase 3 只做固定选项的 `observe`、`talk`、`investigate`；自由输入、AI 意图解析、移动、任务推进、战斗与物品使用均不在本阶段。
- 行动结果必须先以原子 compare-and-swap 写入 SQLite；版本冲突或拒绝的行动不得留下事件或部分状态。

## 实现记录

### Intent、拒绝码、事件类型

**PlayerIntent（四种固定意图；move 为 Phase 4 新增）**：
- `observe { locationId }` - 观察当前地点
- `talk { npcId }` - 与在场 NPC 交谈
- `investigate { factId }` - 调查可调查事实
- `move { locationId }` - 移动到连通且已解锁的相邻地点

**ValidationCode（稳定拒绝码）**：
- `LOCATION_NOT_CURRENT` - 目标地点不是当前地点
- `UNKNOWN_LOCATION` - 地点不存在
- `LOCATION_ALREADY_OBSERVED` - 地点已观察过
- `LOCATION_ALREADY_CURRENT` - 已在目标地点（Phase 4，move）
- `LOCATION_NOT_CONNECTED` - 当前地点与目标不连通（Phase 4，move）
- `LOCATION_LOCKED` - 目标地点尚未解锁（Phase 4，move）
- `NPC_NOT_PRESENT` - NPC 不在当前地点
- `UNKNOWN_NPC` - NPC 不存在
- `NPC_ALREADY_MET` - NPC 已见过
- `FACT_NOT_INVESTIGABLE` - 事实不在可调查列表中
- `UNKNOWN_FACT` - 事实不存在
- `FACT_ALREADY_DISCOVERED` - 事实已发现

**GameEvent（Phase 3 新增三种 + Phase 4 新增三种）**：
- `LocationObservedEvent { type: "location_observed", occurredAt, locationId }`
- `NpcMetEvent { type: "npc_met", occurredAt, npcId }`
- `FactDiscoveredEvent { type: "fact_discovered", occurredAt, factId }`
- `LocationVisitedEvent { type: "location_visited", occurredAt, locationId }`（Phase 4）
- `QuestCompletedEvent { type: "quest_completed", occurredAt, questId }`（Phase 4）
- `QuestUnlockedEvent { type: "quest_unlocked", occurredAt, questId }`（Phase 4）

### SQLite revision / migration 与原子写入

**Schema v2（从 v1 迁移）**：
- `games` 表新增 `revision INTEGER DEFAULT 0` 列
- Migration 幂等、事务化，保留 Phase 2 存档并补 revision 0
- `compare-and-swap` 逻辑：`WHERE gameId = ? AND revision = ?`

**原子操作**：
- `GameRepository.applyResolvedAction(gameId, expectedRevision, nextState, events)`
- 同一事务更新 `stateJSON`、`eventLedgerJSON`、`revision`
- revision 不匹配时返回 `STALE_GAME_REVISION`，不重试、不覆盖
