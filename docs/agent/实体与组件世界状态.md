# 实体与组件世界状态

## 职责

`EntityStore` 是世界实体事实的唯一来源；`WorldState` 保留由 store 投影的兼容集合和不属于实体的运行时字段。解析、构造和持久化必须先验证 store，再使用投影。

## 当前契约

- `EntityStore.version` 为 2；`WorldState` schema version 为 6，`StoryState` schema version 为 8。WorldState 6 将初始化历史与开放问题事件纳入正式 ledger payload 契约；SQLite 对包括 WorldState 5 在内的已知旧版本返回 `UNSUPPORTED_RECORD`，未知版本返回 `VERSION_MISMATCH`。JSON/record 无法解析为 `UNPARSEABLE_RECORD`，当前结构、引用或 memory 漂移为 `ENTITY_STATE_INVALID`。旧版本不迁移、不自动清档或静默修复。
- entity kind 为 player、npc、location、item、enemy、faction、quest、fact。每个 kind 有固定组件集合；record 的 core keys、ID/kind 对应、lifecycle 和嵌套组件都必须 exact-key 校验。
- NPC 组件由 [NPC人格知识与关系图](./NPC人格知识与关系图.md) 约束；世界位置、任务、物品持有、战斗、结局和事件账本仍由各自规则/状态字段维护。
- `createWorldStateFromProjection` 是唯一组装点：编译 EntityStore，再由 `projectEntityStore` 生成 locations/npcs/items/quests 等兼容字段。生产写入禁止单独修改兼容数组。
- `eventLedger` 是 `CommittedNarrativeEvent[]`；实体组件中的 provenance 引用必须指向已提交事件，并满足顺序和实体存在性校验。
- 实体状态变更只能经 `src/game/gameplay/rpg/entityWorld/entityMutation.ts` 的 `applyEntityMutations` 细粒度 mutation 写入；`src/game/gameplay/rpg/entityWorld/proposedEntityCommand.ts` 的 `ProposedEntityCommand` 只负责解析、审批并转换为 mutation，目前没有接入 provider。
- 本地 SQLite 事务由 `sqliteClient` 为每次事务独占一条连接，沿用 write/read/deferred 的 BEGIN 映射。固定 COMMIT/ROLLBACK 经本地 SDK 的 exec 路径执行，避免失败的预编译 COMMIT 保留锁；普通语句仍用 execute。commit、rollback 和异步 close 均结束 SQL 后关闭连接；未提交 close 与失败 commit 先执行回滚，BEGIN 失败也关闭新连接，错误继续向仓储边界传播。所有事务 finally 必须 await close。关闭父 client 不终止已开始的独立事务，但拒绝新事务；并发事务仍由 SQLite 锁和仓储 CAS/fence 约束，不新增串行队列。事务端口仅提供 execute/commit/rollback/close/closed，不提供 batch 或 executeMultiple。
- 战斗快照保存 entity store 与 event ledger；失败恢复快照，避免失败行动进入永久连续性。

## 关键流程

```
SQLite JSON
  → parseEntityStore / validateEntityStoreStructure
  → EntityStore
  → projectEntityStore
  → WorldState selectors and gameplay rules
```

世界演化先审批 proposed delta，铸造实体 ID 和组件，再 materialize 到预览状态，最后由 application 的叙事整包 CAS 写回。任何未经审批的 provider 对象都不能直接进入存档。
