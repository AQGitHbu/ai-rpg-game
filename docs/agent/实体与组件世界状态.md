# 实体与组件世界状态（Plan 2/3 实现事实，待验收）

## 已实现边界

`WorldState.version=4` 的 `entityStore`（`EntityStore.version=2`）是玩家、NPC、地点、物品、敌人、阵营、任务、事实八类实体的唯一权威事实源。每个实体由稳定 ID、kind、名称、创建回合和生命周期组成，并携带固定命名组件；不存在动态 component 字典或任意 JSON Patch。旧 WorldState v3 / Entity Store v1 存档返回 `UNSUPPORTED_RECORD`，不做隐式迁移或静默重置。

兼容的 `player`、`locations`、`npcs`、`items`、`worldFacts`、`quests`、`enemies`、`factions`、位置/持有/解锁/到访/击败索引均由 `projectEntityStore` 确定性生成。`EntityMutation` 是规则层唯一写入语言，整批 mutation 在校验通过后一次性投影；世界引用、地点连接、NPC/物品位置和任务目标由 domain validator 约束。

`NpcEntityRecord` 现在固定由 `identity`、`position`、`dynamicState`、`knowledge`、`relationships`、`history` 组成：人格锚点（selfConcept、values、speechStyle、capabilityBoundaries、taboos）属于 identity；目标、相遇状态、情绪与同伴状态属于 dynamicState；知识条目保存 canonical `FactId`、certainty、disclosure 和 provenance；relationships 保存指向玩家或 NPC 的有向边、四维关系、stage/trend、承诺和有限证据；history 保存有界结构化交互。兼容 `NpcEntry/NpcMemory/relationship.affinity` 只能由 projector 读出，不能成为生产写路径。

战斗检查点保存完整战前 Entity Store 与 event ledger；失败或撤退时从检查点重建兼容投影，NPC 全组件一并恢复。SQLite 持久化边界严格验证 v4 envelope、Entity Store、引用闭包和投影一致性；旧版本返回 `UNSUPPORTED_RECORD`，损坏的 v4 实体状态返回 `ENTITY_STATE_INVALID`。

## 不可信命令与叙事上下文

`ProposedEntityCommand` 只允许 `move_npc`、`set_npc_lifecycle`、`place_item` 三种封闭形状。parser 拒绝未知字段、动态 component、patch 结构；approver 额外检查实体 kind、allowlist、地点 allowlist、生命周期和 active battle immovable 列表，再映射为规则可信 `EntityMutation`。命令目前未接入 provider 输出，AI 对既有实体没有更新权限；人格、知识、关系和承诺也没有通用 patch 入口。

`buildEntityContextProjection` 从 Entity Store 生成 mandatory/optional 规则闭包和五类撞名集合。scene、world、narrative bundle 上下文使用 store 投影，保留既有 DTO、预算、隐私边界、body-free manifest 与一次 provider 调用；不向 prompt 注入完整 store、event ledger、generation seed、未授权私密事实或裸关系数值。焦点 NPC 的 `NpcSpeechAuthority` 再按当前 speaker、scene-visible FactId、目标和交互历史生成唯一台词引用许可。

## NPC 创建与写入边界

- 开局 NPC 和 world-delta 新 NPC 都必须携带经 parser/approval 验证的 anchors 与 typed goals；动态 NPC 可携带最多四条定性 `relationshipSeeds`，只解析到既有 active NPC，服务器按 stance 铸造 source、stage、维度与 ID。
- 关系 seed 只创建 `newNpc → targetNpc`，不会自动生成反向边；普通行动不能更新 identity anchors。所有知识、关系、承诺、历史写入均由封闭 `EntityMutation` 的细粒度操作完成。
- `initial_world` 是创建时背景来源；行动来源必须带真实 `actionId + turnNumber`。`FactChange.audience` 决定知识接收者，没有 audience 不扩散；`npc_revealed` 还必须有真实 `sourceNpcId`。
- `importNpcLayers` 仅供测试 fixture/兼容投影把旧形状组装到组件，生产 opening、world materialization 和规则路径不使用 `legacy_import` 回退。
