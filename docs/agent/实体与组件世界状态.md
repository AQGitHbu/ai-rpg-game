# 实体与组件世界状态（Plan 2 实现事实）

## 已实现边界

`WorldState.version=3` 的 `entityStore` 是玩家、NPC、地点、物品、敌人、阵营、任务、事实八类实体的唯一权威事实源。每个实体由稳定 ID、kind、名称、创建回合和生命周期组成，并携带固定命名组件；不存在动态 component 字典或任意 JSON Patch。

兼容的 `player`、`locations`、`npcs`、`items`、`worldFacts`、`quests`、`enemies`、`factions`、位置/持有/解锁/到访/击败索引均由 `projectEntityStore` 确定性生成。`EntityMutation` 是规则层唯一写入语言，整批 mutation 在校验通过后一次性投影；世界引用、地点连接、NPC/物品位置和任务目标由 domain validator 约束。

战斗检查点保存完整战前 Entity Store 与 event ledger；失败或撤退时从检查点重建兼容投影。SQLite 持久化边界严格验证 v3 envelope、Entity Store、引用闭包和投影一致性；v2 存档返回 `UNSUPPORTED_RECORD`，损坏的 v3 实体状态返回 `ENTITY_STATE_INVALID`。

## 不可信命令与叙事上下文

`ProposedEntityCommand` 只允许 `move_npc`、`set_npc_lifecycle`、`place_item` 三种封闭形状。parser 拒绝未知字段、动态 component、patch 结构；approver 额外检查实体 kind、allowlist、地点 allowlist、生命周期和 active battle immovable 列表，再映射为规则可信 `EntityMutation`。命令目前未接入 provider 输出，AI 对既有实体没有更新权限。

`buildEntityContextProjection` 从 Entity Store 生成 mandatory/optional 规则闭包和五类撞名集合。scene、world、narrative bundle 上下文使用 store 投影，保留既有 DTO、预算、隐私边界、body-free manifest 与一次 provider 调用；不向 prompt 注入完整 store、event ledger、generation seed、未授权私密事实或裸关系数值。
