# 战斗与结局

## 状态

Phase 6 已规划，尚未开始（2026-07-28）。本阶段只为已解锁的主线第三阶段 boss 提供确定性轻量回合战，并让胜利与失败分别走到结构化、可恢复的两个结局。

## 设计边界

- 战斗地点、敌人、数值和任务目标都来自已编译 `ScenarioBlueprint`；UI、API、自由文本和 AI 都不能创建敌人、改生命或宣布胜负。
- 只允许 stage 3 active 时，在 boss 的预定义地点发起战斗。普通敌人继续只是蓝图内容，不产生可点击遭遇。
- 回合和伤害完全由纯 gameplay 规则确定；Phase 6 不使用随机、模型输出、客户端时钟或客户端数值。
- 胜利把 boss ID 写入 `GameState.defeatedEnemyIds`，由 reconciliation 满足 `defeat_enemy` 并完成任务；失败（撤退或生命归零）必须把该 active quest 置为 `failed`，再按其 `onFailure` 抵达失败结局。失败不删除存档，也不能伪装成成功。
- 结局是显式 runtime state 与领域事件，不从 UI 文案、事件文本或“最后一个任务状态”猜测。结局后禁止继续发起普通行动或第二次结算。
- 不含普通敌人遭遇、随机命中、技能、状态、掉落、经验、治疗、装备/物品效果、重试、关系/记忆或 AI 叙事。

## 预期完成事实

- 蓝图能验证敌人的地点落位；fallback boss 位于第三阶段可达的主要地点，三种固定 seed 都有一条有限的胜利行动序列。
- 玩家以 `start_battle { enemyId }` 发起战斗，并在 active battle 中选择 `attack`、`guard` 或 `withdraw`；非法阶段、地点、敌人、动作和非 active battle 都有稳定拒绝码且零写入。
- 每个 battle action 产生结构化回合结果和事件；胜利、撤退与生命归零各自只结算一次。
- 胜利完成 stage 3 并抵达成功结局；失败标记 stage 3 failed 并抵达失败结局；刷新恢复同一 ending read model，后续 action 被安全拒绝。
