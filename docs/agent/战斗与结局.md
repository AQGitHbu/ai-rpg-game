# 战斗与结局

## 职责

战斗、战败恢复、敌人击败、终幕立场和结局都是规则状态。AI 只提供已审批的场景表现与续接内容，不决定伤害、胜负或结局。

## 当前契约

- `attack` 只对当前位置合法敌人开启战斗；active battle 期间只投影当前玩家单位的 battle controls。
- 角色战斗属性由规则持有：`maxHp`、`maxEnergy`、`attack`、`defense`、`speed`。技能消耗能量，防御影响后续伤害，伤害使用 `combatMath` 的确定性公式。
- `battle_action` 由速度队列逐单位结算攻击、技能、防御和撤退；`advanceUntilPlayerDecision` 自动推进 rule-controlled 单位至下一玩家决策或结局。
- 活跃战斗回合最多一次 CAS，不创建 provider job。战斗开始与胜利交接只消费已批准的生产 `narrativeBundle` 步骤；缺步骤返回稳定错误并零写入。`PreparedContinuationState` 仅用于 offline fixture。
- 战败或撤退恢复战前检查点（entity store、event ledger 与 `NarrativeHistory`）；未击败敌人可再次挑战，胜利敌人由 `defeatedEnemyIds` 阻止重复开战。失败尝试可留在审计日志，但不能回到游戏 History。
- 敌人击败、任务完成/失败、候选事件和结局解析在同一规则提交中完成。结局后普通 Action 和叙事生成均停止。
- 终幕立场由 `src/game/gameplay/rpg/narrativeBundle/endingDecision.ts` 根据 World/Story 状态铸造为两个服务端 talk choices；结局 bundle 本身不提供终幕选项，结局对话不开放自由输入。
- `resolveEnding` 读取终幕 NPC 的结构化 dialogue act，并以支持/质疑立场和既有结构化条件决定结局；不读取台词关键词或玩家原文。

## 必要流程

```text
attack / battle_action → battleResolver / advanceBattle
→ checkpoint、战斗事件、任务 reconciliation → victory / defeat / retreat
→ endingDecision / resolveEnding → BattleView 或 ending read model
```

战斗失败链不进入永久事件记忆；成功战斗和结局事件带有真实 provenance，可由 event ledger 重建。
