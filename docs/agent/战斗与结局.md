# 战斗与结局

## 职责

战斗、战败恢复、敌人击败、终幕立场和结局都是规则状态。AI 只提供已审批的场景表现与续接内容，不决定伤害、胜负或结局。

## 当前契约

- 普通成功终幕先展示作者提供的两种实际选择标签；support/challenge 仍是既有规则动作，保密违约等规则可使实际结局不同于按钮主题。结算后只发布与真实 `endingId` 绑定的获批结果场景，并与 `ending_reached`、玩家选择、History 和当前场景在一次 CAS 中提交；结局后不再调用 provider。

- `attack` 只对当前位置合法敌人开启战斗；active battle 期间只投影当前玩家单位的 battle controls。
- 角色战斗属性由规则持有：`maxHp`、`maxEnergy`、`attack`、`defense`、`speed`。技能消耗能量，防御影响后续伤害，伤害使用 `combatMath` 的确定性公式。
- `battle_action` 由速度队列逐单位结算攻击、技能、防御和撤退；`advanceUntilPlayerDecision` 自动推进 rule-controlled 单位至下一玩家决策或结局。
- 活跃战斗回合最多一次 CAS，不创建 provider job。战斗开始与胜利交接只消费已批准的生产 `narrativeBundle` 步骤；缺步骤返回稳定错误并零写入。`PreparedContinuationState` 仅用于 offline fixture。
- 战败或撤退恢复战前检查点（entity store、event ledger 与 `NarrativeHistory`）；未击败敌人可再次挑战，胜利敌人由 `defeatedEnemyIds` 阻止重复开战。失败尝试可留在审计日志，但不能回到游戏 History。
- `BattleStartSnapshot` 还保存当前 `StoryState.threads` 与递送角色绑定；战败或撤退由 `performBattleRound` 一并恢复，战斗失败不能推进或清除开放问题、制造新的接应身份。
- 敌人击败、任务完成/失败、候选事件和结局解析在同一规则提交中完成。结局后普通 Action 和叙事生成均停止。
- 主线主动退出使用正式 `abandon_quest` Action：A 写入 `quest_abandoned` 并标记失败，B 通过唯一 `story_exit/story_exit` 生成退出终局；退出不伪造焦点 NPC 对话，也不自动转移任务物品。
- 终幕立场由 `src/game/gameplay/rpg/narrativeBundle/endingDecision.ts` 根据 World/Story 状态铸造为两个服务端 talk choices；按钮表达支持或保留疑虑，不预设取证、真相等故事事实。结局 bundle 本身不提供终幕选项，结局对话不开放自由输入。
- 终幕许可只闭合有规则依据的 Thread：无显式 closure、目标或承诺约束的 Quest-bound concern，须在所绑定任务均 completed/failed 且有对应已提交 outcome Event 后才能 resolved；多个 Thread 可绑定同一 Quest。无绑定、条件未满足或仍有目标/承诺的 Thread 保持未解决。结局对已存在时不再请求新 pair；终幕回应场景不带作者 choices，随后由 read model 投影两条规则立场。
- `resolveEnding` 对递送故事先确认唯一物品确实交给绑定接应人；无交付不能因最后一次支持/质疑结束。已经违背保密条款时优先采用承担后果的 doubt 方向，其余情况再依据结构化立场和条件选择。物品送达与是否守密分别保留，最后立场不清除违约；不读取台词关键词或玩家原文。

## 必要流程

```text
attack / battle_action → battleResolver / advanceBattle
→ checkpoint、战斗事件、任务 reconciliation → victory / defeat / retreat
→ endingDecision / resolveEnding 或 story_exit B → BattleView 或 ending read model
```

战斗失败链不进入永久事件记忆；成功战斗和结局事件带有真实 provenance，可由 event ledger 重建。
