# 战斗与结局

## 系统定位

战斗和结局是规则系统的正式状态，不由 AI 决定。玩家只能消费当前 `GameSessionView` 下发的战斗 opaque token；ruleEngine 计算伤害、回合、胜负、任务结果和 ending 条件。

## 当前规则

- `attack` 只对当前地点合法敌人开启战斗；active battle 期间只下发 battle controls。
- 战斗结束状态只保存上一场结果；撤退或失败后，未被击败的敌人仍可再次挑战，胜利后的敌人由 `defeatedEnemyIds` 阻止重复开战。
- `battle_action` 由规则计算玩家/敌人 HP、round 和结果；AI 只能描述已提交结果。
- 场景战斗的表现固定为己方在左、敌方在右；攻击时己方短距离突进，受击方抖动，伤害/回合提示在对应单位上方短暂浮现，并遵守 `prefers-reduced-motion`。
- 敌人击败、任务完成/失败、候选事件和结局解析在同一个玩家回合 StateCommit 中完成。
- 结局到达后，普通 Action 与 narrative scene 生成都停止；UI 显示结构化 ending name/description/outcome。
- stale、tampered 或已消费 token 不得重复伤害、奖励、任务或结局事件。

## 多结局证明

- 开局世界必须提供至少两个合法 ending 定义和可达条件。
- 同 seed 的“支持”与“质疑”路线在 NPC 关系和候选事件上分化，并分别抵达 `ending_trust` 与 `ending_doubt`。
- 各分支 15+ 成功回合、三次以上 reload，重复 replay 后 world/story state 完全一致。
- 结局差异必须由结构化选择后果驱动，不能只换 ending 文案。

## 主要文件与测试

- `src/game/gameplay/rpg/ruleEngine/battleResolver.ts` — 战斗规则。
- `src/game/gameplay/rpg/ruleEngine/resolveEnding.ts` — 结局解析。
- `src/game/application/performTurn.ts` — 战斗/结局回合编排。
- `src/game/application/gameSessionView.ts` — battle controls 与 ending read model。
- `src/game/application/testing/foundationJourney.test.ts` — 战斗与结局完整旅程。
- `src/game/application/testing/storyDivergenceJourney.test.ts` — 同 seed 多结局。

## 修改注意事项

- 不从 narration、NPC 台词或玩家自由文本直接设置胜负/ending。
- 新结局必须有可验证结构化条件、至少一条可达路径和分支回归。
- 结局后的请求必须稳定拒绝并零写入。
