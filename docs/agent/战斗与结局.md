# 战斗与结局

## 状态

Phase 6 已实现完成（2026-07-28）。本阶段为已解锁的主线第三阶段 boss 提供确定性轻量回合战，并让胜利与失败分别走到结构化、可恢复的两个结局。

## 设计边界

- 战斗地点、敌人、数值和任务目标都来自已编译 `ScenarioBlueprint`；UI、API、自由文本和 AI 都不能创建敌人、改生命或宣布胜负。
- 只允许 stage 3 active 时，在 boss 的预定义地点发起战斗。普通敌人继续只是蓝图内容，不产生可点击遭遇。
- 回合和伤害完全由纯 gameplay 规则确定；不使用随机、模型输出、客户端时钟或客户端数值。
- 胜利把 boss ID 写入 `GameState.defeatedEnemyIds`，由 reconciliation 满足 `defeat_enemy` 并完成任务；失败（撤退或生命归零）必须把该 active quest 置为 `failed`，再按其 `onFailure` 抵达失败结局。失败不删除存档，也不能伪装成成功。
- 结局是显式 runtime state 与领域事件，不从 UI 文案、事件文本或"最后一个任务状态"猜测。结局后禁止继续发起普通行动或第二次结算。
- 不含普通敌人遭遇、随机命中、技能、状态、掉落、经验、治疗、装备/物品效果、重试、关系/记忆或 AI 叙事。

## 实现事实

### 领域层扩展

**GameState 新增字段**：
- `defeatedEnemyIds: readonly EnemyId[]` - 已击败敌人 ID 列表
- `battle: BattleState` - 战斗运行时状态（idle | active | resolved）
- `ending: EndingState | null` - 结局运行时状态（null 表示未抵达）

**事件类型新增**：
- `BattleStartedEvent { type: "battle_started", enemyId, occurredAt }`
- `BattleRoundResolvedEvent { type: "battle_round_resolved", enemyId, round, playerHp, enemyHp, action, occurredAt }`
- `BattleResolvedEvent { type: "battle_resolved", enemyId, outcome: "victory" | "defeat" | "withdraw", occurredAt }`
- `EnemyDefeatedEvent { type: "enemy_defeated", enemyId, occurredAt }`
- `QuestFailedEvent { type: "quest_failed", questId, occurredAt }`
- `EndingReachedEvent { type: "ending_reached", endingId, outcome: "success" | "failure", occurredAt }`

**蓝图扩展**：
- `EnemyTemplate` 新增 `locationId: LocationId` 字段
- `EndingRequirement` 新增 `kind: "quest_failed"` 选项

**迁移兼容**：
- Phase 1-5 存档读取时补默认值：`defeatedEnemyIds: []`、`battle: { status: "idle" }`、`ending: null`
- Phase 5 蓝图（无 enemy.locationId）在 read-back 时补默认值（validator 校验时已被拒绝，但旧存档兼容）

### Gameplay 层实现

**Battle facade**（`src/game/gameplay/rpg/battle/`）：
- `startBattle(blueprint, state, enemyId, deps)` - 开始战斗，校验阶段/地点/敌人/状态，初始化 battle runtime state
- `battleAction(blueprint, state, action, deps)` - 处理 attack/guard/withdraw，计算确定伤害，更新 battle runtime state

**伤害公式（完全确定）**：
- `attack`: 玩家造成 `max(1, player.attack - enemy.defense)` 伤害；敌人未倒下时反击 `max(1, enemy.attack - player.defense)`
- `guard`: 玩家不造成伤害；敌人反击伤害固定减 2（最低 1）
- `withdraw`: 立即以失败结束战斗，不产生回合事件
- 胜利时敌人不反击；生命归零时战斗结束

**Quests facade 扩展**：
- `failQuest(blueprint, state, questId, deps)` - 显式失败入口，将 active quest 置为 failed 并应用 onFailure
- `resolveEnding(blueprint, state, deps)` - 结局解析器，检查所有结局 requirements，写入 ending runtime state

### Application 层实现

**Intent 扩展**：
- `start_battle { enemyId }` - 在敌人地点发起战斗
- `battle_action { action: "attack" | "guard" | "withdraw" }` - 执行战斗行动

**ValidationCode 新增**：
- `UNKNOWN_ENEMY` - 敌人不存在于蓝图
- `ENEMY_NOT_AT_LOCATION` - 玩家不在敌人所在地点
- `BATTLE_ALREADY_ACTIVE` - 已有进行中的战斗
- `ENDING_REACHED` - 游戏已结局
- `ENEMY_NOT_STAGE3_TARGET` - 敌人不是当前 stage 3 active 任务的击败目标
- `ENEMY_ALREADY_DEFEATED` - 敌人已被击败

**PerformAction 编排**（`src/game/application/performAction.ts`）：
1. 读取游戏与 revision 预检
2. 结局已抵达时安全拒绝且零写入
3. 路由到 battle facade（start_battle / battle_action）
4. Battle resolved 后按 outcome 走 quest success/failure 路径
5. Quest reconciliation/failure 后调用 resolveEnding 检查结局条件
6. 一次 `applyResolvedAction` CAS 原子写入
7. 从已保存 state 投影最新 `GameSessionView`

**Read Model 投影**（`src/game/application/gameSessionView.ts`）：
- `BattleView { enemyName, playerHp, enemyHp, round }` - 仅在 active battle 时投影
- `EndingView { name, description, outcome }` - 结局抵达后投影
- 结局后 `availableActions` 为空；战斗中只投影 `battle_action` 类型的行动
