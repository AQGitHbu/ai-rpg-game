# 剧情连续性与结构化记忆

## 职责

本系统维护事件账本、已发布叙事原文、情节记忆与检索；主线和幕推进由任务规则负责，叙事生成由运行时 AI 负责。规则提交事件，事件账本是连续性的事实来源；`StoryState.history` 保存实际提交的 A/B 原文，`StoryState.memory` 是从完整账本确定性重建的投影，二者都不是候选正文的缓存。

## 当前契约

- 存档版本与错误分类见 [实体状态](实体与组件世界状态.md)；事件以稳定身份、顺序和引用定义，不用 WorldState 的 schema 号命名。
- `CommittedNarrativeEvent` 由 canonical commit helper 铸造，带稳定 `eventId`、`episodeId`、顺序、因果事件引用、实体/任务/事实/地点引用和 payload。规则、开局、世界增量、场景写回与战斗使用同一账本。
- `NarrativeHistory` 由 `appendHistory` 按稳定 ID 幂等追加；玩家选择/自由输入保存完整原文，实际发布的旁白、NPC 台词和展示选项按 `expressions` 顺序保存。`shown_choice` 只是展示，不是玩家言行，也不产生 Event；生成但未消费的 continuation 不进入 History。
- 场景表达式的 `audienceIds` 是实际听众。旁白只对玩家可见；同场 NPC 不会自动听见私聊，后续 NPC 只能使用在更早表达中明确披露给自己的事实。旧 `segments`/`npcLine` 字段只作为输入和 UI 兼容投影，正文权威是有序 `expressions`。
- 初始化既往事件按顺序提交 `opening_history_established`，开放问题提交 `opening_thread_established`；两者属于 `init:<generationId>` episode、turnNumber=0，并携带事实、参与者与因果引用。公开历史正文由账本和当前知识权限投影，SQLite reload 后从同一 ledger 重建，不另存一份权威摘要。
- `rebuildEpisodicMemory` 从完整 ledger 重建 episodes、recent scenes 和 NPC contacts。SQLite reload 校验 ledger 与 memory 的深度一致性。
- `retrieveNarrativeMemory` 按 required event/episode、任务或事实、实体、因果、地点、显著度和顺序稳定排序，输出有界 memory cards；近期场景是独立的有界工作上下文。
- 历史 memory cards 不包含玩家原文、secret fact 正文、其他 NPC history 或裸关系数值；本轮 job 的玩家选项或自由输入由生产叙事上下文按当前任务提供，不写入历史记忆卡。引用只能指向已提交且顺序有效的事件。
- 战斗失败回滚战前 entity store、event ledger 与 History 快照，不留下失败链；胜利只提交胜利 episode 及其 cause chain。
- 生产场景消费 narrative bundle；消费当前 scene 的 presented event 与规则结果同次 CAS 写入。PreparedContinuationState 仅离线 fixture。

## 关键流程

```
规则/开局/审批结果
  → commitEventDrafts
  → rebuildEpisodicMemory
  → StoryState.history 与 memory、ledger 同次持久化
  → retrieveNarrativeMemory / renderNarrativeMemory
  → 有界 prompt context
```

初始化 thread 只是首轮回应与因果召回使用的开放问题种子，不进入 `unresolvedThreads` 的节奏或终幕规则。当前没有覆盖创建、推进、关闭的完整 Story Thread 生命周期，也没有层级 Living Outline、真实 Arc 或分段账本；初始问题在第一次 handoff 后不被永久当作当前局面。相关计划不代表已实现。

连续性判断仍由规则状态完成：`currentAct`、`reveal` 游标、active quest/objective、`endingAllowed` 和 evolution status 决定可见目标；记忆只提供相关历史，不改变行动裁决。

## 代码与测试入口

- 状态：`src/game/domain/storyState.ts`、`src/game/domain/events.ts`、`src/game/domain/eventLedger.ts`、`src/game/domain/episodicMemory.ts`
- 记忆：`src/game/domain/episodicMemory.ts`、`src/game/gameplay/rpg/narrativeMemory/retrieveNarrativeMemory.ts`、`src/game/gameplay/rpg/narrativeMemory/renderNarrativeMemory.ts`
- 编排：`src/game/application/reconcileCommittedMemory.ts`、`src/game/application/generatePendingNarrativeBundle.ts`
- 会话与规则：`src/game/gameplay/rpg/dialogue/`、`src/game/gameplay/rpg/narrativeContext/`、`src/game/application/performTurn.ts`
- 测试：`src/game/gameplay/rpg/narrativeMemory/*.test.ts`、`src/game/application/server/persistence/*Validation.test.ts`、`src/game/application/*NarrativeBundle*.test.ts`

`episodicMemoryJourney` 验证长间隔事件召回与 reload；`npcContinuityJourney` 验证完整中篇的规则链。它们使用显式 fixture 场景/续接，不能证明生产 decision bundle 完整旅程；生产 bundle 单元测试与中篇初始化测试的覆盖范围不同。
