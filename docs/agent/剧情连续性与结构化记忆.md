# 剧情连续性与结构化记忆

## 系统定位

Phase 11 计划把追加式规则事件账本归约为有界、可持久化的结构化剧情记忆，并把按角色最小授权裁剪后的连续性信息提供给运行时叙事链路。它是内容推进引擎，不是让 AI 自由写世界历史。

## 已冻结设计

- `eventLedger` 是事实源；memory 只由纯 reducer 从已提交事件归约，AI 原文不入记忆。
- memory 最多保存 12 个近期里程碑与每个 NPC 最后一次结构化接触；旧存档缺失字段安全回退为空记忆。
- 每个 ready scene 以 `narrative_scene_presented` 记录安全的结构索引，并与 scene/memory 同一次 CAS 保存。
- 主线阶段派生 allowed pacing；不合阶段的 director proposal 会被规则拒绝。
- NPC 只能看到自己的接触记录与本次批准的 fact cards；不得读取其他 NPC history、完整账本或隐藏事实。

## 修改注意事项

- 不从 narration 或 NPC text 反推事实、关系或任务状态。
- 不把完整 `GameState`、`eventLedger`、prompt、provider/config 传给任一角色。
- director 接收最多 12 条玩家安全连续性；writer 仅接收最近 6 条、角色身份和已批准 fact cards；NPC 仅接收自身最后接触与本次 fact cards，不接收全局事件或其他 NPC 信息。
- 玩家可见场景选项的标签由规则 action candidate 最终决定；AI 可写 narration，但不能把 actionKey 的含义改写为另一种行动。
- CAS 冲突必须丢弃已生成内容，不能补写 memory 或再调用 AI。
- 动态蓝图扩展、关系数值、自由输入和真实 AI 录制都不属于本阶段默认实现。

## v2.1 持久化规模边界与长篇门禁（Task 32）

### 当前支持的存档规模

- **正式支持：短篇 / 中篇。** `v2.1` 的 `GameRecordV2` 以单个 JSON `worldState + storyState` 列承载整局状态，`revision` 为唯一 CAS 屏障。80 回合连续 CAS 写入 + reload 一致性已由 `sqliteGameRepositoryV2.test.ts` 规模用例覆盖（事件逐回合累积、turnNumber/张力/事件数语义正确）。
- **long / open 尚未正式承诺。** 当前实现**不是**独立 append-only event table；`eventLedger` 随整份 JSON 一起重写，超长局会线性增长单条 record。

### 长篇门禁（启用 long/open 之前必须满足）

1. 先另立专门的 **segmented ledger Plan/Spec**，覆盖：事务原子性、snapshot/cursor、事件归档、确定性回放和存档迁移；不得在本 Task 顺手重写 repository。
2. 该 Plan 完成前，**UI / 产品配置不得声称“无限长期记忆”或“无限时长游戏”**；只能呈现短篇/中篇上限。
3. 超长局到达边界时应给出明确错误分类（例如 `LEGACY_V2_RECORD` / `corrupt` / 长度超限），而不是让旧因果不完整状态伪装成新状态。
