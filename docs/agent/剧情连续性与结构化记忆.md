# 剧情连续性与结构化记忆

## 系统定位

结构化事件与 story state 保存玩家选择造成的长期后果，并为下一幕提供有界、最小权限的连续性上下文。它不是让 AI 保存自由文本历史，也不是无限增长的聊天记录。

## 当前规则

- `WorldState.eventLedger` 与 `StoryState` 是正式事实；AI narration/NPC 台词不反推规则状态。
- `StoryState.contract` 保存开局故事契约（幕数、中心冲突、两个抽象结局方向）；`StoryState.evolution` 保存 ID 铸造序号与演化状态（`stable` / `needs_next_act` / `needs_ending_pair`）。两者都不含任何未来实体 ID。
- 2026-08-23 起，共享上下文编译器位于 `src/game/application/server/ai/narrativeContext/`：统一 IR `NarrativeContextBlock={id, slot, title, content, authority, retention, priority, conflictKey?, source}`；authority 固定按 `rule → state → event → plan → memory → lore` 比较，输出 slot 固定按 `system_rules → world_canon → story_contract → current_state → current_resolution → current_location → focus_character → relationships → relevant_events → recent_scenes → director_guidance → player_action → legal_actions → output_contract` 排序。当前 v7 生产决策链通过 `compileDecisionNarrativeContext` 生成统一 `narrative_bundle` Prompt。
- 每个成功玩家回合形成唯一 `actionId`、`TurnResolution`、结构化事件和 `PendingNarrativeJob`。
- `talk_to_npc` 的权威 `ask` 会创建目标 NPC 的零轮未完成 `dialogueSession`，不会完成任务；完成两次正式回应后规则层写入 `npc_dialogue_completed`。后续目标切换时以该结构化事件保留历史完成事实，`met` 只表示接触过，不能代替对话完成证据。
- 回合提交前从规则结果 + before/after 状态纯派生 `ObjectiveTransition`（before/completed/after + mode）与强制节拍（`MandatoryNarrativeBeat`，≤8）并随 job 持久化；禁止把事件正文/账本字符串丢给 AI 去推断状态变化。
- NPC 记忆只保存规则化 dialogue act、topic summary、learned fact IDs、关系、情绪和最近有限条 interaction history；玩家原文不进入长期记忆。
- 焦点 NPC 上下文只含最近 5 条结构化交互与关系政策；场景表演只收到该 NPC 自己的已知/允许隐藏事实与交互 actionId，私密事实正文不出现。
- 同 action ID 的重试不能重复追加 NPC 记忆；CAS 失败零写入。
- SceneGenerationContext 只提供当前任务的结构化摘要/节奏/预算、玩家安全摘要、在场 NPC、焦点 NPC 隔离上下文与当前合法候选；对话选项依赖这些结构化字段，不从 NPC prose 反推主题。
- 已批准的世界演化（新实体）与 ready scene、choice registry、候选事件池经独立 scene CAS 原子写回。
- `StoryState.reveal` 保存当前任务的可见目标游标；演化写入可以完整保存一幕，但 read model、合法行动和 AI 场景上下文只投影游标以内的目标。目标满足后规则层只释放下一步，避免 NPC、证物或敌人提前出场；没有该字段的旧存档按“全部已释放”兼容读取，不破坏历史进度。

## 叙事上下文编译器（2026-08-23）

- `compileNarrativeContext` 先丢弃空正文块（`empty`），再按 `id` 去重（`duplicate`），再按 `conflictKey` 冲突裁决（`conflict`），最后只对 optional 块做预算裁剪（`budget`）。mandatory 块永远进入输出，即使导致 `overflowEstimatedTokens > 0`；optional 块按 `priority desc → authority → slot → id` 选择，直到命中 `maxEstimatedTokens`。
- 编译结果分成 `selected`、`dropped`、`selectedEstimatedTokens`、`overflowEstimatedTokens` 和 `manifest`。`manifest` 只保留 block 元数据、预算与裁剪结果：`compilerVersion/maxEstimatedTokens/selectedEstimatedTokens/overflowEstimatedTokens/selected[]/dropped[]`；不保存 Prompt 正文，也不复制额外 prompt 片段。
- 当前 v7 生产决策调用由 `compileDecisionNarrativeContext` 生成；它将 Story Contract、当前幕/张力/节奏/预算、近期 beats、强制节拍、焦点 NPC 五条结构化交互、公开事实、实体索引、叙事包图和完整 output contract 组成一个 8k 预算 Prompt，并产出无正文 manifest。历史 scene/world source 分别保留 `compileSceneNarrativeContext` / `compileWorldNarrativeContext`。初始化 `opening` 分支与 `intent` 仍沿用现有上下文与 schema，尚未迁入该编译协议；Entity/Episode/Living Outline 记忆仍属后续 Plan，不应视为已落地能力。
- 本阶段只重组 Prompt 上下文，不引入存档迁移、不增加额外 AI 调用、不改变规则结算、scene/world 审批链，也不改变战斗失败回滚。

## 世界演化与连续具象化

- 演化需求由领域纯派生：幕推进 → `needs_next_act`，节奏低 → `pacing: complicate/escalate`，终幕 → `needs_ending_pair`；正常回合为 `none`，不调用演化源。
- 只在 `need.kind !== "none"` 时调用世界演化源；AI 产出 `WorldDeltaProposal`（纯字符串引用），`approveWorldDelta` 校验类型/引用/预算/可达性/结局对后由服务端铸造品牌化 ID，`materializeWorldDelta` 装配预览状态。
- 未知实体引用回合可走修复路径：把行动引用 ID 原样铸造为缺失实体并重演算，成功则单次 CAS 提交。
- 终幕具象化一对互斥结局（trust/doubt 两个抽象方向）；requirements 由规则按关键 NPC 亲和度派生，AI 仅提供名称/描述/方向，不存在预生成的隐藏任务图。
- live 世界演化提案即使 JSON 合法但语义审批失败，也只在允许的 provider job 内按一次内容修复重试；仍失败则零演化写入并进入 stable failed，不能用确定性 fallback 冒充生产成功。显式 fixture 才能提供离线确定性世界演化。
- 目标链结构由 seed+act 在四种合法变体（全程链/调查聚焦/对峙聚焦/跑腿聚焦）中确定性选择；任何变体保留 talk 锚点，过滤为空回退全程链。完整链按 `discover_fact → visit_location → talk_to_npc → obtain_item → defeat_enemy` 排列，变体在此基础上过滤出合法子集；物化新地点的幕，链首恒保留 `visit_location`（含变体过滤掉后补挂回链首）——否则新地点永远不会被释放游标解锁，挂载其上的交谈/取证/战斗目标全部不可达，主线软锁；此时调查聚焦/对峙聚焦实际产出的是比全程链仅少尾部步骤的四步链。例如全程链时先调查酒楼后巷的车轮印，再前往北巷旧道，最后与顾砚交谈。地点名称、人物台词和线索正文必须与当前空间层级一致；完成整条链才推进下一幕，不能用一次对话跳过取证与冲突。
- 场景中出现非焦点 NPC 时，同一次场景生成可以为其写入零回合闲聊，但持久化记录必须标记 `speechPurpose=ambient`；焦点正式台词标记为 `focus`。读模型不能用 `speechSource=generated` 推断用途：当环境 NPC 随后成为权威目标时，旧 ambient 台词不得充当开场，只显示单一 `ask` 入口并等待正式 provider 回应。旧存档缺少 purpose 时，仅 `scene.npcLine.npcId` 兼容推断为 focus。
- 具象化受软顶/硬顶约束；达到收束或预算边界时停止扩张。

## 选择分化

- 15+ 回合旅程跨多次 repository reload 后，turn number、事件、任务、关系与结局保持一致。
- 同 seed 的"支持/质疑"固定选择与后续不同自定义输入会改变 NPC affinity、emotion、interaction history 与 candidate event。
- 两条路线分别抵达不同结局方向（trust/doubt：结局以规则要求铸造，按关键 NPC 亲和度裁决，离线可达）；同一路线重复 replay 的 `WorldState + StoryState` 完全一致。
- 分化必须来自结构化后果，不以 narration 不同冒充状态不同。

## 持久化规模边界

- `GameRecord` 以单条 JSON `worldState + storyState` 保存整局，`revision` 是唯一 CAS 屏障。
- 正式支持短篇/中篇；当前产品 UI 只开放这两档。
- 不承诺无限长期记忆、无限时长或无限扩张。

### 长篇门禁

启用长篇/开放式之前必须另立 segmented ledger Spec/Plan，并完成：

1. append/event 分段与事务原子性；
2. snapshot/cursor、事件归档与确定性回放；
3. 存档迁移、完整性检测与容量错误分类；
4. 长局 reload、恢复、压缩和因果一致性门禁。

## 修改注意事项

- 不记录完整 prompt、模型原文、玩家原文、完整 state 或其他 NPC 的私有历史。
- 新 memory 字段必须能由已提交事件确定性归约，并有长度边界与坏数据处理。
- CAS 冲突不补写 memory，也不自动重放玩家选择或再次调用 AI。

## Entity Store 基础（Plan 2）

自 `WorldState.version=3` 起，实体事实由 `entityStore` 统一承载，兼容数组由 projector 派生；持久化读取会校验 store、引用和投影一致性。Entity 上下文只投影当前规则闭包，NPC 私密事实与交互历史仍受焦点授权边界约束。
