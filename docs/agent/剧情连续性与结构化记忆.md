# 剧情连续性与结构化记忆（Plan 4 已实现并合入 main）

## 系统定位

结构化事件与 story state 保存玩家选择造成的长期后果，并为下一幕提供有界、最小权限的连续性上下文。它不是让 AI 保存自由文本历史，也不是无限增长的聊天记录。

## 2026-09-04 main 复核修复

- `eventPayloadValidation.ts` 对全部 28 种 payload 做必填/可选字段、嵌套结构和值域校验，拒绝夹带任意 rawText；`parseCommittedEventLedger` 同时验证封闭 envelope、Event ID 唯一、连续 sequence、较早 cause、时间与引用数组形状。Entity 引用仍由提交/持久化边界负责，不把结构校验当成所有语义均已验证。
- `commitEventDrafts` 校验输入账本和最终账本，幂等比较包含 turnId/turnNumber；提交时复制 payload 与引用数组，避免调用方后续修改 draft 污染已提交事件。
- `retrieveNarrativeMemory` 的显式 Event 引用可提升关联 Episode；Fact 与 Quest 同级，当前必需事件的直接前因可召回。生产 scene/bundle 查询以本 job 最早 domain Event sequence 为历史上界，从 ledger 前缀重建历史 memory，不把本轮结果重复当旧经历；本轮必需 Event 仍单独提供。
- 物品不伪装为 actor/target 角色：检索直接匹配 item_obtained/item_given payload 的 itemId；每个命中 Episode 最多投影 3 条精确物品事件卡并记录 manifest Event ID。仅凭相关物品也能召回取得/赠送经历，不改持久化 Episode schema。
- `consumeNarrativeBundle` 只有真正消费某一步时才提交 `narrative_scene_presented`，沿用该规则回合/战斗 Episode 与因果，在原有单次 CAS 中重建 memory；准备未来步骤时不提前记账，不新增 provider 调用。
- 中文占用名称索引显式采用 `zh-CN` 排序，保证 prompt 投影和回归测试不依赖机器默认 locale。
- 本轮通过针对性回归、完整测试（181 文件 / 2450 tests）、typecheck、test:fast、journey:foundation 和 build；lint 无错误但保留既有 warnings。未重新执行真实 AI 游玩验收。战斗失败/撤退回到战前的设计保持不变。
- 下一阶段为 `docs/superpowers/plans/2026-09-04-hierarchical-living-outline-story-threads.md`，仅已规划；当前 StoryState 尚无 outline 字段，仍是 v8。

## 当前规则

- `WorldState.eventLedger` 与 `StoryState` 是正式事实；AI narration/NPC 台词不反推规则状态。
- `StoryState.contract` 保存开局故事契约（幕数、中心冲突、两个抽象结局方向）；`StoryState.evolution` 保存 ID 铸造序号与演化状态（`stable` / `needs_next_act` / `needs_ending_pair`）。两者都不含任何未来实体 ID。
- 当前正式存档为 `WorldState.version=5`、`StoryState.version=8`、`EntityStore.version=2`；v4/v7 及更早的开发存档返回 `UNSUPPORTED_RECORD`，不做静默迁移。Entity Store 继续承载 NPC 的 identity/dynamicState/knowledge/relationships/history 五层组件；旧 `NpcMemory` 与 `relationship.affinity` 只是不具权威性的兼容投影。
- 2026-08-23 起，共享上下文编译器位于 `src/game/application/server/ai/narrativeContext/`：统一 IR `NarrativeContextBlock={id, slot, title, content, authority, retention, priority, conflictKey?, source}`；authority 固定按 `rule → state → event → plan → memory → lore` 比较，输出 slot 固定按 `system_rules → world_canon → story_contract → current_state → current_resolution → current_location → focus_character → relationships → relevant_events → recent_scenes → director_guidance → player_action → legal_actions → output_contract` 排序。当前 v7 生产决策链通过 `compileDecisionNarrativeContext` 生成统一 `narrative_bundle` Prompt。
- 每个成功玩家回合形成唯一 `actionId`、`TurnResolution` 和结构化事件；只有正式焦点 NPC 决策进入 `PendingNarrativeJob`，线性 bundle 消费不创建新 provider job。
- `WorldState.eventLedger` 只保存由 `commitEventDrafts` 铸造的 `CommittedNarrativeEvent`：稳定 `eventId`、连续 `sequence`、真实 `turnId/turnNumber/actionId`、参与者、地点、因果、Fact/Quest 引用、结果和显著度都在 envelope 中。初始化、规则回合、世界演化、场景写回和战斗共用该提交边界。
- `StoryState.memory` 由完整 ledger 确定性重建为 Episode、近期场景和 NPC 接触索引；`retrieveNarrativeMemory` 按硬引用、任务/事实、实体、因果、地点、显著度和 sequence 稳定排序，renderer 只输出有界 memory cards，不输出完整账本。
- 含 `narrativeBundle` 的 provider pending 写回也必须在同一 CAS 前把场景事件并入最终 ledger，再重建 `StoryState.memory`；否则 SQLite 的 ledger/memory 一致性校验会拒绝写回并留下不可推进的 pending 状态。
- `talk_to_npc` 的权威 `ask` 会创建目标 NPC 的零轮未完成 `dialogueSession`，不会完成任务；完成两次正式回应后规则层写入 `npc_dialogue_completed`。后续目标切换时以该结构化事件保留历史完成事实，`met` 只表示接触过，不能代替对话完成证据。
- 回合提交前从规则结果 + before/after 状态纯派生 `ObjectiveTransition`（before/completed/after + mode）与强制节拍（`MandatoryNarrativeBeat`，≤8）并随 job 持久化；禁止把事件正文/账本字符串丢给 AI 去推断状态变化。
- NPC history 只保存规则化 dialogue act、topic summary、learned fact IDs、关系、情绪和最近有限条 interaction history；玩家原文不进入长期记忆。knowledge 额外保存 FactId、certainty、disclosure 与真实 Event ID 来源；relationship evidence、interaction 和台词引用也必须指向 ledger 中已提交的 Event。
- 焦点 NPC 上下文只含最近 5 条结构化交互与关系政策；场景表演由 `NpcSpeechAuthority` 投影该 NPC 自己的可披露事实、允许的 interaction actionId、目标关系和 identity anchors，私密事实正文不出现。
- 同 action ID 的重试不能重复追加 NPC 记忆；CAS 失败零写入。
- SceneGenerationContext 只提供当前任务的结构化摘要/节奏/预算、玩家安全摘要、在场 NPC、焦点 NPC 隔离上下文与当前合法候选；对话选项依赖这些结构化字段，不从 NPC prose 反推主题。
- 已批准的世界演化（新实体）与 ready scene、choice registry、候选事件池经独立 scene CAS 原子写回。
- `StoryState.reveal` 保存当前任务的可见目标游标；演化写入可以完整保存一幕，但 read model、合法行动和 AI 场景上下文只投影游标以内的目标。目标满足后规则层只释放下一步，避免 NPC、证物或敌人提前出场；没有该字段的旧存档按“全部已释放”兼容读取，不破坏历史进度。

## Plan 3 NPC 连续性

- `NpcIdentityAnchors` 只在 opening 或经审批的动态 NPC 创建时进入 Entity Store；普通场景、关系 signal 和 AI command 不能改写人格。创建材料同时包含有界 typed goals，动态 NPC 可建立定性、单向的 `relationshipSeeds`。
- FactChange 只有在规则明确列出 `audience` 时才传播 knowledge；`hidden` 零写入，`npc_revealed` 必须有真实 `sourceNpcId`。同一 NPC/FactId 幂等，certainty 只能升级，disclosure 只能由显式 mutation 改变。
- 关系边保存 `affinity/trust/fear/hostility`、stage/trend、evidence 和 debt/promise commitments。变化只由封闭 relationship signal 表产生，受单行动 cap、stage 邻接、证据上限和 actionId 幂等约束；A→B 不自动产生 B→A。
- 对话、调查、赠物、明确 NPC 任务和共同战斗从同一 `projectNpcRuntimeProfile`/Entity Store 读取。没有明确参与者时不猜关系后果；战斗失败/撤退恢复全部 NPC 组件，胜利只给真实参战同伴写 `fought_together`。
- 每条 NPC 台词和闲聊的 Fact/Interaction 引用都经过同一 `NpcSpeechAuthority`；opening preview、narrative bundle、prepared continuation、scene write-back 四条审批路径拒绝重复或越权引用，而不是静默删掉引用。

## 叙事上下文编译器（2026-08-23）

- `compileNarrativeContext` 先丢弃空正文块（`empty`），再按 `id` 去重（`duplicate`），再按 `conflictKey` 冲突裁决（`conflict`），最后只对 optional 块做预算裁剪（`budget`）。mandatory 块永远进入输出，即使导致 `overflowEstimatedTokens > 0`；optional 块按 `priority desc → authority → slot → id` 选择，直到命中 `maxEstimatedTokens`。
- 编译结果分成 `selected`、`dropped`、`selectedEstimatedTokens`、`overflowEstimatedTokens` 和 `manifest`。`manifest` 只保留 block 元数据、预算与裁剪结果：`compilerVersion/maxEstimatedTokens/selectedEstimatedTokens/overflowEstimatedTokens/selected[]/dropped[]`；不保存 Prompt 正文，也不复制额外 prompt 片段。
- 当前 v7 生产决策调用由 `compileDecisionNarrativeContext` 生成；它将 Story Contract、当前幕/张力/节奏/预算、近期 beats、强制节拍、焦点 NPC 五条结构化交互、公开事实、实体索引、叙事包图、结构化 Episodic Memory 和完整 output contract 组成一个 8k 预算 Prompt，并产出无正文 manifest。历史 scene/world source 分别保留 `compileSceneNarrativeContext` / `compileWorldNarrativeContext`；Event/Episode 记忆已由同一 ledger 接入，Living Outline 仍属后续 Plan。
- Plan 4 不引入存档迁移、不增加 provider 调用、不改变规则结算、scene/world 审批链或战斗失败回滚；它只把已提交事实编译为确定性的结构化记忆。

## 世界演化与连续具象化

- 演化需求由领域纯派生：幕推进 → `needs_next_act`，节奏低 → `pacing: complicate/escalate`，终幕 → `needs_ending_pair`；正常回合为 `none`，不调用演化源。
- 只在 `need.kind !== "none"` 时调用世界演化源；AI 产出 `WorldDeltaProposal`（纯字符串引用），`approveWorldDelta` 校验类型/引用/预算/可达性/结局对后由服务端铸造品牌化 ID，`materializeWorldDelta` 装配预览状态。
- 未知实体引用回合可走修复路径：把行动引用 ID 原样铸造为缺失实体并重演算，成功则单次 CAS 提交。
- 终幕具象化一对互斥结局（trust/doubt 两个抽象方向）；requirements 由规则按关键 NPC 亲和度派生，AI 仅提供名称/描述/方向，不存在预生成的隐藏任务图。
- live 世界演化提案即使 JSON 合法但语义审批失败，也只在允许的 provider job 内按一次内容修复重试；仍失败则零演化写入并进入 stable failed，不能用确定性 fallback 冒充生产成功。显式 fixture 才能提供离线确定性世界演化。
- 目标链结构由 seed+act 在四种合法变体（全程链/调查聚焦/对峙聚焦/跑腿聚焦）中确定性选择；任何变体保留 talk 锚点，过滤为空回退全程链。完整链按 `discover_fact → visit_location → talk_to_npc → obtain_item → defeat_enemy` 排列，变体在此基础上过滤出合法子集；物化新地点的幕，链首恒保留 `visit_location`（含变体过滤掉后补挂回链首）——否则新地点永远不会被释放游标解锁，挂载其上的交谈/取证/战斗目标全部不可达，主线软锁；此时调查聚焦/对峙聚焦实际产出的是比全程链仅少尾部步骤的四步链。例如全程链时先调查酒楼后巷的车轮印，再前往北巷旧道，最后与顾砚交谈。地点名称、人物台词和线索正文必须与当前空间层级一致；完成整条链才推进下一幕，不能用一次对话跳过取证与冲突。
- 场景中出现非焦点 NPC 时，同一次场景生成可以为其写入零回合闲聊，但持久化记录必须标记 `speechPurpose=ambient`；焦点正式台词标记为 `focus`。读模型不能用 `speechSource=generated` 推断用途：当环境 NPC 随后成为权威目标时，旧 ambient 台词不得充当开场，只显示单一 `ask` 入口并等待正式 provider 回应。旧存档缺少 purpose 时，仅 `scene.npcLine.npcId` 兼容推断为 focus。
- 具象化受软顶/硬顶约束；达到收束或预算边界时停止扩张。

## 选择分化

- 15+ 回合旅程跨多次 repository reload 后，turn number、事件、任务、关系与结局保持一致。
- 同 seed 的"支持/质疑"固定选择与后续不同自定义输入会改变 NPC 关系维度/stage、emotion、interaction history 与 candidate event；兼容 read model 仍投影 player edge 的 affinity。
- 两条路线分别抵达不同结局方向（trust/doubt：结局以规则要求铸造，按关键 NPC 亲和度裁决，离线可达）；同一路线重复 replay 的 `WorldState + StoryState` 完全一致。
- 分化必须来自结构化后果，不以 narration 不同冒充状态不同。

## 持久化规模边界

- `GameRecord` 以单条 JSON `worldState + storyState` 保存整局，`revision` 是唯一 CAS 屏障；每次 state/scene CAS 前重建 memory，SQLite 读取会用完整 ledger 重建并 deep-compare，漂移按稳定 corrupt 分类拒绝。
- 正式支持短篇/中篇；当前产品 UI 只开放这两档。
- 不承诺无限长期记忆、无限时长或无限扩张。

### 长篇门禁

启用长篇/开放式之前必须另立 segmented ledger Spec/Plan，并完成：

1. append/event 分段与事务原子性；
2. snapshot/cursor、事件归档与确定性回放；
3. 存档迁移、完整性检测与容量错误分类；
4. 长局 reload、恢复、压缩和因果一致性门禁。

## Entity Store 基础（Plan 2/3）

自 `WorldState.version=5` / `StoryState.version=8` / `EntityStore.version=2` 起，实体事实由 `entityStore` 统一承载，兼容数组由 projector 派生；持久化读取会校验 store、ledger、memory、引用和投影一致性，旧版本返回 `UNSUPPORTED_RECORD`。Entity 上下文只投影当前规则闭包，NPC 私密事实与交互历史由 `NpcSpeechAuthority` 进一步按 speaker、scene-visible facts、目标和真实 Event ID 授权。
