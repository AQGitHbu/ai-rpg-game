# NPC 闲聊功能实现说明

> 本文早期版本记录的 `smallTalk` 和 read model 确定性闲聊方案已废弃。旧场景数据中的 `smallTalk` 字段仍可读取以保持兼容，但不再进入新的场景生成契约。
>
> 2026-08-23 起，live scene API 在生成焦点 NPC 场景时，同一次响应同步返回所有非焦点 NPC 的 `npcDialogues`；这些对白随场景写回并保留 `speechSource="generated"`。点击非焦点/交接 NPC 仍是零回合只读展示，不提交回合、不创建 pending、不推进剧情。

## 当前契约（2026-08-23）：同次 API 生成、零回合闲聊

- live scene JSON 的 `npcDialogues` 为除 `npcLine.npcId` 外的每个在场 NPC 各提供一条直接闲聊；它与主场景、焦点 NPC 台词使用同一次 API 请求生成，不新增 API 调用。
- 闲聊只允许承接公开身份和当前地点，不推进任务、不改变规则、不泄露私密事实、不创造新实体；缺失或非法对白会触发内容修复，不能把 generated 场景静默写成确定性成功。
- 交接场景中，旧焦点 NPC 必须继续作为 `npcLine` 发言，并在最后一句自然引出权威新目标；`quest_advanced` 必须引用新目标实体 ID，否则进入内容修复。
- 交互形态：点击非焦点/交接 NPC 显示预生成台词弹窗，仅“知道了”关闭，不提交输入、不创建 pending、不推进剧情。
- 投影规则：非焦点 NPC 的 `choices` 固定为空（`choices: []`）；`ask` 交谈入口与 `talkChoice` 仅由当前权威 talk 目标投影。
- 旧存档或 offline 场景缺少 `speechSource`/AI 闲聊字段时，read model 才使用 `composeIdleNpcLine` 或确定性问候兼容读取，并标记为 fallback。

## 历史实现（不适用于新的 live scene 契约）

以下章节保留早期 `smallTalk` 数组、按钮和 read model 生成方案，供旧存档/迁移排查使用；新代码不再按这些字段生成或投影客户端按钮。

## 功能概述

为非焦点 NPC 添加了闲聊功能，让场景中所有 NPC 都能与玩家互动，提升游戏的沉浸感和代入感。

## 核心特性

- **AI 生成闲聊内容**：在场景生成时，AI 会为非焦点 NPC 同步生成闲聊选项和回复
- **不消耗回合**：点击闲聊按钮后，直接在本地显示 NPC 的回复，不会触发服务器回合
- **视觉区分**：闲聊按钮使用虚线边框和次要视觉权重，与主要对话选项明确区分
- **符合 NPC 身份**：闲聊内容由 AI 生成，符合 NPC 的角色和当前情境

## 改动文件

### 1. 数据模型 (`src/game/domain/narrative.ts`)

**`NpcDialogueInScene` 类型**：添加可选的 `smallTalk` 字段
```typescript
readonly smallTalk?: {
  readonly prompt: string;  // 闲聊选项文本，如"向韩征打个招呼"
  readonly response: string; // NPC 的回复内容
};
```

**`buildNpcDialoguePages` 函数**：接受 `smallTalkData` 参数，将闲聊数据分配给相应的 NPC

### 2. 场景生成 (`src/game/application/sceneSource.ts`)

**`ScenePackageProposal` 类型**：添加可选的 `smallTalks` 字段
```typescript
readonly smallTalks?: ReadonlyMap<string, { prompt: string; response: string }>;
```

### 3. AI 生成器 (`src/game/application/server/ai/sourceFactory.ts`)

**增强的 AI Prompt**：
- 添加 `smallTalks` 数组到 JSON 输出格式
- 指导 AI 为非焦点 NPC 生成符合身份的闲聊内容
- 要求闲聊回复简短（1-2句），不包含剧情关键信息

**解析逻辑**：
- 解析 AI 返回的 `smallTalks` 数组
- 验证 npcId 必须是非焦点在场 NPC
- 验证 prompt 和 response 都不为空
- 构建 `Map<npcId, {prompt, response}>` 传递给审批流程

### 4. 场景审批 (`src/game/application/approveAndWriteScene.ts`)

将 `proposal.smallTalks` 传递给 `buildNpcDialoguePages`，让闲聊数据进入最终场景状态

### 5. 视图层 (`src/game/application/gameSessionView.ts`)

**`NpcDialogueView` 类型**：添加 `smallTalk` 字段

**视图构建逻辑**：从场景的 `npcDialogues` 中提取 `smallTalk` 数据并传递到 view

### 6. UI 组件 (`src/components/LocationSceneScreen.tsx`)

**`NpcDialogueModal` 组件**：
- 添加 `smallTalkShown` 状态，跟踪闲聊是否已被点击
- 添加 `handleSmallTalkClick` 函数，点击后切换状态
- 在台词区域显示闲聊回复（带样式区分）
- 在交互区域显示闲聊按钮（仅非焦点 NPC 且未点击时）

### 7. 样式 (`src/app/globals.css`)

**新增样式类**：
- `.npc-dialogue-small-talk-btn`：闲聊按钮，使用虚线边框和灰色文字
- `.npc-dialogue-small-talk-response`：闲聊回复，使用斜体和上边框分隔

## 使用示例

### AI 生成的 JSON 格式

```json
{
  "narration": "你站在老槐树下...",
  "npcLine": {
    "npcId": "npc_lao_zhou",
    "text": "小兄弟，那告示上的事...",
    "emotion": "neutral"
  },
  "choices": [
    { "label": "表示愿意支持周伯", "candidateId": "candidate_1" },
    { "label": "质疑周伯的说法", "candidateId": "candidate_2" }
  ],
  "smallTalks": [
    {
      "npcId": "npc_he_zheng",
      "prompt": "向韩征打个招呼",
     "response": "有什么事直接找我，别耽误正事。"
    }
  ]
}
```

### 玩家交互流程

1. **场景呈现**：玩家与周伯（焦点 NPC）对话，同时看到韩征（非焦点 NPC）也在场
2. **点击 NPC**：玩家点击右侧人物列表中的"韩征"
3. **对话框显示**：
    - 显示韩征的直接台词："我还要继续巡视，有事就直说。"
   - 显示闲聊按钮："💬 向韩征打个招呼"
4. **点击闲聊**：玩家点击闲聊按钮
5. **显示回复**：在对话框中直接显示回复，无需等待服务器响应
6. **按钮消失**：闲聊按钮消失，避免重复点击

## 设计理念

### 增强沉浸感
让场景中的每个 NPC 都能与玩家互动，不再是静态背景板

### 不干扰主线
- 闲聊不消耗回合，不影响游戏进度
- 视觉上明确区分闲聊和主要对话选项
- 闲聊内容不包含剧情关键信息

### 一次性生成
- 在场景生成时同步完成，不增加额外的 AI 调用
- 所有内容持久化在场景状态中，可以反复查看

## 未来扩展方向

1. **条件化闲聊**：根据 NPC 关系等级、玩家状态等条件生成不同的闲聊
2. **隐藏线索**：某些特殊 NPC 的闲聊可能包含隐藏线索或彩蛋
3. **记忆系统**：在 NPC 记忆中记录玩家主动搭话，影响好感度
4. **动态更新**：随着剧情推进，同一 NPC 的闲聊内容会变化

## 性能影响

- **AI token 消耗**：每个非焦点 NPC 增加约 20-40 tokens（prompt + response）
- **场景生成时间**：无明显增加（仍是一次 AI 调用）
- **存储空间**：每个闲聊约 50-100 字节
- **渲染性能**：无影响（本地状态切换）
